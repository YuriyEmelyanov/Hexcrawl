# Материал выбранного мифа

Контракт: `agent-operations/agent-work/specs/HX-BL-041-MYTH-CARD1.md`, MC1-1.0.

У существующего POI типа `myth` с сохранённым `mb.myth` доступно раскрытие справочного материала. Ключ — точный owner, definitionVersion1 и согласованная пара d6×d12 с сохранённым entryId. Авторское имя не меняет идентичность. Неизвестная версия, несовпадающая пара или отсутствующие данные показывают недоступность без исправления карты.

`src/tags/mythMaterial.ts` содержит чистый выбор и проверку данных. Соответствие `mythic-bastionland-ru-core-v1` / materialVersion1 закреплено manifest; произвольный выбор новой версии не допускается. Знамения и групповые роли имеют переменную длину, исходный порядок и уникальные ID; пустая секция требует явного подтверждения данных. Ошибочная запись изолирована по entryId, дубликат целевой записи отвергается. Пределы:128 блоков на коллекцию,16384 Unicode code points на строку и262144 на запись; превышения не обрезаются.

Материал загружается лениво из отдельного статического модуля и выводится как текст React. При отсутствии английского перевода показывается тот же русский материал с одной языковой пометкой. Характеристики и ссылки остаются справочным текстом; карточка ничего не бросает и не применяет к карте.

Раскрытие transient: смена owner, записи, revision, языка или документа сбрасывает его. Уходящий запрос не может заполнить новую карточку, включая A→B→A. Pointer/click/key capture защищает активные черновики до общих обработчиков сохранения имени и выхода из переноса POI. Чтение не меняет JSON v9, теги, RNG, историю, заметки или экспорт PNG.

**Готовность данных:** production-модуль `mythMaterialData.ts` сейчас содержит пустой реестр. Это техническая оболочка MC1-01…09, а не готовые72карточки. Вымышленные записи существуют только в тестах и подставляются браузерной проверкой вместо отдельного модуля; они не включены в production bundle. Полный пользовательский выпуск требует проверенного корпуса MC1-10 и отдельного разрешения владельца. Реальные тексты книги в этот пакет не входят.

Проверки расширяют существующие Node tags и браузерный tags workflow. Они отдельно проверяют идентичность/ошибки реестра и настоящий App: неизменность документа, черновики, смену состояния, ошибки/задержку загрузки и компоновку1500/390/320px. Конечный набор Chromium-сценариев не подтверждает физический touch, screen reader или полное WCAG.
