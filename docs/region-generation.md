# Создание региона по клику

Статус: действующая сводка требований, очищенная 22.10.2026 без изменения алгоритмов.
Речные правила и их ID: [river-model.md](river-model.md); дороги: [road-model.md](road-model.md).
Полная прежняя редакция с baseline, причинами дефектов и результатами проверок сохранена
в [историческом журнале](archive/2026-10-22/region-generation.md). Его заменённые
формулировки не являются требованиями к новой работе.

## Якорь, размер, рост и центр

Для новой пустой карты классического режима интерфейс предлагает первый якорь
`0/0`. Последующие действия начинаются с выбранного доступного гекса-кандидата.
Якорь входит в новый связный регион; рост добавляет свободные соседние гексы,
не перекрывая ранее созданную сушу, существующее море и запретные гексы.
В Mythic первый регион и Престол начинают в центре области; это отдельное
правило [mythic-bastionland.md](mythic-bastionland.md), а не перенос классического якоря.

При автоматическом размере классического региона `rollRegionTargetSize` делает
бросок 1…100, затем равномерно выбирает целое значение внутри диапазона:

| Бросок | Вероятность | Целевой размер |
| --- | --- | --- |
| 1–5 | 5% | 6–10 |
| 6–40 | 35% | 11–20 |
| 41–65 | 25% | 21–30 |
| 66–83 | 18% | 31–40 |
| 84–95 | 12% | 41–50 |
| 96–100 | 5% | 51–60 |

Явно заданный `targetSize` заменяет автоматический бросок. Для Mythic используется
`modeRegionSize`: первый регион — 11 или 12, последующие — d12; рост и заполнение
пустот могут увеличить фактический размер. Ранее описанные в README `d20 + XdF`
и палочки Fate не соответствуют текущему коду. Они сохранены
[в архивном README](archive/2026-10-22/README-before-cleanup.md) как история,
не задают текущую генерацию и не должны восстанавливаться без отдельного решения.

Выбор следующего гекса взвешенный. `getGrowthCandidate` требует хотя бы одного
соседа текущего региона и считает вес `(currentRegionNeighborCount +
existingRegionNeighborCount)^growthWeightExponent`. Для обычного роста показатель
равен 1, для аварийного урочища — 1.5. `zeroWeightHexes` имеют вес 0;
`neutralOccupiedNeighborWeightHexes` не добавляют вес соседством с занятой клеткой.
В режиме Материк соседние с морем клетки получают нулевой вес, а в Побережье
само море не усиливает вес соседства. Следовательно, старая формулировка
«вес равен только числу соседей внутри нового региона» неполна.
При отсутствии кандидата с положительным весом рост прекращается; недостаточный
результат затем проходит проверки и повторы обработчика, а не принимается автоматически.

`findFillableEnclosedEmptyAreas` ищет замкнутые свободные области flood-fill.
Доступные для роста замкнутые клетки присоединяются к строящемуся региону,
в том числе сверх целевого размера; обычный рост сохраняет исключение
`zeroWeightHexes`, урочище не занимает уже занятые клетки. После окончательного
выбора моря проверяются также сухопутные карманы: допустимые клетки, не входящие
в `forbiddenHexes`, включаются в регион с обновлением фактического размера и категории.
Это заменяет прежнее описание отказа от каждого гекса, создающего пустоту через
`wouldCreateEnclosedVoid`: такого помощника в текущем коде нет.

После роста `chooseRegionCenter` выбирает гекс с максимальным числом соседей
того же региона, случайно разрешая равенство; единственный гекс является центром.
В обработчике возможен явный `fixedCenter`; в Mythic выбор центра ограничивается
областью королевства, если внутри неё есть кандидаты. Центр хранится как `centerHex`.

## Автоматический выбор высоты биома

Если биом не задан явно, первый регион получает биом высоты 1, включая случай
явно выбранной дикой местности. По умолчанию тип первой местности — освоенный;
явный `landType` сохраняется. Явно заданный биом проверяется на речные ограничения.

Для нового региона реки, входящие из соседей, задают верхнюю границу высоты,
а исходящие в существующих соседей — нижнюю. Когда касаются только исходящие
реки, предпочитается высота на 1 выше максимальной известной высоты соседей,
не выше 3. Исключение: исходящая река F≥3 в соседа высоты 1 даёт предпочтение 1.
Если точный предпочтительный выбор недоступен, остаются общие ограничения:
новый регион не выше соседа выше по течению и не ниже соседа ниже по течению.
При смеси входящих и исходящих отдельное предпочтение «только исходящие» не действует.
Основание реализации: `getRiverHeightConstraintForCandidateRegion` и
`src/biomeHeight.ts`; предпочтение не является разрешением нарушить ограничение.

## Результат действия и сохранность карты

Перед записью результата генерации проверяются safe integer и уникальность ID
регионов, рек, дорог и королевств, а также lake ID и nextLakeId/nextRoadId.
Проверка действует и на промежуточных шагах Mythic. Исчерпание диапазона ID
отклоняет действие через существующий rollback карты, выбора, вида, общей
undo/redo и generation checkpoints; экспорт остаётся пригоден для импорта.
Для дорог и озёр также требуется безопасное max(existing ID)+1, используемое
при загрузке. Сохранённые допустимые ID не перенумеровываются.

В классическом режиме клик по доступному кандидату пытается создать один связный
регион с выбранным якорем. Действуют режимы Авто, Побережье и Материк, существующие
правила биомов, побережья, рек и дорог. Регион без biomeId не принимается.
Обычная генерация перебирает до 30 попыток; штатный отказ может вести к урочищу.
Урочище остаётся сушей, не перекрывает старые регионы и не создаёт самостоятельную
новую реку. Существующие концы обрабатываются по действующим речным правилам.
При отсутствии корректного результата после предусмотренных ниже ограниченных
поисков действие явно отклоняется с сохранением прежней карты и истории.
Гарантии «регион при любом клике» и разрешения оставить некорректный закрытый
конец больше нет. Исчерпание поиска не доказывает отсутствие допустимого решения.
В Mythic один клик создаёт королевство; правила транзакции — ниже и в отдельной спецификации.

Ожидаемая несовместимость ограничений — обычный отказ с причиной (`success: false`,
для речного генератора обязательный `reason`). Неожиданное исключение, в том числе
в помощниках, подготовке названий, водных POI, переправ и урочище, доходит до границы
действия. Оно не запускает аварийную генерацию: карта, история и выбранный гекс
восстанавливаются из независимой резервной копии без пересчёта названий или дорог.
При неудачной перегенерации возвращается также заменяемый регион.
Выполненная заявка перегенерации одноразовая: повтор её обработчика после
другой заявки или undo/redo не меняет карту, RNG и оба стека истории.
Пользователь получает сообщение; следующая попытка очищает его.

Подготовка слоёв и счётчиков завершается до записи нового состояния и истории.
Текущий формат экспорта — `schema: hexcrawl-map`, JSON version 3; поддержка
необязательных слоёв Mythic описана в [mythic-bastionland.md](mythic-bastionland.md).
Состояния независимых потоков географии и POI сохраняются в `generation` и
восстанавливаются при загрузке, undo/redo и откате. Старый v2 получает seed
продолжения без пересоздания принятых объектов; контракт: [RNG](world-random.md). Исправление уже испорченных старых карт автоматически не обещается.

## Исток урочища и море

Исток исходящей реки не может находиться в вершине морского гекса: морские вершины
исключаются явно, независимо от списка кандидатов. При отсутствии пути применяются
общие требования закрытия концов и атомарного отказа ниже. Регрессия исходного
дефекта сохранена в `test/tractSeaSource.test.mjs`: море 0/−1, соседний регион −1/0,
клик 0/0, Побережье, targetSize 8, seed 1; также Авто/Материк, 3 режима × 5 seed.

## Биомы мёртвого леса — 30 сентября 2026

Четыре новых тайла участвуют в автоматическом выборе биома дикой местности с
весом 1 каждый и весом 0 в освоенной. Старые веса не меняются; сумма весов
дикой местности равна 104. Высоты: мёртвый лес и мёртвое редколесье — 1,
мёртвый лес на холмах — 2, мёртвый горный лес — 3. Ручной выбор биома остаётся
доступен независимо от веса, как и для остальных биомов.

Соседство симметрично. С новыми биомами разрешены все пары, кроме перечисленных
ниже (номера относятся к согласованному списку из 24 биомов):

| Биом | Несовместимые соседи |
| --- | --- |
| 11. Мёртвый лес | 4, 6, 10, 16, 19, 20, 21, 22, 23, 24 |
| 12. Мёртвое редколесье | 19, 20, 21, 22, 23, 24 |
| 18. Мёртвый лес на холмах | 4, 6, 10 |
| 24. Мёртвый горный лес | 1–12 |

Обычные биомы сохраняют прежнюю матрицу соседства. При отсутствии строгого
кандидата существующий алгоритм может ослабить проверку соседства; веса 0
при этом и при подборе точной высоты не превращаются в положительные.
Автоматическая генерация не создаёт новые мёртвые биомы в освоенных регионах.
Сохранения и отмена хранят идентификаторы биомов без изменения формата JSON.

Проверка: `test/deadForestBiomes.test.mjs` сверяет все пары с участием новых
биомов в обоих направлениях, высоты и веса, а также выбор освоенного биома
при каждой высоте. Дополнительно действуют тесты настоящего обработчика
генерации и браузерный smoke test.

## Диагностика генерации

Подробные сообщения отключены по умолчанию. Для их включения открыть страницу
с `?generationDebug=1`; удалить параметр или поставить `generationDebug=0` и
перезагрузить страницу для отключения. Это не меняет параметры и случайные
решения генерации. Переключатель отрисовки речной отладки независим от логирования.
Существующий профайлер `?profile=1` сохранён; оба параметра можно совместить.

В обычном режиме сообщения о промежуточных путях, выбранных биомах и каждой
повторной попытке не печатаются. Предупреждения помощников собираются по названию
и числу повторений в `warningCounts`. После действия с предупреждениями или
отклонёнными попытками выводится одна сводная запись `[generation]` через
`console.warn`. Ошибка выводится через `console.error`. Полностью успешное действие
без предупреждений и повторов выводится только в подробном режиме.

Итоговые события (заменяют прежний общий `constraint-rejection`):

| kind | Значение | result |
| --- | --- | --- |
| `generated` | Обычный регион создан; причины предшествующих повторов остаются в записи | `region` |
| `tract-created` | Штатный ранний переход к урочищу, например прямой переход из-за малого размера или отсутствия биома; несовместимые прибрежные концы сначала расходуют обычные попытки | `tract` |
| `attempts-exhausted` | Лимит обычной генерации исчерпан, после него успешно создано урочище | `tract` |
| `constraint-rejection` | После ограниченного поиска корректный результат не найден; прежняя карта сохранена | `rolled-back` |
| `programming-error` | Неожиданное исключение; действие отменено, карта и история восстановлены | `rolled-back` |

Успешный итог записывается только после завершения подготовки и записи карты.
Если построение урочища падает, единственный итог — `programming-error`, а не
успешное создание урочища. Само наличие региона не скрывает исчерпание попыток.

Каждая запись содержит `algorithmVersion`, `action` (добавление/перегенерация),
`options` (размер, освоенность, биом, режим берега; неуказанное — `auto`),
`anchorHex`, `attempt`, `maxAttempts`, `targetSize` последней обычной попытки,
`stage`, `reason`, `rejectionCounts` и `warningCounts`. При исключении добавляются
`message` и `stack`. Нумерация попыток — с 1; 0 означает сбой до первой попытки
или прямой вызов урочища. Счётчики обнуляются перед новым действием. Запись хранит
копию значений и не меняется при следующем действии. Полные данные промежуточных
предупреждений доступны в подробном режиме.

Версия алгоритма задаётся в `src/generationDiagnostics.ts`; её следует обновлять
при изменении правил/алгоритмов генерации, независимо от формата сохранения.
Диагностика содержит detached `random.before/after`, masterSeed и версии,
исходные категории параметров и разрешённые options. Для воспроизведения
продолжения нужны исходный JSON и то же действие на той же версии генератора.
У многошагового Mythic исходные `action` и категории controls сохраняются в
контексте задания до итогового успеха или отказа, а не выводятся из текущего
`pendingRegen` после очередного render. Воспроизведение regenerate восстанавливает
нужный сессионный checkpoint префиксом действий; история не добавляется в JSON.
Журнал находится в консоли браузера; в JSON карты он не добавляется и на сервер
не отправляется.

Проверки: `test/generationDiagnostics.test.mjs` — тихий режим, включение/отключение
подробностей, одинаковая карта при одинаковой случайности, 30 отклонений с одной
сводкой, штатное прибрежное урочище, актуальная причина повторного входа в озеро,
поздний программный сбой урочища без ложного успеха, откат, последующее действие
и отмена. Браузерный сценарий проверяет отсутствие подробных console.log в обычном
режиме и независимую работу `generationDebug` и существующего профайлера.

Историческая проверка изменения диагностики на Node.js 24: `npm run check` — 115 тестов, TypeScript и
production build проходят. Локальный браузерный запуск недоступен из-за
отсутствия Chromium; эти сценарии выполняются в CI до слияния и в Pages workflow.

## Закрытие речных концов — 5 октября 2026

Уточнение заменяет прежнее разрешение сохранять урочище с необработанным
старым речным концом. Добавление региона не может превратить открытое
продолжение в некорректный внутренний исток или устье, даже если старые рёбра
вообще не изменились. Проверяются концы на новой территории и потерявшие
границу с кандидатами, в том числе после расширения моря.

Общая процедура для обычного региона и урочища обрабатывает все такие концы.
Устье продолжается к морю, совместимой реке или озеру; для закрытого истока
F>1 требуется озеро. F=1 допускается без озера. При сохранении выхода в
реально неизведанную территорию конец остаётся открытым продолжением.
Новые пути проходят по рёбрам нового региона, без повторения занятых рёбер,
пересечений и циклов. Старые пути остаются целыми в прежнем направлении,
возможно добавление пути с любого конца. Старые F фиксированы.

Озёра размещаются только на новой суше, с фактической связной площадью,
вне соседства с морем. Баланс, слияния и размеры проверяются существующим
числовым ядром RIV-001…018. Размещение озера и русла происходит атомарно.
После уточнения воды дороги урочища рассчитываются с учётом итоговых водоёмов;
вариант обычного освоенного региона с нарушением минимума дорог отклоняется.

При несовместимости обычная генерация повторяется до действующего лимита.
Урочище также перебирает до 30 вариантов формы. Поиск завершений ограничен
128 состояниями и глубиной 24; исчерпание бюджета не доказывает отсутствия
решения. Если допустимый вариант не найден, действие возвращает штатный
`constraint-rejection` с `result: rolled-back`. Пользователь видит сообщение
о невозможности разместить корректные истоки/устья, карта и история остаются
прежними. Это явное уточнение прежнего требования «регион при любом клике»:
некорректная речная сеть больше не принимается ради появления региона.
Программные исключения по-прежнему идут отдельно как `programming-error`.

Регрессии: `test/riverEndpoints.test.mjs` воспроизводит пропуск неизменённого
старого конца; проверяет истоки и устья F=1/3/5, море, соединение с другой
рекой, несколько концов, нехватку площади, сохранность старых F, настоящий
обработчик урочища, JSON, откат и продолжение работы. Браузерный сценарий
проверяет полную речную сеть после каждого добавления на чистой карте.
Старые карты не мигрируют автоматически; исправление старых дефектов при
загрузке в эту задачу не входит. Не затронутые расширением старые компоненты
не пересчитываются.

## Повторные попытки прибрежного региона — 5 октября 2026

Несовместимые речные концы побережья (`coastal_river_endpoints_incompatible`)
отклоняют текущую форму региона, но больше не вызывают немедленное урочище.
Генератор продолжает обычные попытки до общего лимита 30. Условия допустимости
побережья, исходный бросок Авто и правила рек остаются прежними. Если последняя
попытка отвергнута по этой причине, создаётся прибрежное урочище; диагностика
записывает `attempts-exhausted`, число попыток и счётчики причин. Это уточнение
заменяет описанный выше ранний прибрежный переход.

Регрессия: seed 2, размер 20, первый регион Материк, следующие Авто, каждый раз
первый кандидат. На 12-м клике прежний алгоритм создавал урочище из 8 гексов.
Теперь вторая попытка создаёт обычный регион из 20 гексов. Тест проверяет всю
речную сеть, прежние регионы, историю, JSON и отмену. Отдельный тест подтверждает
переход к урочищу после 30 прибрежных отказов.

## Старое озеро не блокирует новый регион — 5 октября 2026

На сохранении `test/fixtures/lake-reentry-map.json` гекс −1,14 раньше давал
30 отказов `river_lake_reentry`: река 10 повторно касается озера 10 ещё до клика.
Общая проверка всей карты ошибочно относила прежнее взаимодействие к новому
действию. Теперь сохраняется допустимость неизменившегося старого взаимодействия,
но новые и изменённые повторные входы отклоняются. Окончательная проверка после
размещения воды применяется также к урочищу; штатный отказ сохраняет карту и историю.

Регрессионные проверки: обычный регион на исходном сохранении, JSON и отмена;
позднее озеро на старом русле; новое нарушение при наличии старого; изменение
пути, формы и идентификатора озера; искусственное позднее размещение конфликтного
озера через настоящий обработчик, откат и успешное продолжение после снятия сбоя.

Историческая проверка соответствующего изменения на Node.js 24: `npm run check` — 133 теста, TypeScript и production
build проходят. Браузерные сценарии выполняются в CI перед слиянием и публикацией.

## Локальное освобождение моря — 5 октября 2026

Если обычная генерация и урочище штатно отклонены, обработчик пробует локально
освободить море, не принадлежащее существующим регионам. Программное исключение
этот поиск не запускает. Пробуются связанные с якорем наборы по возрастанию числа
гексов: радиус до 3, до 6 морских гексов в наборе, не более 30 наборов. Для каждого
действуют прежние лимиты попыток региона и урочища. Это ограниченный поиск,
а не гарантия глобально минимального изменения или успеха любого клика.

Море, касающееся существующего устья, исключено из удаления. Старые регионы,
русла и полноводность сохраняются. Освобождённые гексы могут стать новым регионом
или свободной прибрежной полосой, необходимой для продолжения и размещения озёр.
Оба старых конца у якоря проверяются с принудительным закрытием прежней точки:
само исчезновение моря не позволяет объявить незавершённый конец открытой
границей. Нужно допустимое завершение или продолжение русла; новый открытый
конец возможен на действительной дальнейшей границе неизведанной территории.

Каждый вариант работает с локальной копией моря и пересчитанными кандидатами.
Море записывается только вместе с успешно проверенным регионом, реками и прочими
слоями. Неудача сохраняет исходную карту и историю; одна отмена возвращает также
морские гексы. Диагностика содержит `seaRecoveryAttempt` и `reclaimedSeaKeys`
(для отказа — последний пробовавшийся набор). По-прежнему одна итоговая сводка.

Регрессия: сохранение `test/fixtures/sea-pocket-map.json`, якорь 3/−3.
Проверки настоящего обработчика покрывают Авто, Материк и Побережье, старые русла
и полноводность, устья, завершение обоих концов, JSON, отмену, полный отказ и
исключение во время резервного поиска. Браузерная проверка загружает сохранение,
создаёт регион в 3/−3 и отменяет действие.

Историческая проверка соответствующего изменения, Node.js 24: 137 тестов, TypeScript и сборка прошли. Chromium в локальном
окружении отсутствует; production-браузерная проверка обязательна в CI.

## Отображение лесов и редколесья — 9 октября 2026

В режиме «Цвет» озёрные гексы сохраняют лесной покров своего базового биома:
вода накладывается поверх непрерывной структуры. Исходная подложка биома
из `BIOME_GROUND_COLORS` сохраняется также в прогалинах. Вдоль гексов-кандидатов
кромка леса совпадает с прямым ребром; между построенными гексами используются
согласованные извилистые шаблоны.

При создании региона редколесья вариант записывается в `woodlandStyle`.
Если стартовый гекс соседствует с плотным лесом, весь регион получает прогалины;
иначе — островки. Добавление соседей не меняет сохранённый вариант. Старые
сохранения без этого поля читаются: стартовый контакт определяется по более
ранним регионам. Ручные островки редколесья внутри региона другого биома
сохраняют существующее правило выбора по окружению.

Согласованные композиции (24, по 3–4 формы) сохраняют исходные контуры,
масштаб и положения. Близкие островки соединяются с плотным лесом перемычками, близкие прогалины
получают выход в построенную открытую сушу. Перемычки — дополнительные
контуры; исходные формы не растягиваются и не масштабируются.
Окантовка рисуется по объединённому силуэту, без внутренних линий в реальных
пересечениях и без увеличения исходных форм. На озёрных гексах островки и
прогалины скрыты, базовая лесная заливка сохраняется под водой.
Специальная подгонка соседнего леса к берегу озера отключена: озеро накладывается
поверх исходной геометрии. Обрезка внешней кромки по реке сохраняется; внутри
лесного массива русло накладывается сверху. Геометрия рек, озёр, полноводность
и правила генерации водной сети не меняются.


## Ручная местность существующей карты (HX-BL-023, E2)

Это редактирование данных, а не повтор генерации. В общем режиме значение под именем региона меняет его базовый биом; значение «Местность» под координатами меняет локальную местность выбранного наземного гекса. Inline-список гекса содержит24 биома и «Как в регионе», удаляющее только его локальную запись. Водная отрисовка и высота региона не изменяются.

Региональный список ограничен сохранённой высотой:12/6/6 биомов для уровней1/2/3 до фильтра соседства. Нулевой генерационный вес не запрещает ручной выбор. Новый биом должен быть совместим с canonical биомами регионов с общей стороной по действующей матрице и dead-forest исключениям; тот же биом соседа допустим. Недоступные варианты имеют причину; callback проверяет ограничения повторно. No-op не ремонтирует исторические противоречия. Смена региона сохраняет **все** локальные записи, включая совпадающие с новой базой и скрытые водой.

Меняются только biomeId и четыре canonical поля его подписи/эмодзи. Высота, освоенность, woodlandStyle, геометрия, вода, пути, POI, имена, заметки, счётчики и состояние RNG остаются прежними. Один выбор — одна атомарная запись общей Undo/Redo; no-op не очищает Redo. Формат сохранения не меняется. Изменённая карта может иначе влиять на последующую генерацию, но две одинаковые отредактированные копии продолжаются одинаково.
