# Создание региона по клику

## Биомы мёртвого леса — 30 сентября 2026

Четыре новых тайла участвуют в автоматическом выборе биома дикой местности с
весом 1 каждый и весом 0 в освоенной. Старые веса не меняются; сумма весов
дикой местности равна 104. Высоты: мёртвый лес и мёртвое редколесье — 1,
мёртвый лес на холмах — 2, мёртвый горный лес — 3. Ручной выбор биома остаётся
доступен независимо от веса, как и для остальных биомов.

Соседство симметрично. С новыми биомами разрешены все пары, кроме перечисленных
ниже (номера относятся к согласованному списку из 24 биомов):

| Биом | Несовместимые соседи |
| --- | --- |
| 11. Мёртвый лес | 4, 6, 10, 16, 19, 20, 21, 22, 23, 24 |
| 12. Мёртвое редколесье | 19, 20, 21, 22, 23, 24 |
| 18. Мёртвый лес на холмах | 4, 6, 10 |
| 24. Мёртвый горный лес | 1–12 |

Обычные биомы сохраняют прежнюю матрицу соседства. При отсутствии строгого
кандидата существующий алгоритм может ослабить проверку соседства; веса 0
при этом и при подборе точной высоты не превращаются в положительные.
Автоматическая генерация не создаёт новые мёртвые биомы в освоенных регионах.
Сохранения и отмена хранят идентификаторы биомов без изменения формата JSON.

Проверка: `test/deadForestBiomes.test.mjs` сверяет все пары с участием новых
биомов в обоих направлениях, высоты и веса, а также выбор освоенного биома
при каждой высоте. Дополнительно действуют тесты настоящего обработчика
генерации и браузерный smoke test.

## Задача №1

Клик по доступному гексу кандидату на корректной карте должен добавить ровно один
регион, содержащий выбранный гекс. Требование действует для Авто, Побережья и
Материка, с морем и без моря, без рек, с входящими, исходящими и смешанными реками.
Отклонение обычной генерации не должно превращаться в молчаливое отсутствие результата.

Обычная генерация использует существующие правила побережья. Когда построение
отклонено или исчерпаны попытки, создаётся урочище. Урочище остаётся сушей,
не перекрывает старые регионы и не создаёт самостоятельных новых рек. Допускается
добавить исток к существующей исходящей реке; если путь истока не найден,
урочище сохраняется с прежними реками. Текущая трактовая ветка выбирает одну
исходящую реку с минимальным ID. Изменение этой политики не входит в задачу.

Сохраняются история добавлений, отмена и формат JSON v1. Недопустимо сохранять
регион с отсутствующим biomeId. Географическая правдоподобность всех карт и
создание моря при любой геометрии не являются доказанными следствиями этого исправления.

## Причина отказа

Baseline: 29fceaf995cd06b50553be89aba8cea39b37fc02.
В addFallbackTractToMap использовалась необъявленная tractHasOutgoingRiver.
Обработчик исключений повторно вызывал ту же падающую функцию. Речной генератор
уже содержит отдельную ветку урочища, поэтому дублирующая проверка удалена.
Исправлены также необъявленные переменные в продолжении побережья, диагностике
дорог и подписях POI, а отсутствие биома направлено в fallback.

## Проверка

`npm run check`: TypeScript, все тесты, production build. Node.js 24.
`test/regionGeneration.test.mjs` проверяет настоящий обработчик с фиксированным
потоком случайных чисел: 6 вариантов рек × 2 состояния моря × 3 режима берега ×
5 seed = 180 случаев. Проверяются добавление региона, якорь, отсутствие пересечений,
сохранность старых регионов и рек урочища, удаление кандидата, JSON и отмена.
Отдельно проверяются прямой fallback, берег без рек и исключение обычного генератора.

Harness заменяет только React hook storage и финальный JSX возврат для доступа к
обработчикам. Он не заменяет генераторы; эффекты React и DOM этим тестом не покрыты.
Браузерная проверка: `npx playwright install chromium`, затем `npm run test:browser`.
Она проверяет production build: 19 добавлений, перегенерацию, отмену, загрузку JSON
и продолжение генерации. Локальная проверка 21 сентября 2026: все 54 теста и 180
случаев матрицы прошли, TypeScript без ошибок, браузерных pageerror нет.
При наличии заранее установленного Chromium можно задать CHROMIUM_EXECUTABLE_PATH.
Это ограниченная проверяемая матрица, а не математическое доказательство 100% карт.

Проверки запускаются для PR и перед публикацией main. При сбое публикация
останавливается до загрузки артефакта GitHub Pages. Настройка защиты ветки —
отдельный механизм; один workflow не запрещает слияние PR.

## Исток урочища рядом с морем — 22 сентября 2026

Исток, добавляемый урочищем к исходящей реке, не может находиться ни в одной
вершине морского гекса. Море отсутствует в списке кандидатов, поэтому проверки
границ с кандидатами и соседними регионами недостаточно: морские вершины
исключаются явно перед поиском пути. При отсутствии допустимого пути действует
прежний fallback: урочище создаётся, существующие реки сохраняются без изменений.
Последующее расширение моря уже исключает гексы, касающиеся рек.

Регрессия: море 0/-1, соседний регион -1/0 с исходящей рекой, клик 0/0,
Побережье, targetSize 8, seed 1. До исправления новый исток был в вершине
0,-28 на морском гексе. test/tractSeaSource.test.mjs проверяет этот случай
и Авто/Материк с принудительным малым размером: 3 режима × 5 seed.
Проверяются итоговое море, сохранность старого пути и региона, JSON и отмена.
Все три теста до исправления падали на seed 1.

Изменение предотвращает создание новых морских истоков урочищем;
автоматическое исправление уже испорченных загруженных карт в него не входит.
