# Устойчивые имена морей

E8-N-SEA / SEA-1.0. Редактирование существующей карты; прежние E6/RIV/ROAD ограничения сохраняются.

**SEA01.** `hexcrawl-map` v9 хранит `map.seas: {id,hexKeys[]}[]`, `map.nextSeaId` и разреженное имя `editorNames["sea:<id>"]={en,ru}`. Один Sea — максимальная компонента явных `terrainOverride=sea` по шести общим рёбрам. Озеро, общая вершина или неизвестная территория её не соединяют. Участие в регионе не влияет на ID. Реестр однозначно покрывает всё море; координаты/ID/floor — safe integers. Floor строго больше живых ID и не понижается при удалении. Имя не привязано к выбранному гексу.

**SEA02.** Сначала E6 готовит геометрию, затем пересечения прежних и новых Sea. Неизменённый/расширенный Sea сохраняет ID. При split один потомок наследует ID: для именованного выбор явный, для безымянного по умолчанию наибольшее пересечение, при равенстве численно минимальный(q,r). Только после всех split-наследников вычисляются merge-кандидаты. Один именованный кандидат сохраняется по умолчанию, несколько требуют выбора, даже с одинаковым текстом. Новые ID выделяются в порядке минимальной координаты компоненты. Изменённый выбор аннулирует согласия о потерях; изменение split также сбрасывает merge-ответы.

**SEA03.** Каждое удаляемое авторское имя перечислено с ID, парой языков и результатом слияния/удаления. Checkbox потери не отмечен заранее. Выбор наследника не означает согласие удалить другое имя. Все choices, E6 зависимости и потери проверяются до единственной транзакции. No-op/cancel/stale/busy/ошибка не меняют документ, RNG, ID или историю. Имя не копируется в озеро автоматически; заметки гексов и чужие имена сохраняют адреса.

**SEA04.** Генерация Classic/Mythic использует тот же пересчёт без дополнительных random draws. Когда нужен явный именованный split/merge или удаление имени, всё действие отклоняется с возвратом backup/RNG; мастер разрешает конфликт вручную. При восстановлении checkpoint изменение Sea или его имени включает существующее предупреждение воды: после согласия реестр, имена и floor возвращаются вместе с остальным снимком. Undo/Redo возвращают точные данные. Reset создаёт новый документ с floor1 и подчиняется существующей защите авторских имён.

**SEA05.** V2…v8 проходят прежний валидатор, затем получают только метаданные Sea: компоненты по численному min(q,r), IDs1…N, floorN+1. География, старые singleton/замкнутые моря и RNG не исправляются. V9 требует точный реестр и корректные ссылки имён; malformed/dangling/future версии отклоняются атомарно. Экспорт сортирует реестр по ID, члены численно; draft/choices не сохраняются. Старое приложениеv8 экспортv9 не открывает.

**SEA06.** Имя использует общий E8 парный редактор, trim/1…80UTF-16, уникальность по языкам и защиту от управляющих символов. Два пустых поля очищают override. Внутри региона имя находится в строке «Вода», снаружи доступно тому же Sea. Find даёт одну строку на Sea и фокусирует живой член. RU/EN и стартEN сохранены. Подписей поверх карты и новых PNG overlays нет; PNG содержит только принятую карту. Choices находятся в существующем водном preview, без постоянного пояснительного блока.

Проверки расширяют существующие `manualWater`, `mapTransactions`, `saveSafety`, `entityNames` и браузерный `save-history` lifecycle. Это конечные проверки контракта, не полная поддержка НРИ или физическая touch/AT проверка.
