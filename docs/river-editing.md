# Ручные реки: состояние документа E5

Статус: ветка `agent/hx023-e5-rivers`, промежуточный пакет PR486. Это описание подготовленного слоя сохранения и проверок, не объявление законченного редактора или опубликованной функции. Полная приёмка — E5-1.0, AC01–AC11 в agent-operations.

## Формат v7

Экспорт использует `hexcrawl-map` версии7. Обязательные новые поля:

```json
{
  "map": {
    "riverFeatures": {"rapids": [], "waterfalls": []}
  },
  "counters": {"nextRiverId": 1}
}
```

Это фрагмент, а не самостоятельный файл карты. Прежние поля карты, состояние случайности, имена и теги сохраняются. Читатель v6 не обязан открывать v7.

Пороги: `{riverId, edgeKey, state:"on"|"off"}`; ключ ребра канонический, неориентированный. Водопады: `{vertexKey, state:"on"|"off"}`; одна физическая вершина может быть общей нескольким рекам. Отсутствие override означает Auto. Запись `state:"auto"` в JSON не допускается: команда Auto удаляет override. Off сохраняет намерение даже при отсутствии автоматического значка.

Ссылки должны вести к живым рёбрам/вершинам. On порога запрещён на скрытом озёрном/морском ребре и любом crossing; On водопада запрещён в начале реки, слиянии, у озера/моря и без видимого речного ребра. Вероятности автоматических отметок не являются запретом ручного выбора. Auto сохраняет прежние stable hash и таблицы, не расходует RNG при отрисовке. Сохранённые overrides участвуют в производных SVG-слоях и экспорте PNG.

## Миграция и идентичность

v2…v6 сначала проходят прежнюю структурную проверку и общий preflight delta parent. Отсутствующий parent, self-reference и цепь рукавов недопустимы. Затем добавляются пустые overrides и `max(river.id)+1`, либо1 для пустой карты; старые русла/F/ID/имена не меняются. Невозможность выделить safe-integer счётчик — отказ до записи. v7 требует положительный safe-integer `nextRiverId`, строго больше всех живых речных ID; низкий счётчик не нормализуется молча.

При генерации сначала создаётся полный временный proposal. `reserveGeneratedRiverIds` выделяет новые ID от сохранённого floor, обновляет ссылки секторов и delta parent, затем готовятся имена и crossings. Старые ID остаются прежними. Удаление наибольшего ID не позволяет последующей генерации использовать его снова; неудачный proposal не сдвигает live counter. Снимок и Undo/Redo возвращают счётчик буквально.

## Границы транзакции

`checkedRiverMap` проверяет новые поля до подготовки транзакций/первой записи истории. Восстановление точного документа и отдельный generation rollback возвращают оба поля. Снимки до генерации и последующие checkpoint restore также содержат их. Новый формат не мигрирует исторические нарушения числовой модели RIV и не перекладывает геометрию при импорте.

Невалидный импорт и конфликт ручного On с новым crossing/истоком/слиянием не дают частичной записи. Реальный тест перегенерации с исключением должен сравнивать счётчик вместе с картой, RNG и обоими стеками. Одного теста чистого helper недостаточно.
