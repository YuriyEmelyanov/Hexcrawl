# Ручные реки: состояние документа E5

Статус: ветка `agent/hx023-e5-rivers`, PR486 для независимой проверки полного редактора. Функция не опубликована; готовность подтверждается проверками точного SHA, а не этим описанием. Полная приёмка — E5-1.0, AC01–AC11 в agent-operations.

## Формат v7

Экспорт использует `hexcrawl-map` версии7. Обязательные новые поля:

```json
{
  "map": {
    "riverFeatures": {"rapids": [], "waterfalls": []}
  },
  "counters": {"nextRiverId": 1}
}
```

Это фрагмент, а не самостоятельный файл карты. Прежние поля карты, состояние случайности, имена и теги сохраняются. Читатель v6 не обязан открывать v7.

Пороги: `{riverId, edgeKey, state:"on"|"off"}`; ключ ребра канонический, неориентированный. Водопады: `{vertexKey, state:"on"|"off"}`; одна физическая вершина может быть общей нескольким рекам. Отсутствие override означает Auto. Запись `state:"auto"` в JSON не допускается: команда Auto удаляет override. Off сохраняет намерение даже при отсутствии автоматического значка.

Ссылки должны вести к живым рёбрам/вершинам. On порога запрещён на скрытом озёрном/морском ребре и любом crossing; On водопада запрещён в начале реки, слиянии, у озера/моря и без видимого речного ребра. Вероятности автоматических отметок не являются запретом ручного выбора. Auto сохраняет прежние stable hash и таблицы, не расходует RNG при отрисовке. Сохранённые overrides участвуют в производных SVG-слоях и экспорте PNG.

## Миграция и идентичность

v2…v6 сначала проходят прежнюю структурную проверку и общий preflight delta parent. Отсутствующий parent, self-reference и цепь рукавов недопустимы. Затем добавляются пустые overrides и `max(river.id)+1`, либо1 для пустой карты; старые русла/F/ID/имена не меняются. Невозможность выделить safe-integer счётчик — отказ до записи. v7 требует положительный safe-integer `nextRiverId`, строго больше всех живых речных ID; низкий счётчик не нормализуется молча.

При генерации сначала создаётся полный временный proposal. `reserveGeneratedRiverIds` выделяет новые ID от сохранённого floor, обновляет ссылки секторов и delta parent, затем готовятся имена и crossings. Старые ID остаются прежними. Удаление наибольшего ID не позволяет последующей генерации использовать его снова; неудачный proposal не сдвигает live counter. Снимок и Undo/Redo возвращают счётчик буквально.

## Границы транзакции

`checkedRiverMap` проверяет новые поля до подготовки транзакций/первой записи истории. Восстановление точного документа и отдельный generation rollback возвращают оба поля. Снимки до генерации и последующие checkpoint restore также содержат их. Новый формат не мигрирует исторические нарушения числовой модели RIV и не перекладывает геометрию при импорте.

Невалидный импорт и конфликт ручного On с новым crossing/истоком/слиянием не дают частичной записи. Реальный тест перегенерации с исключением должен сравнивать счётчик вместе с картой, RNG и обоими стеками. Одного теста чистого helper недостаточно.

## Взаимодействие

В общем Edit выберите реку в «Рядом», через Find или на карте. Физические hit targets сохраняют44CSSpx при zoom/rotation; перекрывающиеся участки требуют явного выбора с подсветкой. Выбранная River подсвечена целиком, выбранный гидрологический участок — отдельно.

Полноводность1–5 меняется native select на всём участке между озёрами/слияниями/концами. Недопустимые значения имеют причину. Безопасное изменение и Auto/On/Off — одна транзакция без локального Apply. Разворот/удаление/потери/конфликты используют именованный inline preview. Глубокий брод требует явного bridge/ferry; запрещённый ручной On — Off/Auto в том же commit. E3 добавление переправы также предлагает Off/Auto для конфликтующих порогов.

Добавление и «Русло» используют временный RiverDraft. Замена допускает собственные старые рёбра, сохраняет ID/имена/теги и owner по правилам смежности. Enter/конечная вершина/Done проверяют весь путь; Escape сбрасывает его. Ошибка оставляет черновик и документ неизменными. Панорамирование не добавляет шаг. Все setters проверяют revision и identity, не только disabled DOM; посторонние мутации заблокированы до завершения/сброса. JSON/PNG выгружают подтверждённую карту без черновика, стрелок, приглушения и выбора.

Предпросмотр — отдельный detached candidate; временный safe bridge/Auto нужен только для полного списка зависимостей и никогда не записывается без явных ответов. Commit повторяет строгую подготовку. Отмена/stale/double completion не меняют карту, seed/streams, IDs и оба стека. Перед восстановлением generation checkpoint интерфейс предупреждает о потере изменённых русел/маркеров. Undo возвращает точный предоперационный документ.

## Промежуточный адаптер реальной геометрии

`buildManualRiverGeometryContext` читает текущую карту, а `buildManualRiverNetwork` переводит её направленные физические рёбра в сеть ядра. Вершины/соседства и владельцы берутся из настоящих созданных гексов; открытая граница выводится из соседней несозданной суши, без доверия к кешированному UI-списку кандидатов. Координаты сверяются с точностью канонического ключа (0.001), NaN и подмена координат отвергаются. Пропуск/противоречие F и инородный owner возвращают явное диагностическое нарушение, без fallback F1.

Один `lakeId` объединяет уникальные гексы всех регионов. Внутренний озёрный штрих не считается дополнительным портом. Помеченные BR-009 рукава занимают физические рёбра, но не включаются в обычное слияние2→1. Проверка их зависимостей выполняется общей подготовкой транзакции.

Совместимость ручной проверки сравнивает локальные числовые нарушения по реальным incident edges, направлениям, F, владельцам/высотам и площади озера. Старый дефект не блокирует допустимую правку в той же связной компоненте при неизменности его условий. Старый общий `CYCLE` не разрешает новый цикл: сравниваются отдельные циклические подграфы, включая связи через озёра. Ошибка степени в другом месте не скрывает новую ошибку баланса.

Подготовка F сохраняет пригодные controlPoints; разворот меняет их начало/конец. Причины границ секторов учитывают реальные озёра/слияния, а не только смену региона. Геометрический контекст теперь предоставляет `solvePath`; полный `additionalValidation` добавляет `prepareRiverMapEdit`: delta, reentry, переправы и feature resolutions. Сама геометрия не выдаётся за полную приёмку E5. Preview, черновик и явный выбор мест используют эту подготовку; отдельные ограничения приёмки перечислены в evidence точного SHA.


## Неизвестные F и единая подготовка изменения

У create/replace `fullness` — необязательное жёсткое F всего пути, `fullnessByEdge` задаёт отдельные жёсткие условия. Противоречия условий одного гидрологического участка отклоняются. Явное условие охватывает весь участок до озера/слияния/конца; старые F выбранной реки вне этого охвата и все соседние реки фиксированы. Отсутствие условия у нового ребра означает неизвестное, а не F1. Неполное старое покрытие сохраняемого ребра не становится свободным значением.

Кандидат строится отдельно с optional F. Существующее ядро получает затронутые узлы и фиксированные внешние порты; каждый связный компонент имеет максимум5000 состояний. `limit` возвращает отдельную ошибку «Проверка слишком сложна; упростите русло», без частичного решения. После расчёта полная сеть снова проверяется, включая циклы за пределами локального среза. Сохранённые внутренние озёрные штрихи не являются портами; у новых скрытых штрихов F выводится только из реального входа/выхода этой реки. Для BR-009 unknown F не решается как обычное слияние: существующий рукав получает явное значение и отдельную dependency validation.

`prepareRiverMapEdit` сначала проверяет принятые features/counter, затем целиком готовит русла/F, реальные пересечения road/trail, BR-009, reentry и ручные признаки. Старый kind переправы сохраняется; новая получает bridge. Углубление ford требует явного bridge/ferry; пути дорог не изменяются. Неизменённые старые глубокие броды не чинятся глобально. Маркеры, ставшие запрещёнными, разрешаются списком Off/Auto в том же кандидате, с одной финальной проверкой всего списка. E3 умеет передать такие же явные feature resolutions при создании переправы.

`editRiverDocument` и `editRiverFeatures` используют существующую атомарную историю: clone, names/tags и проверки готовятся до записи. Они блокируют busy/stale/name/road/obstacle состояния, сохраняют redo при no-op, не потребляют generation streams и требуют подтверждение удаления/разворота/потерь зависимостей. Это готовые backend handlers, а не заявление о готовом интерфейсе. Общий river draft lifecycle, пользовательский preview с именами/тегами, выбор targets, RU/EN/keyboard/touch и фактический walkthrough остаются обязательными перед review_ready.


Feature UI checkpoint: in Edit, select a nearby river, then an explicit local edge or vertex. Native Auto/On/Off selectors call the existing atomic feature command. Selected geometry is an editor-only overlay, excluded by the existing export filter. Off persists even when Auto has no mark; Auto removes the override. Forbidden On is disabled with a reason. This is not full E5: direct map hit picking, route/fullness/dependency preview and RiverDraft remain pending before independent review.


Create-path draft checkpoint: Edit → Add river opens a UI-only draft. Choose real neighbouring vertices; the previous vertex removes a step. Enter, clicking the end again or Done validates through the existing physical/solver/dependency preparation and commits once. Escape/Reset discards the draft. Other writers are blocked by the ref guard, not only disabled controls. Selection/Find/language/panel transitions attempt completion and stay on an invalid draft. JSON/PNG continue exporting the confirmed map only, with an explicit draft-exclusion notice; camera gestures never finish a path. Replacement/fullness/named dependency preview and full E5 acceptance remain pending.
