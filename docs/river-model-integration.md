# Подключение модели рек — 23 сентября 2026

Независимое ядро `src/riverModel/core.ts` подключено к двум обработчикам в
`src/App.tsx`: обычной генерации и аварийному урочищу.

## Путь данных

`buildRegionRiverNetwork` переводит направленные vertexPath в сеть событий.
Регион и высота берутся из assignedRegionId сектора; для старого ребра — из
предыдущего снимка. Старые F фиксируются, исчезновение или разворот старого
ребра отклоняется. Узлы вне изменяемой области представлены фиксированными
граничными условиями: старые ошибки карты автоматически не мигрируются.

Открытый конец определяется контактом с текущими кандидатами; море принимает
вход и запрещает выход. Один lakeId собирается по всем регионам, его площадь —
число уникальных гексов. Внутренние штрихи русла внутри озера не считаются
повторными входами/выходами. Все внешние русла участвуют в общем балансе.

`solveRiverComponents` решает независимые компоненты отдельно, с пределом
5000 состояний на компоненту. Применяется та же таблица ограничений в обоих
направлениях. Сначала соблюдаются старые значения, затем предпочтения ядра.

`reconcileRegionRiverModel` сначала пробует имеющуюся геометрию. При конфликте
у истока, закрытого внутреннего устья, продолжения или существующего озера
запрашивает у решателя необходимую площадь озера. Озеро размещается связно
на новой территории у соответствующего события, без соседства с морем.
После размещения повторно строится и проверяется фактическая сеть: заранее
запрошенная площадь никогда не заменяет реальную. Не более 8 таких исправлений
на попытку; сложная несовместимая геометрия отправляется на перегенерацию.
Частичный ответ решателя при исчерпании бюджета не принимается.

Обычная генерация проходит модель после окончательного выбора суши, моря и
очистки озёр, до дорог и записи истории. Несовместимость не разрешается даже
на последней попытке. После существующего лимита 30 попыток создаётся урочище.
Урочище пробует достроить допустимый исток; если это невозможно, сохраняет
старые реки без нового истока. Новое озеро и новые русла записываются вместе.
Отмена возвращает прежний снимок, включая водоёмы.

Старые частные функции роста и горного снижения полноводности удалены.
`assignRiverSectors` теперь только подготавливает геометрическое деление;
окончательные F назначает ядро. Числа, предлагаемые старым построителем путей,
не являются ограничениями для новых участков. Дороги/переправы строятся после
расчёта, пороги/водопады читают получившиеся сектора и региональные высоты.

## Совместимость и границы

- Существующие карты не пересчитываются автоматически. Импорт проверяет F=1…5,
  но не объявляет всю историческую сеть соответствующей новым правилам.
- Формат JSON v2 сохраняется. Новые рукава дельты имеют необязательное поле
  deltaParentRiverId. Дельты остаются отдельным правилом BR-009, не обычным
  слиянием RIV-005; строятся после расчёта основного русла, по его нижней F.
  Старые непомеченные рукава сохраняются как историческая геометрия.
- Неудача построить источник в урочище не превращает сохранённый старый конец
  в новый источник F=1: он остаётся прежним незавершённым продолжением.
- Озеро-исток с несколькими выходами по-прежнему не определено спецификацией
  и не принимается числовым ядром.
- Размещение истоков/слияний на перепадах высот остаётся предпочтением старого
  построителя геометрии; глобальной оптимизации геометрии здесь нет.
- Перебор вариантов озёр ограничен. Допустимое решение не гарантируется для
  каждой формы региона; предусмотренный результат неудачи — урочище.
- Время работы на очень больших пользовательских картах ещё не измерено.

## Проверки

`test/riverIntegration.test.mjs` использует настоящий обработчик App:

- AUD-01/02: 5 seed × 2 размера × 3 фиксированных F = 30 продолжений вверх;
  каждый результат проверяется моделью, старые F сравниваются точно, затем
  проверяются сохранение и отмена.
- AUD-03: запрос трёх гексов озера при одном доступном возвращает отказ без
  частичного изменения terrain.
- AUD-04: JSON отклоняет 0, 6, 99, дробное число, строку и null вместо F.
- Три режима берега × три seed × до восьми последовательных кликов;
  после каждого клика проверяются сеть, сохранность старых рёбер и число регионов.
- Направленный секторный пример 2+1 даёт 3 на низменности и 2 на высоте 2;
  принадлежность региона сохраняется, входные объекты не мутируются.
- Секторный пример озера на границе двух регионов учитывает два гекса и
  три русла один раз: 4+3→5 допустимо, одного гекса недостаточно.
- Урочище seed 2 действительно добавляет источник 3 и озеро не меньше двух
  гексов, а не просто отказывается от подключения.

Вместе с числовыми и прежними регрессиями: 84 теста. `npm run check` включает
TypeScript и production build. Браузерный сценарий отдельно проверяет клики,
перегенерацию, отмену, импорт и продолжение карты. Успешный конечный набор
прогонов не является доказательством всех возможных карт.
