# Map navigation

Wheel zoom and two-finger pinch scale the existing SVG using a composited CSS transform. SVG dimensions stay fixed in map coordinates. A separate map stage supplies the scaled scrolling bounds. Mouse drag and zoom updates are coalesced to at most one update per animation frame. The compositor hint is released 180 ms after input stops so the browser can rasterize vectors sharply at the final scale. Single-finger scrolling remains native; wheel and pinch cancellation use non-passive native listeners.

Navigation does not update React application state or rebuild forest, water, POI or terrain artwork. The wheel focal point uses the actual SVG bounds, including the centered position of small maps. Scale is clamped as before; wheel delta units are normalized. Import restores the live scale; JSON reads the latest scale, including queued input. PNG export clears navigation transforms and exports the complete original map at its original coordinates. Rotation continues to use the original artwork transform.

`test/browser/navigation.smoke.mjs` loads a 400-hex forest, exercises actual wheel and mouse handlers, and checks unchanged SVG contents/dimensions, batching, focal point, panning, rotation, JSON and PNG export. It reports animation-frame and handler timings. With `NAV_BASELINE=dist-baseline` it compares the same interactions to the production version before this change. Frame timings are runner-specific and do not establish a device-independent frame rate.

## Large maps

Color maps with at least 600 positioned hexes prepare a bounded viewport buffer after input stops. The buffer renders the existing SVG at the current zoom and device pixel ratio, with surrounding space for panning. Intermediate filter and mask surfaces are restricted to that window with a 112-map-unit halo; artwork geometry, colours and effects are retained. The buffer has an 8-million-pixel budget. If the visible window itself exceeds that budget, an asset fails, or movement leaves the prepared area, the original SVG remains visible.

Only navigation uses the buffer. After the navigation hint ends, the original vectors return. The transparent SVG remains the hit target throughout, and exports clone only that SVG. Rotation, artwork edits, generation and mode changes invalidate the buffer. Pending work cannot replace a newer map's buffer. Hex selection retains the artwork element; candidate click handlers read current generation options through a ref. Debug selection still updates its overlay.

`test/browser/large-navigation.smoke.mjs` exercises a 1200-hex map through the real input handlers, verifies buffer coverage, screenshot similarity, unchanged artwork, rotation and mode invalidation. `scripts/profile-large-map.mjs` profiles 400, 1200 and 2400 hexes. With `LARGE_BASELINE=dist-baseline`, it compares paired builds and checks identical SVG markup and full PNG output. These fixtures represent synthetic forest-heavy maps, not timings for every possible generated kingdom.

Paired Chromium 151 measurements (headless Linux, 1500×1000, no CPU throttling): at 2400 hexes, pan-frame p95 changed from 200 ms to 49.94 ms; median selection latency from 122.8 ms to 28.7 ms. At 1200 hexes pan p95 changed from 133.3 ms to 33.4 ms and selection median from 53.8 ms to 31.3 ms. Median navigation frames were 16.7 ms in both builds; this change primarily removes expensive stalls rather than increasing that median rate. Both large maps used the buffer for all 48 movement samples. Mean channel difference in viewport screenshots was under 0.034 out of 255; vector markup matched exactly. The buffer takes idle time to prepare and cannot guarantee a particular frame rate on other hardware.
