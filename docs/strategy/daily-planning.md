# Ежедневное планирование HexCrawl

Статус: проект регламента; расписание запускает только планирование, пока стратегия и задачи не утверждены.

## Вход и порядок

1. Прочитать AGENTS.md main; найти утверждённое видение по конкретному ref/SHA и approval_ref, включая утверждённую ветку до merge. Если его нет, читать vision.md в strategy/agent-vision-2026-10-22 и отметить strategy_pending_approval.
2. Прочитать agent-operations: latest.json, предыдущий план/результаты, backlog.json, approvals.json, budget.json если существуют. Отсутствие данных не заменять выдуманными записями.
3. Сравнить текущий main SHA с предыдущим. Читать только изменения, относящиеся к задачам; открытые PR и подтверждённую обратную связь. Не повторять полный аудит без основания.
4. Проверить действующие согласования и бюджет. Если бюджет неизвестен, только короткий план blocked_budget; не запускать исполнителей. Если стратегия не утверждена, новые продуктовые задачи только proposed.
5. Определить критические проблемы, зависимости, ожидаемые переходы grade и стоимость. Выбрать основную задачу, указать причину отказа от двух ближайших альтернатив. Не создавать обязательный объём работ, если полезных утверждённых задач нет.
6. Сохранить MD, JSON, затем обновить latest.json последним. Не писать в main, не делать merge, деплой, отправку сообщений/публикаций, удаление документов. Проверить JSON и доступность записи другим агентам.
7. Кратко сообщить результат и один пакет решений для владельца. При недоступном GitHub вернуть план в чат со статусом save_failed; не заявлять, что другие агенты могут получить сохранённый план.

## Передача и защита от конфликтов

- Дата дня по Europe/Moscow; plan_id = дата + baseline_sha; run_id включает время запуска или attempt, plan_revision увеличивается при обновлении. При повторном запуске обновлять существующий план, не создавать дубликаты задач.
- Перед исполнением агент читает latest, сверяет strategy_version, baseline_sha, approval_ref, статус задачи и доступный бюджет.
- Смена состояния задачи требует чтения последней версии и записи с ожидаемым SHA; конфликт записи не перетирать.
- Один активный исполнитель на изменяемый участок; иной baseline или исчерпанный бюджет → blocked и пересмотр.
- Ночной план не является согласием и не является автоматическим запуском всех ролей.
- Приватные замечания, персональные данные, закрытые кампании, показатели аккаунта и токены доступа в публичный репозиторий не записывать. В публичном плане допустимы только обезличенный статус бюджета и ссылки на публичные задачи. Чувствительные согласования хранить в доступном приватном источнике, с неприватной ссылкой/ID без содержания при необходимости.

## Минимальная структура машинного плана

```json
{
  "schema_version": 1,
  "date": "YYYY-MM-DD",
  "timezone": "Europe/Moscow",
  "plan_id": "YYYY-MM-DD:BASE_SHA",
  "run_id": "YYYY-MM-DD:BASE_SHA:ATTEMPT",
  "plan_revision": 1,
  "baseline_sha": "BASE_SHA",
  "strategy": {"version": "0.1", "status": "pending_approval", "ref": "docs/strategy/vision.md", "sha": null, "approval_ref": null},
  "budget_status": "unknown",
  "execution_allowed": false,
  "facts": [],
  "tasks": [],
  "decisions_needed": [],
  "deferred_candidates": [],
  "blockers": ["strategy_pending_approval", "blocked_budget"],
  "result_refs": []
}
```

Каждый tasks item использует обязательные поля поручения из vision.md, статус и отдельное разрешение на выпуск. Неизвестный grade = null, возможный delta = null до расчёта. JSON не допускает вымышленных current_score, token_spend или owner_approval.

В MD: изменения за сутки; доступные подтверждённые факты; одна рекомендуемая задача; назначение роли; критерии и evidence; что заблокировано; что согласовать. Latest содержит дату и пути файлов с версией/SHA, чтобы следующий агент не искал результат по переписке.
