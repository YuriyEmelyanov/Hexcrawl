## Метод и границы проверки

`test/audit/road-model.mjs` вызывает настоящий `safelyAddRegionToMap` через
существующий VM harness. React-хранилище заменено тестовым; генераторы не подменены.
Это проверка обработчика без браузерного интерфейса.

72 создания: seeds 7, 42, 103 × освоенная/дикая местность × материк/побережье
× 6 последовательных расширений. Первый регион всегда материковый. Размер 15,
для seed 103 — 35. Выбирается первый кандидат, для seed 42 — последний.
После каждого шага проверяется отмена и восстанавливается результат для продолжения.
Это разные направления роста, не исчерпывающий перебор порядков генерации.

Проверяется граф реальных участков дорог и троп. Конец степени 1 без POI/центра,
без соседней ещё не занятой суши отмечается как закрытый тупик. Отдельно ищутся
пустые окончания, полностью окружённые гексами своего региона. Старые участки
сравниваются по координатам и типу, а не по владельцу записи `Road`.

Наблюдения: [audit/road-model-observations.jsonl](audit/road-model-observations.jsonl).
В каждой строке `click` записана вся последовательность якорей и параметров.
Воспроизведение на Node.js 24:

```sh
node test/audit/road-model.mjs > docs/audit/road-model-observations.jsonl
```

Seed здесь относится к LCG тестового harness, а не к полю интерфейса приложения.
Сохранения ниже можно непосредственно загрузить кнопкой «Загрузить JSON».

## Подтверждённые результаты

### ROAD-AUD-01. Выходы оказываются закрыты без продолжения

**Подтверждено через обработчик**, ROAD-05/ROAD-EX-09.

- Seed 103, дикая местность, материк: после второго региона конец дороги
  `-3,1` первого региона остаётся без продолжения, POI и свободного сухопутного
  выхода. Пример: [road-sealed-mainland.json](audit/road-sealed-mainland.json).
- Seed 42, освоенная местность, побережье: после пятого региона конец `1,1`
  четвёртого региона закрыт. Пример:
  [road-sealed-coast.json](audit/road-sealed-coast.json).
- Также обнаружены seed 103 / освоенная / побережье (`0,3`) и
  seed 103 / дикая / побережье (`-3,1`).

Итого четыре сочетания сценария и координаты, 14 наблюдений по шагам: повторное
обнаружение одного сохраняющегося тупика не считается новой отдельной ошибкой.
Во всех этих случаях конец принадлежит дороге, а не только тропе.

Причину каждого полного сценария ещё нужно локализовать. Не утверждаем, что
следующие два дефекта вспомогательных функций объясняют все четыре случая.

### ROAD-AUD-02. Соседство скрывает несоединённые концы

**Подтверждено минимальным вызовом функции**, ROAD-EX-08.

Две дороги: `(-2,0)—(-1,0)` и `(0,0)—(1,0)`. Между ними нет участка.
`getRoadEndpointHexKeysImpl` возвращает только `-2,0` и `1,0`, скрывая оба
ближних конца. В функции соседний гекс другой дороги считается достаточным
основанием исключить конец.

Этот помощник используется при защите концов дорог от заполнения моря.
Подтверждена неверная классификация; затопление именно этой искусственной
конфигурации через полный обработчик отдельно не воспроизводилось.

### ROAD-AUD-03. Вход в центр исключается до поиска пути

**Подтверждено минимальным вызовом функции**.

Старая дорога `(-2,0)—(-1,0)`, новый регион из гекса `(0,0)`, он же центр.
`findIncomingRoadEndpointsForRegion` возвращает пустой список при пустом terrain.
Причина — `isUsableIncomingRoadEntryHex` отвергает центр без проверки возможности
соединить его одним участком. Это ограничение не следует из согласованных правил.

Это воспроизведение ограничения помощника, не утверждение о частоте такой
геометрии в обычных регионах: одногексовая область здесь искусственная.

### ROAD-AUD-04. Минимум одновременно ограничивает число дорог сверху

**Подтверждено чтением кода**, ROAD-07. Сценарий с избытком входящих дорог
полным обработчиком пока не воспроизведён.

В `generateRoadsForRegionImpl` дополнительные входящие дороги обрабатываются
только пока счётчик меньше `getSettledMainRoadLimit`. Затем
`normalizeSettledRegionRoadIds` сводит лишние записи к этому количеству.
Последнее само по себе не удаляет геометрические участки, но показывает, что
число ID нельзя использовать как независимое доказательство выполнения минимума.

### ROAD-AUD-05. Урочище использует другую процедуру дорог

**Подтверждено через обработчик; применимость числовой нормы требует уточнения**.

Из 24 аварийных урочищ в серии 12 имеют `biomeLandType: settled`, но ноль
новых записей с дорожными сегментами. Пример:
[road-tract-count.json](audit/road-tract-count.json).
Аварийная ветка вызывает `ensureRoadAdjacentTractPoiAndTrail`, а не обычную
генерацию: она пытается соединить POI с соседним путём тропой.

Это не записано как «12 нарушений обязательных двух дорог»: соответствующая
норма урочища явно не согласована. Продолжение существующего выхода проверяется
независимо от числа новых дорог.

## Подозрения, которые не стали подтверждёнными ошибками

- `getAvailableRoadFallbackHexes` и `getSupplementalRoadStartHexes` допускают
  пустые внутренние гексы. В данной серии таких окончаний не найдено.
- Число попыток `buildWildRegionTrailsImpl` не гарантирует число построенных
  троп. В обычных диких регионах серии недобора по текущему счётчику не найдено.
- Все освоенные области не проверялись на глобальную связность: разрыв между
  областями через ещё неизвестную территорию сам по себе ошибкой не является.
- Типы переправ прочитаны в `reconcileRiverCrossings`, но отдельная матрица
  соответствия полноводности/высот/типов переправ в этот аудит не входит.

и обеспечить продолжение выхода до окончательного принятия нового региона.
