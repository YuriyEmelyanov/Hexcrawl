# Названия объектов карты

## Область действия

Названия автоматически получают регионы, населённые пункты (центральные и вторичные POI), реки и озёра. Для регионов с лесным, горным или болотным биомом используются отдельные окончания. Поляны, побережья, острова и водопады пока не существуют как самостоятельные именуемые объекты приложения; не создаём для них фиктивные записи. Числовые ID остаются ключами геометрии и связей; имя можно свободно изменить.

В боковой панели есть отдельный генератор: можно выбрать один из семи типов и количество (1, 5, 10, 20), получить список пар RU/EN и скопировать его. Списки пробных имён не изменяют карту; новый запрос даёт новую подборку.

## Правила

- Одна модель `germanic`: единая германская фэнтези-традиция с преимущественно северным звучанием. Это оригинальные игровые названия, а не реконструкция какого-либо исторического языка или подборка реальных географических названий.
- Каждая основа и каждое окончание хранятся парой латиница/кириллица. Интерфейс RU/EN переключает представление одной записи, а не запускает генератор повторно. Например: `Hrafnvatn` / `Храфнватн`, `Ravnelv` / `Равнэльв`.
- Окончание выбирается по типу объекта: поселение, регион, река, озеро, лес, гора или болото. При недостатке уникальных простых сочетаний добавляются уточнения из той же модели (`Nord`, `Syd` и другие).
- Выбор основы/окончания детерминирован для seed карты, ключа объекта и номера варианта. Генератор названий не расходует поток случайных чисел генератора географии. Уже существующие имена сохраняются при добавлении и перегенерации регионов и не зависят от порядка обхода объектов; даже если биом региона изменился, его имя остаётся прежним.
- Уникальность соблюдается отдельно для обеих языковых форм по всей карте (без учёта регистра и краевых пробелов). Ручная правка требует обе формы, не более 80 символов каждая; совпадения с другими названиями отклоняются. «Другое название» меняет только выбранный объект.

Словарь, окончания и соответствующие русские формы находятся в `src/toponymModels/germanic.ts`. Общий механизм выбора, проверки уникальности и повторной генерации находится в `src/toponyms.ts`; `src/App.tsx` только собирает объекты карты, вызывает механизм и показывает результат. Для следующей языковой группы добавляется отдельный файл модели и запись в реестре моделей; существующие имена остаются привязаны к своей модели.

## Жизненный цикл и сохранение

Ключи реестра: `region:<id>`, `settlement:<regionId>:<q>,<r>`, `river:<id>`, `lake:<id>`. Новые имена и seed сохраняются в необязательном поле `map.toponyms` JSON версии 2, вместе с ID модели `germanic`. Старые сохранения той же версии без этого поля читаются; seed вычисляется из идентификаторов и якорей существующих регионов, а имена создаются однократно и войдут в следующий экспорт. При импорте проверяется структура имён; удалённые объекты не оставляют записей. Отмена и перегенерация последнего региона возвращают географический снимок и seed; ручные правки имён у сохранившихся объектов продолжают действовать.

Название региона подписано на карте и включено в PNG. В обычной панели показаны «Река Равнэльв», «Озеро Храфнватн» и имена регионов без номера. Экспорт JSON содержит обе языковые формы, модель и номер варианта. Числовые ID остаются в JSON и в панели отладки для служебных связей рек и дорог.

## Проверка

`node --test test/toponyms.test.mjs` проверяет оба языка, типовые окончания одной модели, 120 озёр одного типа, детерминизм, сохранение старых названий, ручное переименование, повторный выбор варианта и реальные обработчики создания/отмены региона. `npm run check` выполняет проверку типов, все тесты и сборку; `npm run test:browser` проверяет экран и JSON в реальном браузере.
