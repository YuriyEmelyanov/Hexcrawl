# Названия генерируемых объектов

## Область действия

Имя автоматически присваивается только созданным картой регионам, населённым пунктам (центральным и вторичным POI), рекам и озёрам. Для региона с лесным, горным или болотным биомом используется соответствующий тип названия. Поляны, острова, водопады и прочие объекты без собственной записи в модели карты имён не получают.

Имя видно в существующем информационном блоке выбранного гекса или региона: например, «Река Равнэльв». Отдельного генератора или элементов управления именами в интерфейсе нет. SVG-карта и экспортируемый PNG не содержат подписей топонимов: выбор их размещения будет отдельной задачей. Числовые ID нужны для связей и остаются в JSON и отладке.

## Модель

Доступна одна модель с ID `germanic`. Внутри неё несколько согласованных способов образования названий с северногерманским, английским, верхненемецким и нижненемецко-нидерландским звучанием. Это внутренняя структура словаря, не переключаемые пользователем стили. Основа и окончание берутся из одного набора, чтобы не получить смесь вроде английской основы с норвежским окончанием.

Для каждого типа объекта есть собственные окончания (река — `-elv`, `-brook`, `-bach`, `-beek`; озеро — `-vatn`, `-mere`, `-see`, `-meer` и т. д.). Поселение может образоваться от местного слова или имени человека. Часть названий задана целиком, поэтому результат не сводится к одной формуле «основа + суффикс». Для пары вариантов письма хранятся отредактированные латинская и русская формы. Интерфейс RU/EN меняет отображаемую форму записи без нового выбора имени.

Это вымышленные игровые топонимы, вдохновлённые способами именования, а не реконструкция исторических языков, корпус всех германских языков или гарантия отсутствия совпадений с реальной географией. При подготовке структуры использованы материалы [исследователей норвежских имён](https://www.nordicsocioonomastics.org/typical-and-untypical-in-norwegian-naming-formations/), [университета Ноттингема об английских именах](https://digitalresearch.nottingham.ac.uk/2026/03/13/key-to-english-place-names-kepn/), [Гёттингенской академии о немецкой топонимии](https://adw-goe.de/forschung/forschungsprojekte-akademienprogramm/ortsnamen-zwischen-rhein-und-elbe/) и [исследование составных нидерландских топонимов](https://link.springer.com/article/10.1007/s10828-015-9075-0).

Словарь и формы находятся отдельно в `src/toponymModels/germanic.ts`, общий механизм уникальности и устойчивости имён — в `src/toponyms.ts`. Для другой языковой группы понадобится отдельная модель и запись в реестре; география карты от неё не зависит.

## Устойчивость и сохранение

Выбор определяется seed карты и ключом объекта, не расходует случайные числа генерации географии. Поселение использует тот же внутренний способ образования, что и его регион. Уникальность латинских и русских форм проверяется по всей карте. Имена уже созданных объектов не меняются при расширении, удалении/перегенерации последнего региона или смене биома; история региона возвращает старые имена вместе с географией.

Ключи: `region:<id>`, `settlement:<regionId>:<q>,<r>`, `river:<id>`, `lake:<id>`. Имена, seed и ID модели хранятся в необязательном поле `map.toponyms` JSON версии 2. Файл без поля принимается, для него имена генерируются один раз. Сохранённые имена, в том числе полученные прежней моделью или изменённые вручную, при загрузке сохраняются без замены; новые объекты получают имена по обновлённой модели.

## Проверка

`npm run check` проверяет типы, модульные и интеграционные тесты и собирает приложение. `npm run test:browser` открывает production-сборку в Chromium, создаёт регионы, проверяет видимость имён только в информационном блоке, отсутствие отдельного генератора, переключение RU/EN, импорт/экспорт и перегенерацию. Оба набора запускаются в CI до публикации.
