# Работа над HexCrawl

## Источники и полномочия

Начинай с [индекса](docs/index.md), [видения](docs/strategy/vision.md), [score-модели](docs/strategy/score-model.md), затем agent-work/latest.json в ветке agent-operations. Видение и основа модели согласованы22.10.2026; поправка к модели от25.10.2026 привязывает игровые критерии к требованиям НРИ. Топ игр пока не определён; уже учитывать четыре игры из реестра в agent-operations/agent-work/market/systems-register.md. Производительность измеряется количеством гексов N; размеры тестов и дополнительные пороги ещё согласуются. Исторические262.5 балла не являются текущей оценкой.

Решения владельца имеют приоритет. Профильные спецификации задают правила реализации; код показывает фактическое поведение, но не отменяет требования. Архивы, прежние Handbook и whitepaper не являются текущими поручениями.

Исполнитель начинает только утверждённую задачу с scope, приёмкой, бюджетом и условиями остановки. Видение не разрешает все будущие задачи. При неизвестном бюджете — короткое планирование, без тяжёлых работ/делегирования. Все роли входят в общий предел ≤50% каждого применимого лимита подписки; usage не выдумывать, кредиты/API без согласования не покупать.

## Технические требования

Перед изменением генерации прочитай README и профильную спецификацию: регионы — docs/region-generation.md; реки — docs/river-model.md и docs/river-model-integration.md; дороги — docs/road-model.md. Аудиты читать для конкретного случая с учётом статуса исправлений.

- Сначала воспроизведи ошибку тестом или сохранением с точными шагами.
- Проверяй результат через настоящий обработчик генерации, смежные ветки, существующие регионы/реки, сохранение и отмену.
- Перед передачей изменений выполни `npm run check` на Node.js24.
- Для изменений генерации дополнительно выполни `npm run test:browser` после сборки.
- При изменении поведения обнови связанные RIV/ROAD-правила, примеры и тесты в том же PR. Не меняй правила ради прохождения тестов.
- Не смешивай изменение алгоритмов с широким рефакторингом.
- Не называй конечный набор успешных прогонов доказательством отсутствия любых ошибок.
- Недоступные проверку или публикацию явно укажи как незавершённые.
- Сохраняй уникальные требования, стабильные ID правил и отрицательные evidence при очистке.

Сохраняй GitHub Pages workflow из main; перенос размещения — отдельная задача. Ночные планы пишут только в agent-operations. Merge, деплой, публичные сообщения и маркетинг — отдельное согласование конкретного результата.

Каноническая модель: docs/strategy/score-model.md. Предыдущие имена — указатели/архив, не альтернативная шкала. Реестр задач — agent-operations/agent-work/backlog.json; Trello — краткая проекция. Процедуры разработки: [development-workflow.md](docs/development-workflow.md).
