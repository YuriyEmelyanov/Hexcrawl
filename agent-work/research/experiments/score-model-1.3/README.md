## Как считается оценка

1. Единица — уникальное действие мастера в профиле игры, с объектом, исходом и приёмкой. Синонимы и вторые источники той же операции объединяются. Отдельная общая функция с двумя проверенными игровыми профилями даёт эффект в обеих играх. Её разработка в очереди учитывается один раз.
2. Полная поддержка даёт 1, отсутствие даёт 0. При фиксированном списке исходов — доля подтверждённых исходов. Когда историческая приёмка доказывает только существенную часть результата и ещё не разделена на атомарные проверки, используется промежуточная ступень 0,5. Это договорённость модели, не измеренная доля кода. Unknown не даёт подтверждённого кредита, остаётся в знаменателе и показывается отдельным счётчиком и интервалом. Не применимое исключается с основанием. Детали — baseline.json и отчёт калькулятора.
3. Для игры g и уровня L покрытие равно сумме кредитов, делённой на число применимых требований этой игры и уровня. Для целевого топ-20 каждый игровой слот имеет равный вес 1/20. Пока корпус игры пуст, его вклад в нижнюю границу 0, в верхнюю 1. Границы условны на фиксированный каталог: новые требования меняют знаменатель. Абсолютные заработанные единицы хранятся без потолка. Улучшение одного правила с 0 до 1 при N правилах игры повышает её оценку на 100/N п.п., а уровень топ-20 на 5/N п.п.; округляем только при показе. Нет порога в пять полностью готовых игр. Полная поддержка игры требует закрытого тематического корпуса и полного результата по каждому применимому правилу.
4. Общие критерии уровня образуют вторую шкалу. Для L1 это создание и редактирование, масштаб, переносимость содержимого, читаемость, сохранность, скорость подготовки, использование. Для L2 это сохранение экспедиции и выдача информации участникам. Для L3 пока выделен проверяемый обмен с внешней механикой. Надёжность и статистика распространяются на все использующие их сценарии; числа сверяются один раз на релиз. Исторические критерии и целевые пороги 1.2 сохранены для миграции в legacy-criteria.json. Полный зачёт старого критерия из одной новой строки не выводится.
5. Лидерство оценивается отдельно на каждом уровне. Сравниваются одинаковые задания мастера одной редакции игры на одинаковых входах против именованной альтернативы. Сначала сравниваются правильность, потери и возможность завершить, затем время/ручные действия. Без сравнительного прогона публикуется готовность и пробелы, статус лидерства неизвестен. L3 можно расширять по мере принятия интеграций.
6. Приоритет работы: блокирующая потеря результата → уровень L1, затем L2, затем L3 → место игры в актуальном сценарном рейтинге (create / play_now; L3 по прямой зависимости). При равной позиции выбирать большее подтверждаемое приращение с учётом переиспользования, стоимости и зависимостей. Unknown порождает проверку, установленный пробел — кандидата на разработку.

## Изменение требований и оценка PR

На каждый пересчёт фиксируются release SHA, версия критериев, когорта, границы корпуса и доказательства. Для влияния PR сравниваются родитель и merge на одном каталоге. Поправка каталога считается на одном SHA по двум редакциям и показывается отдельно. Исторические оценки сохраняются. Регрессии дают отрицательную разницу. Для одинакового результата в новом PR повторное начисление равно нулю.

Пример: UI даёт 1 и 6 миль, расчётный модуль также знает 12 и 24. Семейство «выбор физической сетки» имеет 2/4. Если владелец включит 60 миль, оно станет 2/5 на том же релизе. Для L1 общего блока с 16 критериями это 65,625% → 65,0%. Для плавных русел и дорог в каталоге есть два общих требования; сначала фиксируются контрольные изломы, сохранность концов и переправ, вид на карте и PNG. Каждая закрытая строка даёт 1/16 общей оценки L1. При дроблении существующей строки на подусловия её вес сохраняется. Замена одного правила несколькими возможна только с отдельным объяснением изменения знаменателя.

## Решение для разработки

Для PF2 правило PF2-RM-044-L1-v2 сменило состояние с «отсутствует» на «работает». После PR509 в гексе 2,0 сохраняются одновременно горы и снежно-ледяная поверхность. Повторно разрабатывать эту возможность не требуется. Конкретный открытый пробел L1 игры №1 по create: DND5-2014-020-L1-v2-draft, отметка тонкого льда на водной поверхности. Штатный слой снега и объект препятствия на суше не выполняют эту операцию. Следующую приёмку можно привязать к сохранению и повторному открытию выбранного водного гекса с тонким льдом без изменения соседнего участка. Это исследовательская рекомендация стратегу.
