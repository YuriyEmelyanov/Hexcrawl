# Модель 1.3-rc8 · три оценки по 1000

Решением владельца от 20 ноября 2026 года для каждого уровня установлены равные веса. Итог уровня = (общие функции + поддержка сценарного топ-20 НРИ + рыночная позиция в этом сценарии) / 3. Каждая составляющая оценивается от 0 до 1000. Максимум каждой в итоге уровня равен 1000/3. Округление выполняется после расчёта. В отчёте три самостоятельных итога.

| Уровень | Общие функции и игровой корпус | С кем сравниваем аудиторию |
|---|---|---|
| L1 · подготовка карты | Создание, наполнение, правка и сохранение. Топ-20 create. | Инструменты, которыми мастера создают или готовят региональную карту. |
| L2 · ведение | Навигация, маршрут, состояние экспедиции и выдача информации во время игры. Топ-20 play_now. | Инструменты, которыми мастера ведут гекскроул. Foundry VTT включается по фактически относящемуся к этому сценарию использованию. |
| L3 · сопутствующие механики | Для каждой принятой механики рассматриваем интеграцию. Корпус и сценарный топ-20 ещё предстоит определить. | Инструменты, которыми пользуются для принятого круга сопутствующих механик. Границы сравнения пока открыты. |

Вклад общих функций берём из приёмки ядра с учётом применимых весов, сохранности и согласованных порогов качества. Игровая часть равна сумме по 20 играм величин 50 × доля принятых правил данной игры на этом уровне. Частичная приёмка даёт дробный вклад. При N равновесных правилах в игре полная приёмка одного ранее неподдержанного правила добавляет 50/(3N) к итогу уровня.

Для каждой рыночной позиции переиспользуем [шкалу топ-100](../rc7-top100/README.md). При 100-м месте вклад в итог уровня равен 10/3, при 50-м — 510/3 = 170, при первом — 1000/3. Первое место означает рыночное лидерство в данном сценарии. Полные 1000 баллов уровня требуют полного результата всех трёх частей.

Сравниваются уникальные внешние пользователи приложений за один период и для одной задачи. Приложение может войти в несколько списков с отдельно обоснованной аудиторией каждого сценария. По примеру владельца использование Foundry для ведения учитывается в L2. Импорт готовой карты в Foundry сам по себе не подтверждает создание карты. Посещение HexCrawl с неизвестным сценарием входит в общий счётчик пользователей. Для места в L1, L2 или L3 нужна привязка к задаче. При неизвестной аудитории конкурента, который может входить в рынок уровня, передают интервал от 0 без верхней границы либо учитывают его среди возможных пропусков; пустой каталог с неизвестной полнотой не доказывает первое место.

**Первый пересчёт на сохранённых данных PR509.** Состав и приёмки перенесены из [зафиксированного отчёта rc3](../rc3-quality/report.json). Сопоставимого замера положения в трёх рынках пока нет. Таблица показывает границы, обусловленные имеющимися свидетельствами и зафиксированным каталогом.

| Уровень | Общие функции, подтверждённый минимум | Игры, подтверждённый минимум по полной приёмке | Рыночное место | Итоговый диапазон |
|---|---:|---:|---|---:|
| L1 | 11,11 | 0 | неизвестно | 3,70–951,88 |
| L2 | 15,31 | 0 | неизвестно | 5,10–798,92 |
| L3 | корпус открыт | корпус открыт | неизвестно | 0–1000 |

Указанные минимумы отражают объём оформленной приёмки на историческом срезе. При добавлении наблюдений диапазоны пересчитываются. Любая неизвестная треть сохраняет полный вес. Последующие проверки конкретных правил переносятся в данные модели после сверки их критериев качества. Исторические снимки релизов и рейтинг привлекательности игр версионируются отдельно.

[Расчёт и проверки](verify.mjs) запускаются командой `node verify.mjs` из этой папки. Проверяются независимость рынков на синтетическом примере Foundry, места 100 и 101 и открытый L3. [Входы](baseline.json) · [Расчёт без округления](report.json).
