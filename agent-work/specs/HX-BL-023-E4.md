# HX-BL-023 / E4 — препятствия
Версия E4-1.0, 31.10.2026. Статус: ready_for_development. Аналитическая спецификация, не реализованная функция.

Основание: родительская спецификация2.3 и owner-decision-2026-10-28-editor-additional-functions-approved. Следующий утверждённый этап после принятого E3. База разработки — d7bb38fbcee367621e5f5ce9fbaf369fbc775e0a, PR480; E3 пока не опубликован. Создать отдельную ветку от этого SHA; не изменять принятый PR480. После изменения базы повторно проверять интегрированный пакет. Main и публикация требуют отдельного разрешения.

## Цель и границы
Ведущий добавляет преграду между существующими соседними гексами, удаляет её или переносит на другое ребро. Сценарий develop_existing: убрать случайную преграду и поставить её у нужного перевала, сохранив карту и продолжив работу. Create_from_scratch: после создания суши обозначить препятствие в Classic или Mythic. Это L1 подготовка карты; не расчёт движения, видимости, обхода или правил путешествий L2/L3. Типы/названия препятствий, рисование цепочки одним жестом и массовые операции вне E4.

## Фактическая основа и модель
На указанном SHA src/modes/obstacles.ts хранит {kingdomId,hex,neighborHex,edgeKey}; persistence.ts требует существующее королевство и оба гекса внутри его области. Генератор выбирает24 ребра, исключая воду/реки/путь, использует RNG. App показывает список «Рядом», красные линии, включает препятствия в snapshot и запрещает дорожные пересечения. Прямого редактора нет. edgeKey — ключ геометрии из getHexEdgesAsVertexPairs, НЕ pairKey осевых координат. Перенос меняет edgeKey, поэтому он не может быть устойчивым ID.

Ввести JSON v5 и стабильный положительный safe-integer id у каждого препятствия. Поля hex,neighborHex,edgeKey сохраняются; kingdomId становится необязательной реальной принадлежностью. counters.nextObstacleId — max(existing id)+1 или больше, не переиспользовать удалённый ID в текущей ветви истории. Не использовать RNG, время или фиктивное королевство для ID. Добавление при исчерпании safe-integer отклонить до изменения документа. Undo/Redo восстанавливает снимок счётчика вместе с картой; новая ветка после Undo может использовать восстановленный счётчик, внешних глобальных ссылок на ID не вводится.

Для ручного размещения kingdomId определяется по области kingdomKeys: если оба гекса внутри одного существующего королевства — его ID, иначе поле отсутствует. При переносе пересчитать принадлежность; показать смену/снятие связи до выбора конечного ребра. id сохраняется. Это не смена региона или игрового режима; ручная правка не восстанавливает квоту24. Генератор новых королевств сохраняет нынешние правила и порядок выбора24 ребер; ID присваиваются при атомарной фиксации из общего счётчика, без дополнительных RNG-вызовов. Смена UI-режима не удаляет препятствия и не переписывает принадлежность.

## Совместимость и импорт
Продолжить читать v2/v3/v4 через прежнюю валидацию. После успешной проверки, до apply/history, детерминированно присвоить препятствиям ID по лексикографически отсортированным edgeKey (1..N), не менять порядок массива и старые геометрию/kingdomId. Пустое/отсутствующее obstacles => [], nextObstacleId=1. Существующие миграции RNG/заметок/terrain остаются прежними. Повторный импорт одного файла даёт одинаковые ID; история не импортируется.

v5 требует уникальные ID, уникальные edgeKey, корректные целочисленные координаты соседей и совпадение общего геометрического ребра. Если kingdomId указан — сохранить действующие проверки реальной области/ссылки. Отсутствие kingdomId допустимо и в Classic, и в Mythic. nextObstacleId валидировать/нормализовать вверх относительно max по общей политике счётчиков; переполнение — видимая ошибка без изменения карты. Путь ошибки включает map.obstacles[index] либо counters.nextObstacleId. Не ужесточать задним числом правила старых допустимых карт: миграция и последующий v5 round-trip должны сохранять прежние препятствия даже там, где новые команды уже не разрешат размещение. Ограничения новых команд ниже применяются к новому целевому ребру, не запускают починку всей карты.

Экспорт всегда v5, включая карту без препятствий; явно указать пользователю, что старые версии приложения v5 не читают. Все save/history/snapshot/импорт/PNG пути использовать с новой моделью, без потери неизвестных вне E4 поддерживаемых полей. Неверный импорт, отмена выбора файла и ошибка подготовки сохраняют документ/историю/redo/счётчики/RNG. Корпус совместимости v2/v3/v4 расширить v5; старые fixtures не заменять на новые.

## Размещение и инварианты
Два гекса должны существовать на карте и быть соседями, оба сухие; нельзя внешнее ребро в ещё не созданный гекс, ребро реки, озера/моря или сегмента road/trail. Использовать действующие источники воды/речных edgeKeys/road pairKeys, а не цвет или SVG. Не разрешать второе препятствие на занятом ребре в обратной ориентации. Разница высот влияет на генерацию, но не ограничивает ручное размещение на сухом ребре. Не создавать/удалять пути, переправы, воду, POI или заметки автоматически. Удаление существующего препятствия всегда допустимо и не вызывает восстановления квоты.

Add: одна атомарная операция, один новый ID. Remove: удалить ровно выбранный ID. Move: исходный объект остаётся на месте до принятого целевого ребра; затем один commit меняет только его геометрию/принадлежность. Выбор исходного ребра снова — no-op без истории/счётчиков, завершает перенос. Ошибка цели оставляет перенос активным с объяснением. Устаревшая ссылка на объект или изменение документа между выбором и фиксацией — отмена черновика с сообщением, никаких частичных setters. Все три операции используют общий механизм транзакций и Undo/Redo; no-op не стирает redo.

## UI и состояния
Общий Edit/Done и прямое взаимодействие E2 сохраняются. В обычном режиме список препятствий в «Рядом» доступен для чтения. В Edit строка «Препятствие · к 1,0» выбирает конкретный ID и подсвечивает одно ребро; рядом доступны «Перенести» / Move и «Удалить» / Delete. Удаление одной преграды не удаляет зависимые объекты, поэтому фиксируется сразу с доступным общим Undo, без лишнего модального подтверждения. Если будущая реализация обнаружит зависимые данные — не удалять их молча, вернуть ограниченный вопрос аналитику.

«Добавить препятствие» / Add barrier в информации выбранного гекса раскрывает его6 направлений. Каждая строка указывает соседа и доступность; занятые/несуществующие/водные/речные/дорожные цели имеют текстовую причину и не фиксируются. Нажатие доступной строки или соответствующего ребра карты сразу добавляет объект. В переносе тот же выбор вокруг выбранного целевого гекса; можно выбрать другой гекс карты и затем его ребро. Источник подсвечен сплошным, предлагаемая цель пунктиром, текст «Выберите новое ребро». Не показывать новый блок инструментов над основной информацией, не вводить постоянный режим выбора «гекс/регион».

Escape и «Отменить перенос» / Cancel move снимают только черновик. Done, смена выбранного объекта, Undo/Redo, импорт, очистка/новая генерация и начало редактирования другого поля отменяют незавершённый выбор до соответствующего действия. Экспорт сохраняет текущую подтверждённую карту, не фиксируя цель; предварительно снимает черновик. Панорамирование, zoom и поворот сохраняют выбранный источник/режим; не перемещают препятствие. Текст ошибки доступен через live-region, не только цвет. После удаления фокус возвращается к блоку «Рядом», после переноса — к строке объекта.

Keyboard: Tab, Enter/Space на строках/доступных рёбрах; aria-label включает оба гекса и действие. Для пересекающихся областей hit-target выбирать ровно одно ребро через список. Эффективные44×44 CSSpx при разных zoom, видимый focus, без горизонтального overflow на390px. Подписи RU/EN; все6 направлений доступны с клавиатуры и touch без hover. Макет E4-UI1 рядом со спецификацией — предложение, не реализация; ответ владельца не блокирует разработку.

## Приёмка
- AC01: Classic без kingdoms: Add на сухое свободное ребро, ID/nextObstacleId; обратная ориентация не создаёт дубль; one Undo/Redo точны.
- AC02: Mythic: добавить/удалить/перенести, включая выход из области и вход в другую; id стабилен, kingdomId реален/отсутствует, квота не перебалансируется; режим UI не меняет документ.
- AC03: вода, река, road, trail, внешний/несоседний/занятый edge дают видимый отказ с точным no-op, без расхода RNG/ID/истории. Проверить каждую причину отдельно.
- AC04: перенос на исходное ребро no-op; отмена/ошибка/устаревшая ссылка безопасны; валидный перенос ровно одна история. Несвязанные объекты побитово/структурно неизменны по контракту снимка.
- AC05: старые v2/v3/v4 с/без препятствий мигрируют детерминированно; v5 round-trip без потерь; duplicate ID/edge, неверная геометрия/kingdom/overflow отклонены атомарно. Старые допустимые файлы не теряются из-за новых ограничений команд.
- AC06: две копии редактированной карты дают одинаковое разрешённое продолжение Classic/Mythic; дороги не пересекают ручные препятствия; генератор24 и RNG-результат относительно базы сохраняются, кроме новых ID. Генерационный отказ атомарен, не скрытый retry.
- AC07: реальные UI add/move/remove и Escape/Done/export/import/Undo interleavings на production build; pan/zoom/rotate; RU/EN desktop/390;44px, фокус, клавиатура, точное выделение одного ID.
- AC08: PNG и SVG-сериализация для PNG сохраняют линии, исключают editor overlays; JSON v5 включает ручные правки; E1–E3, заметки и Find не регрессируют.
- AC09: npm run check на Node24; обязательный полный browser после build и существующий world-random gate. Независимое review конкретного SHA с score_assessment1.2 и ограничениями. E3+E4 перед общим выпуском проверяются вместе.
