# HX-BL-041 / TAGS — универсальные теги и Mythic Bastionland

Версия 1.1 • 03.11.2026 • Статус: спецификация для передачи разработчику, реализация не начата.

## 1. Цель и полномочия

Мастер получает описательные свойства объектов непосредственно в карточке карты. У нового удела описание уже заполнено; у природы доступны компактные названия таблиц, которые можно бросить по необходимости. Числа кубов видны рядом с результатами, любой компонент можно перебросить отдельно.

Прямое поручение владельца разрешает подготовку спецификации и макета. Оно не является отдельным разрешением реализации или публикации. Первый этап — общий механизм и ограниченный набор таблиц для существующих объектов карты. Рыцари, мифы и генераторы на их страницах — следующий этап после этого; полная инвентаризация их разворотов и создание NPC сейчас исключены.

Источники: приложенные Mythic_Bastionland_RUS.pdf и Mythic Bastionland Quickstart.pdf, печатные страницы 22–25; назначение таблиц — страницы 14 и 19. Каждая таблица здесь — импровизационная подсказка, не обязательная характеристика и не законченный сюжет. Два d12 выбирают независимо по одному результату из каждого столбца. Это не сумма 2d12 и не одна строка для обоих компонентов.

## 2. Требования владельца и решения спецификации

**Владелец задал:** отдельную сущность «тег» для разных объектов и режимов; название до генерации; число куба рядом с каждым результатом; клик по кубу — анимация и переброс только этого компонента; возможность бросить подходящие теги биома/озера/реки; общий код отдельно от Mythic Bastionland; рыцарей и мифы после текущего этапа.

**Решения этой спецификации:** точная матрица ниже, автоматическое заполнение трёх тегов удела, владелец биомных тегов — экземпляр региона, не глобальный тип биома; доступность бросков в просмотре без включения редактирования; длительность анимации 350 мс; сохранение v6; фиксированный первый набор без редактора пользовательских таблиц. Это детализация в обсуждённых границах, а не дословные требования владельца.

## 3. Объём и матрица

| Владелец тега | Автоматически при создании нового объекта в MB | Доступно по нажатию | Пояснение |
|---|---|---|---|
| Удел любого подтипа; Престол | Удел, Подворье, Замок | Еда, Товары, Роскошь | Теги остаются компактными продолжениями существующего объекта; названия определений доступны невидимо для навигации/доступности, без новых карточек |
| Экземпляр региона биома | — | Земля, Флора, Фауна | Одно описание для данного региона; не одинаковые результаты у всех лесов мира |
| Озеро с существующим lakeId | — | Вода | Одна запись на всё озеро, а не на каждый водный гекс |
| Река с существующим river.id | — | Вода | Одна запись на реку; ветви с разными ID — разные владельцы |
| Уже существующий ориентир | — | Особенность, Чудо или Иномирье | См. отдельное правило ниже; никаких новых POI ради броска |

Для ориентира «Особенность» доступна Жилищу, Монументу, Опасности и Руинам; «Чудо» — Монументу и Святилищу; «Иномирье» — Проклятию. Это выбранная продуктовая применимость, а не утверждение, что книга предписывает такое соответствие. Мифы исключены, даже если присутствуют как маркеры. Ориентир со Святилищем пока получает описательную подсказку места без генерации Провидца.

Удел и Престол используют один набор: Престол — роль удела, не второй объект с отдельным дублем тегов. У других режимов первая поставка не включает новые таблицы: им доступен общий API и безопасное чтение сохранённых результатов MB.

**Отложено из страниц 22–25:** Небо, Погода; Драма, Беда, Вести; все таблицы Людей; все таблицы Боя, включая Конфликт. Причина: текущий этап описывает места L1; события и участники потребуют собственного времени, связей или контекста сцены. Будущая система может применять тот же механизм к состоянию исследования/событию. Флора/Фауна сейчас дают только описательные подсказки, не таблицы встреч или рисков.

## 4. Поведение и интерфейс

1. Существующая информационная карточка и все её строки сохраняются. Теги добавляются в продолжение существующей строки своего объекта: название/иконка объекта → кубы с результатами → текст. Не создавать отдельные карточки, панель «Описание», дублирующие заголовки или новые тулбары. При нехватке ширины содержимое естественно переносится, без постоянного нового блока.
2. До первого броска — текстовая кнопка «Удел +» либо «Вода +». Нажатие генерирует все компоненты одним действием истории. Предложенные доступные теги компактно переносятся на следующую строку; общая панель из 36 таблиц не создаётся.
3. Для независимых столбцов: существующая строка Удела → иконка d12 с выпавшей цифрой внутри → «Тёмный» → вторая иконка d12 с выпавшей цифрой → «Башня». Обозначения d12/d6 рядом с кубами, технические подписи, инструкции и версия не отображаются. Число внутри — выпавшее значение, а не число граней. Визуальная форма различает типы кубов; невидимый aria-label содержит тип и назначение.
4. Клик по кубу меняет только его компонент. Сам текст результата не запускает переброс. Повтор старого числа законен; повторять бросок автоматически ради отличия нельзя. Заголовок заполненного тега не служит скрытой кнопкой переброса всей пары.
5. На первом броске оба куба анимируются; при перебросе — только нажатый. Длительность 350 мс, итог выбирается один раз. Нет звука, полноэкранного окна, 3D-физики и скачков высоты строки. При reduced-motion — мгновенное обновление без вращения.
6. Результат и счётчик RNG атомарно фиксируются сразу при принятии действия; анимация — только отображение. Таймер не записывает данные. Смена выбора или закрытие панели не отменяет принятую правку и не переносит результат к новому объекту.
7. На время анимации блокируется повторный бросок всего данного тега; другие теги доступны, если нет глобальной операции. Блокировка не зависит от таймера после размонтирования. События адресуются по ownerRef + definitionId, не по текущему выделению из замыкания.
8. Во время генерации, импорта, незавершённого черновика дороги/препятствия действуют существующие блокировки мутаций. Куб disabled с краткой подсказкой причины; чтение доступно. Нельзя принудительно завершать черновик ради броска.
9. Броски доступны в обычном просмотре. Редактирование результатов вручную — в существующем режиме «Редактировать»: редактируется только текст текущего языка, число сохраняется как источник броска, появляется ненавязчивая отметка «изменено». Переброс заменяет ручную редакцию данного компонента; Undo восстанавливает её. Нового общего редактора таблиц нет.
10. Enter/Space работают на нативных кнопках; доступное имя: «Перебросить Удел, стиль; d12, выпало 1: Тёмный». Обновление объявляется через polite live-region один раз после действия, без озвучивания кадров. Видимая грань близка к высоте текста: не больше1em–1.15em: при16px тексте16–18px, не30/36/44px. Кнопка не создаёт новую крупную строку; постоянно видимую геометрию ради touch target не увеличивать. Текст и интервалы существующей карточки не увеличивать ради кубов, focus-ring различим. На 390 и 320 px нет горизонтальной прокрутки; строка переносится между компонентами, куб и относящийся текст не разрываются.

## 5. Контракт общего механизма

Имена ниже задают контракт, не обязательные имена физических файлов.

```ts
type TagOwnerRef =
  | { kind: 'region'; id: number }
  | { kind: 'poi'; regionId: number; hexKey: string }
  | { kind: 'lake'; id: number }
  | { kind: 'river'; id: number };

type TagDefinition = {
  id: string;                 // namespace, например mb.holding
  version: number;            // неизменяемая версия таблицы
  labels: Record<string,string>;
  components: {
    id: string;               // style, feature; не индекс UI
    dice: { count: number; sides: number; selection: 'single' | 'sum' };
    tableId: string;
  }[];
};
type TagComponentValue = {
  componentId: string;
  diceValues: number[];
  entryId: string;
  textSnapshot: Record<string,string>;
  overrideText?: Record<string,string>;
};
type TagInstance = {
  definitionId: string;
  definitionVersion: number;
  owner: TagOwnerRef;
  components: TagComponentValue[];
  revision: number;
};
type TagState = { schemaVersion: 1; instances: TagInstance[];
  rollCounters: Record<string, number> };
```

Ключ экземпляра — canonical ownerRef + definitionId. Название/биом/язык/номер строки в UI не участвуют в идентичности. В MB каждый компонент — count=1, sides=12, selection=single. Общий слой поддерживает однокубовый выбор и сумму нескольких одинаковых кубов; частные схемы вроде d66, формулы, связанные броски и редактор контент-паков не входят в первую реализацию. Неизвестный тип будущего вычисления не интерпретировать догадкой.

**Слои:** общий реестр определений/таблиц и независимый RNG/валидатор → сервис команд createTag/rerollComponent/editComponent → общий UI; отдельный MB-пакет данных и policy доступности/автозаполнения. Ядро географии не импортирует таблицы MB. Версия каталога фиксируется в definitionVersion, выпавшие числа и текстовые снимки сохраняются; обновление словаря не переписывает старую карту.

Идентификаторы владельцев опираются на существующие ID: region.id, river.id, lakeId и составной ключ region.id + координата POI. У POI сейчас нет общего UUID; новая глобальная миграция POI вне объёма. При будущем переносе POI потребуется явная миграция ownerRef в той же транзакции; это обязательный контракт расширения, не обещание текущей функции. Биомные теги принадлежат region.id; локальный biomeOverride гекса не создаёт отдельного экземпляра. В таком гексе группа явно подписана «Описание региона», чтобы не представлять её как описание изменённого гекса.

## 6. Случайность, история и жизненный цикл

Домен тегов отделён от существующих geography/POI/toponym random streams. Базовое зерно домена производится из world seed + версии механизма. Бросок детерминирован по (зерно тегов, ownerRef, definitionId/version, componentId, локальный порядковый номер броска). Счётчик хранится на компонент; первый бросок использует 0, последующие — +1. Порядок открытия карточек и броски других тегов не влияют на результат данного компонента. Отображение и анимация не вызывают RNG. Диапазон равномерный; modulo bias исключён rejection sampling или уже доказанным равнораспределённым генератором.

Первоначальные теги новых MB-уделов формируются после окончательной раскладки POI, внутри той же транзакции создания королевства. Ошибка откатывает географию и теги вместе. Перегенерация восстанавливает снимок до действия и создаёт теги для новой финальной раскладки, не расходуя географический поток. Автоматические теги нового вручную добавленного удела включаются в одну транзакцию добавления POI; переключение вида существующего POI в Престол не дублирует теги.

Первый бросок, отдельный переброс и ручная правка — по одной транзакции DocumentSnapshot; снимок включает TagState и счётчики. Undo/Redo восстанавливает точные значения без нового броска. Undo первого броска возвращает кнопку без результата; повтор того же действия после Undo при восстановленном счётчике даёт тот же результат. Даже выпавший повтор числа считается броском и увеличивает счётчик; Undo возвращает счётчик. Теги автоматически сгенерированного удела отменяются вместе с созданием королевства, без шести отдельных команд истории.

Переименование объекта не меняет теги. Смена вида POI сохраняет теги на существующем месте как неактивные, пока тип несовместим; обратная смена восстанавливает их. Удаление POI/реки/озера/региона удаляет его записи и счётчики в той же отменяемой транзакции; Undo восстанавливает. Повторно созданный на том же месте объект после удаления не получает старый тег. Существующие мутации географии не должны молча объединять владельцев разных рек или озёр: при merge/split использовать действующие стабильные ID; исчезнувшие владельцы удаляются с историей, новый ID начинает без тегов. Окончательное географическое обновление валидируется до commit.

Смена MB→Classic не удаляет и не перебрасывает теги MB: заполненные результаты доступны в свёрнутой группе «Mythic Bastionland», новые MB-теги не предлагаются. Возврат MB восстанавливает доступность. Приложение не меняет типы объектов для совместимости тегов.

## 7. Сохранения и валидация

Прочитанный main принимает JSON v2–v5, текущий экспорт v5. Предлагается экспорт v6 с необязательным map.tags: TagState; версии2–5 мигрируют в пустой TagState без бросков при загрузке. Старые MB-уделы получают доступные кнопки, но не заполняются автоматически при открытии. Массовой тихой миграции описаний нет. Карты с v6 не обещают открытие в старой версии приложения.

В UI-состояние не сохраняются animation/busy/timer/focus. История, как в текущем контракте, не переносится JSON-файлом; импорт — одна отменяемая команда, после него можно отменить сам импорт и новые действия. Снимки generationHistory/backup должны включать теги и счётчики; недостаточно расширить только exportMap.

Импорт полностью подготавливается до первой записи React state. Валидируются schemaVersion, owner references, отсутствие дубликатов ключа, компонентные ID, число и границы diceValues, неотрицательные safe-integer счётчики/revision, текст как обычный текст, длина/объём. Пределы первого контракта: 64 тега на владельца, 8 компонентов на тег, 256 Unicode-кодовых точек на текст одного языка, 8 языков на snapshot/override; общий JSON остаётся в существующем лимите приложения, новый меньший общий лимит не вводить. Экспорт собственных допустимых состояний должен проходить обратно.

Известная версия определения: число, entryId и snapshot должны соответствовать таблице; ручная правка только в overrideText. Неизвестное namespace или более новая версия таблицы при корректной структуре сохраняется без потерь и показывается как доступный только для чтения текстовый снимок с числом; переброс отключён с объяснением. Неизвестный формат TagState отвергается до изменения карты. Висячая ссылка, дубликат либо неправильные кубы — отказ всего импорта, текущая карта/выбор/история неизменны. HTML в тексте отображается текстом, не исполняется.

## 8. Словари и перевод

Разработчик переносит нужные таблицы из приложенных источников, сохраняя порядок1–12 и независимость столбцов. В состав поставки входят только таблицы матрицы раздела3. Русский и английский тексты связываются стабильным entryId, а не сравниваются по строке. Не склеивать слова в грамматически согласованную фразу через LLM: показывать два независимых компонента. Результат остаётся подсказкой мастеру.

В переводе есть расхождения: Feature/Seat переведено как «Холм», Cairn как «Дольмен», Glades как «Низины», часть близких стилей различается. До реализации зафиксировать ledger перевода по включённым таблицам: original / supplied translation / выбранная RU-подпись / причина. Семантику задаёт оригинал при явной ошибке; видимая правка переводного термина перечисляется в developer handoff. Не смешивать исправление перевода с созданием новых объектов. Книжные PDF в репозиторий не копировать.

## 9. География и пределы интерпретации

«Земля» не меняет текущий biomeId, «Вода» не меняет гидрологию, «Мост»/«Башня» не создают POI, дорогу или переправу. Возможное несоответствие вроде леса в подсказке горного региона не скрывается фильтрацией броска: таблица остаётся исходной; мастер использует её как локальную деталь большого гекса либо перебрасывает. Постоянная подпись «Подсказка» и пояснения рядом с результатом не выводятся. Если в будущем нужна фильтрация по географии, это отдельное правило распределения, а не случайная правка диапазона d12.

## 10. Приёмка

| ID | Сценарий и проверяемый результат |
|---|---|
| TAG-01 | Новое MB-королевство: у одного Престола и трёх уделов после финального размещения ровно по3 заполненных автоматических тега; по2 независимых числа1–12. Другие POI и старые регионы не меняются |
| TAG-02 | Первый клик «Вода» на озере создаёт одну пару; выбор другого гекса того же lakeId показывает ту же пару; соседняя река имеет отдельную пару |
| TAG-03 | Подставленные независимые результаты1 и2 дают первые записи соответствующих столбцов; переброс первого компонента не меняет второй, включая его override/счётчик |
