## 1. Цель, база и границы

Мастер вводит собственные сведения о месте прямо в карте и сохраняет подготовку между сеансами. Одна многострочная plain-text заметка на существующий гекс. Создание, изменение, очистка, JSON save/load и существующие Undo/Redo. Общая возможность в classic/Mythic, на суше, озере и море; стартовый гекс без мира и кандидаты будущих регионов заметки не получают.

Проверенная база: main@02c2fd5fcbdb2042f2708709ce4f20dfd7354787; дерево3892b812c0910eced73c8abf676f17cb267bba11; src/App.tsx blob a608910031f4c83ce545feebad1618cb5c41f409. Ветка474 не является базой и не включается. Перед реализацией сверить main; если он изменился, проверить пересечение изменений и записать новую базу.

Прочитаны действующие видение и score1.2, включая сценарий объединения модулей, процесс, backlog/approvals/budget/feedback/lessons, каталог HX-FB-002, main src/saveValidation.ts, существующие transaction/saveSafety/browser save-history, docs/specs/HX-NEXT-001.md. Исторические v2-only/RNG-ограничения последнего документа заменены опубликованным v3/RNG контрактом; его атомарность и точная история остаются обязательными.

Не входят: генерация текста/историй/слухов, AI, парсинг книг и сборка модулей, модель фракций/ссылок, rich text/HTML, поиск, облако, совместная работа, карта игроков и права доступа; новая оптимизация, cleanup тестов, замеры474. Заметки — данные ведущего, а не система секретности. В полный JSON входят все заметки; мастер не должен считать этот файл экспортом для игроков. Заметки не отображляются на изображении карты/PNG/SVG, не меняют seed, потоки RNG, имена, биомы, POI, воду, дороги и геометрию.

## 2. Пользовательское поведение и UI до/после

**До:** выбран гекс1,0, лес со святилищем; текст о пропавшем жреце находится вне карты.
**После:** в существующем блоке «Информация о выбранном гексе», после сведений о месте и до отладки, показано поле **«Заметки мастера»** с текстом «Жрец пропал. Следы ведут к северному броду». Есть явное сохранение; после JSON export/import тот же текст у1,0. В другом гексе своя заметка. Undo возвращает прежний текст, Redo — новый.

UI-01. Связанная с label многострочная textarea, обычный шрифт и оформление текущей панели. RU «Заметки мастера», EN «GM notes». Placeholder не заменяет label. Для пустой заметки поле пусто; без автоматического шаблона/текста. Доступно без мыши, видимый focus, без горизонтального переполнения на390px. Enter вводит перенос, не подтверждает форму и не управляет картой; стрелки и пробел в textarea не панорамируют карту.

UI-02. Редактирование локального черновика. При отличии от сохранённого текста доступны «Сохранить»/Save и «Отменить изменения»/Cancel changes; видно «Изменения не сохранены»/Unsaved changes. Save сохраняет весь текст одной логической транзакцией. Cancel changes возвращает сохранённый текст без записи истории. Пустой текст после удаления содержимого и Save очищает заметку. Отдельная кнопка удаления и модальное подтверждение очистки не нужны: операция обратима. Сохранение идентичного значения — no-op, не очищает redo.

UI-03. Пока есть изменённый черновик, выбор другого гекса и команды, меняющие документ/его историю (генерация, перегенерация, удаление, reset, seed, другие ручные редакторы, import, Undo/Redo), а также JSON/PNG экспорт блокируются до Save либо Cancel changes. Обработчики проверяют блокировку, одного disabled недостаточно. При попытке выбора/действия — понятное сообщение «Сохраните или отмените изменения заметки»; текущий гекс и черновик остаются. Панорамирование/zoom разрешены. Блокировка не должна мешать собственному Save/Cancel. Скрытие панели не теряет черновик; при повторном открытии он доступен. Смена языка/представления не сбрасывает его. Это исключает скрытые авто-коммиты и экспорт старого текста.

UI-04. Во время import/kingdomJob/pendingRegen редактор и Save/Cancel изменения документа недоступны по существующим busy/revision guards. Запоздалый обработчик от прежнего гекса/ревизии не пишет текст в новый документ. При Undo/Redo/import открывается значение восстановленного документа, без оставшегося черновика.

UI-05. Для кандидата, пустого выбора и ещё не созданного мира редактируемого поля нет. Для реально существующей воды поле не зависит от наличия selectedRegion/POI; море может быть вне региона. Существующий гекс: ключ входит в объединение regions[].hexes и фактического terrainByHexKey; candidate без фактического гекса не входит.

UI-06. Предупреждение при закрытии/перезагрузке вкладки с несохранённым черновиком — стандартный beforeunload, где браузер поддерживает; не обещать защиту от убийства процесса. После Save данные хранятся в текущем документе и экспортируемом JSON, не в облаке/автоматическом файловом сохранении. Не вызывать сохранённую заметку «сохранённой на диск» до экспорта.

Фактические снимки разработчика: desktop и390px, RU/EN; поле с многострочным текстом, пустое, dirty и busy состояния. Текстовый пример выше — утверждённый эффект, не screenshot готового интерфейса.

## 3. Данные и совместимость

DATA-01. Добавить сохраняемый слой map.gmNotesByHexKey: Record<string,string>. Ключ — канонический axial "q,r" по существующему hexKey, включая отрицательные координаты. Один ключ — одна заметка. Не привязывать её к индексу массива региона или POI: смена биома/POI/имени не меняет заметку.

DATA-02. Значения — только строки. Сохранённый текст не trim, не переводить, не интерпретировать как HTML/Markdown, не подставлять в SVG, CSS или URL. Пробелы, Unicode, эмодзи и переносы сохраняются в JSON точно. "" при подтверждённой очистке удаляет запись (отсутствующий ключ эквивалентен пустой заметке). Строка из пробелов не считается пустой автоматически. Импортированный непустой текст сохраняется точно без редактирования, включая CRLF; при ручном изменении textarea использует браузерные LF — это результат редактирования, не миграция. Не вводить произвольное малое ограничение длины; длинный текст не обрезать молча.

DATA-03. Экспорт нового приложения — schema hexcrawl-map, version=4 с тем же generation-контрактом, что v3, и полем gmNotesByHexKey ({} при отсутствии заметок). Новое приложение читает v2/v3/v4. В v4 отсутствие поля допустимо и означает {}; null/массив/скаляр вместо объекта — ошибка. Для v2/v3 без поля — {}; если расширение gmNotesByHexKey присутствует, валидировать теми же правилами и сохранить, не молча отбрасывать. Будущие неизвестные версии отклоняются. Версия генератора/алгоритм RNG не меняются из-за версии формата.

**Почему v4:** выпущенный v3 reader допускает неизвестные поля и потеряет заметки при re-export. Он уже отклоняет неизвестную версию; новый номер позволяет старому клиенту безопасно отказаться вместо тихой потери пользовательских данных. Совместимость означает чтение новым приложением старых поддерживаемых карт, а не обещание чтения v4 старым сайтом. Не создавать «экспорт для старой версии» с удалением заметок. Согласовать сообщения ошибок RU/EN, не менять принятые миграции v2 RNG.

DATA-04. Структурная проверка каждой записи до commit: канонический ключ безопасных целых q/r, строка, ссылка на существующий фактический гекс (суша/вода). Orphan, неканонический ключ, число/объект/null как значение — отклонение всего импорта с категорией/путём поля, например map.gmNotesByHexKey["1,0"]; не фильтровать и не преобразовывать в строку. Объект обходить через own entries с безопасным созданием результирующего словаря; не использовать непроверенный ключ для прототипного присваивания. Ошибка не выводит полное содержимое заметки/файла в UI/диагностику.

DATA-05. Import — существующее read→parse→validate→prepare→commit. Независимый notes-layer подготовлен вместе с остальной картой. Ошибка чтения/валидации/подготовки не меняет документ, notes, selection, RNG или оба стека; повторная загрузка работает. Успешный импорт полностью заменяет заметки текущего мира заметками файла, не объединяет по совпадающим координатам, и обратим одной транзакцией. Загрузка старой карты очищает текущий notes-layer как часть замены документа; Undo import возвращает его.

## 4. История, генерация и удаление

HIST-01. Слой заметок включён в MapSnapshot/DocumentSnapshot, capture/copy/apply, generation backups, rollback, reset и save/import. Копии изолированы; никакой Map/объект из before не меняется последующим редактированием. Используется существующая общая история100операций в сеансе, не новый параллельный стек; между сеансами история не сохраняется. Одна Save/очистка — одна транзакция независимо от числа набранных символов. Undo/Redo восстанавливают точные заметки и соответствующий документ без новых draws RNG. После undo новая реальная Save очищает redo, отменённый черновик/no-op/ошибка — нет.

HIST-02. Добавление региона/королевства и ручные изменения на существующих гексах сохраняют все заметки прежних гексов. Связь по координате: при смене типа поверхности гекса заметка сохраняется. Никакие имена/случайности не должны пересоздаваться ради notes-only изменения.

HIST-03. Delete last region/kingdom сохраняет существующий смысл генерационной единицы. При восстановлении старого генерационного checkpoint переносит **актуальные** заметки остающихся гексов из текущего документа: старый checkpoint не должен откатывать заметки соседнего региона, написанные после его создания. Заметки исчезающих гексов удаляются только с понятным подтверждением: «Будут удалены N заметок вместе с гексами. Действие можно отменить» / EN equivalent. Отказ — точный no-op с сохранением redo. Подтверждение и удаление — одна общая транзакция; Undo возвращает исчезнувшие гексы и их текст. На гексах, остающихся в фактическом множестве, заметки не удаляются.

HIST-04. Reset при наличии заметок требует аналогичного подтверждения их удаления; Undo reset восстанавливает полный notes-layer. Без заметок поведение reset прежнее. Успешный import является явно выбранной заменой всего документа по DATA-05, дополнительный диалог не требуется.

HIST-05. Regenerate не является разрешением молча потерять ручной текст. Актуальные заметки сохраняются у всех прежних координат, существующих в итоговой карте, включая перегенерированную часть. Если предлагаемая генерация/sea-recovery убирает хоть один гекс с непустой заметкой, весь результат отклоняется атомарно: документ, RNG, notes, оба стека и generation checkpoints восстанавливаются из backup. Сообщение называет затронутые координаты/количество и предлагает сначала перенести либо явно очистить соответствующие заметки. Новый автоархив или автоматический перенос на другой гекс не входит. Обычная генерация без угрозы заметкам работает как прежде. При возможности предсказуемый конфликт выявлять до тяжёлой работы; проверка итогового множества обязательна. Нельзя частично применить внутренний шаг королевства и потом оставить потерянный текст.

HIST-06. Undo/Redo удаления/reset/import восстанавливают зафиксированное before/after, не повторяют подтверждение, генерацию или случайность. Черновик не является частью сохраняемого документа; destructive actions недоступны до UI-03.
