# HX-BL-062 · Обнаружение точек интереса в Classic

Черновик D1 для интервью, 22 ноября 2026 года. [Решение владельца](../decisions/owner-decision-2026-11-20-classic-poi-discovery.json) · [Макет карточки D1](../previews/HX-BL-062-D1/card.svg) · [Исходное поведение](../research/requirements/CLASSIC-POI-discovery-2026-11-20.md).

## Результат для мастера

Мастер открывает подготовленный регион обычного Classic, выбирает точку на карте и видит, при каком действии её можно обнаружить. У столицы указано «При прохождении». Портал может быть виден сразу, найден при исследовании или оказаться секретным. Магия у портала — пример условия, которое мастер описывает сам. Автоматическое раскрытие тумана, изменение карты игроков, броски персонажей и правила заклинаний выходят за пределы задачи.

## Создание и чтение

- R1. Назначать режим один раз при успешном создании объекта (генерация региона и ручное добавление). Каждая отдельная точка имеет собственное значение. Английская локаль использует те же три значения с переведёнными подписями. В карточке строка следует за названием и типом. Выбор другого гекса, смена языка, масштаба и поворот карты читают сохранённую запись. На 390 px длинная улика переносится внутри карточки.
- R2. Предложение D1 — применять одну таблицу к центральным и дополнительным сухопутным точкам и отдельную группу той же таблицы к водным. Приоритет определяется фактическим типом и принадлежностью к воде. Для одномильной проекции существующей точки читать тот же объект. Участие самостоятельно созданных одномильных мест вынести на интервью. Типы, встречающиеся только в Mythic, остаются в своём профиле.
- R3. Для фиксированного значения выбирать его непосредственно. Для случайного — детерминированный выбор из разрешённого множества; на одинаковой исходной карте и при одинаковом создании результат повторяется. Предложение — изолировать выбор от последовательности генерации регионов, рек и дорог. Просмотр, отмена, повтор и открытие файла ничего не перебрасывают. Сохранившийся при перегенерации объект сохраняет значение, новый проходит создание заново.
- R4. Перемещение и переименование существующей точки сохраняют запись за ней. Удаление, отмена и повтор работают с точкой и её записью одной операцией. Предложение для замены типа — применить политику нового типа в той же операции с возможностью отмены. Возможность ручного переопределения фиксированной политики и судьбу написанной улики уточнить до чистовой спецификации.

## Предлагаемая таблица создания

Утверждены обязательный результат для столицы и три достижимых исхода портала. Для обсуждения случайные варианты внутри строки пока равновероятны. В таблице П означает «При прохождении», И — «При исследовании», С — «Секретное место».

| Объекты в Classic | Режим при создании | Основание предложения |
| --- | --- | --- |
| Столица | П, всегда | Пример владельца |
| Город, городок, деревня, замок, форт, крепость, башня | П, всегда | Поселение или крупный силуэт |
| Ферма, пастбище, таверна, мельница, монастырь, лесопилка, пивоварня, винокурня, каменоломня, карьер | П / И | Открытый объект или хозяйство в стороне от пути |
| Лагерь, хижина, пасека, кладбище, обелиск, статуя, постройка, природное место | П / И | Размер и окружение меняют заметность |
| Рудник, пещера, подземелье, сухопутное или водное логово | И / С | Вход можно отыскать или раскрыть через взаимодействие |
| Портал | П / И / С | Пример владельца; доли открыты для обсуждения |
| Руины, святое место, проклятое место | П / И / С | Возможны видимые ориентиры и скрытые места |
| Водоворот, скалы | П / И | Признак на поверхности |
| Подводная пещера, подводные руины | И / С | Потребуется обследование или специальное действие |
| Кораблекрушение | П / И / С | Надводные обломки, следы или скрытое судно |

Перед реализацией сверить каждое имя с каталогами доступных типов в src/App.tsx; один и тот же тип в разных источниках создания получает одинаковую политику. Новое неизвестное значение в файле должно пройти штатную проверку формата; при ошибке текущая карта и история сохраняются.

## Совместимость

R5. Сохранить вместе с владельцем точки выбранный режим; передать его в JSON и восстановить после импорта. Отсутствующая запись в старой карте и явно назначенное «При прохождении» различимы. Предложение: прежняя деревня без записи показывает «Не задано» до явной правки. Открытие и повторный экспорт старой карты не создают случайных значений. При конкурирующих записях Classic и Knave порядок разрешения нужно согласовать до разработки.

R6. Использовать действующую семантику passage / exploration / interaction. Уже сохранённые режим и текст улики Knave имеют приоритет сохранности, включая отключение и повторное включение профиля. Секрет Knave с пустой уликой сейчас отклоняется валидатором. Предложение для обычного Classic — необязательная улика мастера; автогенерация секрета не требует вводить текст. На интервью нужно согласовать переходы между профилями. Формат и возможную миграцию выбрать после этого решения. Ошибка или отмена ввода не должны частично менять ни карту, ни текст.

## Приёмка и доказательства

| ID | Действия | Наблюдаемый результат |
| --- | --- | --- |
| AC1 · R1–2 | Создать в Classic регион со столицей, добавить портал, открыть обе карточки на компьютере и при ширине 390 px | У столицы П, у портала допустимое значение. Плашка видна без включения Knave; RU/EN читаемы |
| AC2 · R2–3 | Пройти все доступные типы из согласованной таблицы. Для портала проверить по одному контролируемому входу на каждый интервал выбора | Для фиксированных строк единственный результат, для случайных все и только разрешённые значения. Повтор создания с тем же входом воспроизводим |
| AC3 · R3–5 | Зафиксировать значение, открыть карточку несколько раз, сменить масштаб, сохранить и заново открыть JSON. Перенести и удалить точку, выполнить отмену и повтор | В каждой версии документа запись относится к нужной точке; карта и состояние генерации при чтении сохраняются |
| AC4 · R4–6 | Импортировать старую деревню без записи и карту Knave с авторским секретом; переключить профиль и язык; попытаться импортировать неверный режим | Результат по согласованной политике для старой деревни; точный текст секрета не теряется; при ошибке активный документ цел |
| AC5 · R2, R4 | Проверить центральное место, дополнительное сухопутное и водное место на одном сохранении. Сменить тип и отменить | Нет переноса значения между соседними владельцами; исходная запись и улика восстанавливаются |

Первое сквозное доказательство — одна реальная карта со столицей и порталом: карточки до/после, сохранение и повторный импорт. Для таблицы расширить существующее покрытие каталогов и жизненного цикла. Маршрутизация: интервьюер проверяет весь D1, ведёт реестр ответов; затем аналитик выпускает F1. Прогноз D1 — ещё 4–7 запусков до готового выпуска при одном раунде интервью, включая разработку, независимую приёмку, исправление при необходимости и выпуск; ожидание ответа владельца по времени отдельно.

## Открытые решения для интервьюера

1. Утвердить или скорректировать группы, вероятности и охват водных и самостоятельных одномильных объектов.
2. Ручная правка после создания: ограничивать ли список политикой типа, что происходит при смене типа, с ранее написанной уликой и при отмене.
3. Обязательность улики в обычном Classic и поведение при переходе в Knave, в частности для автоматически созданного секрета без текста.
4. Поведение прежних объектов без записи, приоритет и владение значением при переключении профиля. Предъявить варианты и последствия по каждой развилке, сохраняя ранее принятые примеры.
