# HX-BL-023 / E5 — ручное редактирование рек

Версия E5-1.0, 04.11.2026. Статус: пригодная спецификация утверждённого этапа. База: `ab75ecb0a5b90888d4e367bfc9a40ecdff8ad429` (опубликованные PR484+485). Это требования к будущей реализации, не отчёт о готовой функции. Родитель: HX-BL-023v2.3; полномочия: owner-decision-2026-10-28-editor-additional-functions-approved и handoffs/2026-11-04-strategist-score-PR485-PR484-E5.json. Разработка разрешена после этой спецификации; публикация — отдельно после независимой проверки точного пакета. Нового согласования дизайна нет.

## Цель, сценарии и границы

Ведущий адаптирует реку к приключению: прокладывает русло по рёбрам уже созданной карты, меняет направление, полноводность, пороги и водопады, удаляет ненужную реку. Все изменения сохраняются и отменяются вместе с зависимостями. Primary_scenario=develop_existing, secondary=create_from_scratch; уровень L1. До: река и её признаки только показаны в информации. После: в общем Edit выбранное русло/значение редактируется на месте; обычный просмотр сохраняет компактность.

Входит в один завершённый E5 пакет: Classic/Mythic; создание/удаление целой River, замена её полного пути с сохранением ID, разворот пути, F1–5 гидрологического участка, пороги на ребре, водопад в вершине, ручные состояния auto/on/off, v7/миграция/история, зависимые crossings и дельты. Модель новых рек использует существующую сетку, не свободную кривую. Частичное удаление нескольких рёбер как самостоятельная команда не входит: заменить русло либо удалить реку целиком. Новая произвольная дельта/несколько выходов обычной вершины не добавляются под видом притока.

Не входит: создание/изменение площади озёр и моря (E6), высота/принадлежность гексов (E7), перенос POI (E8), речная навигация партии/скорость/процедуры встреч (L2/L3), автоматический ремонт исторической карты, новый генератор, платные сервисы. Невозможность нового русла без увеличения озера объясняется, а не обходится скрытым изменением воды.

## Основания и фактическая инвентаризация

Действующие источники: docs/river-model.md (RIV-001…018 и уточнения до11.10), river-model-core.md, river-model-integration.md, road-model.md, region-generation.md; процесс/видение/score1.2 в agent-work/strategy и process.md. Старые числа тестов/JSONv2 в доменных отчётах исторические; фактическая база — v6.

На базе ab75ecb:

- App.tsx River содержит id, regionId, directed vertexPath, sectors и необязательные controlPoints/deltaParentRiverId. F и assignedRegionId находятся в секторах, направление — порядок вершин. Отдельного manualRiver слоя/сохраняемых признаков нет.
- buildRegionRiverNetwork фиксирует прежние рёбра и отвергает их удаление/разворот. Нельзя просто вызвать этот адаптер с полной старой сетью как previous для ручного изменения: явно выделить редактируемую область и фиксированные внешние условия. Числовое ядро не проверяет подлинность геометрии само.
- Пороги вычисляются из F/высоты и stable hash `river.id:edgeKey`, пропускаются на crossings; водопады — hash `waterfall:vertexKey`, запрещены на старте любой реки, слиянии и контакте с озером. Они не объекты River и сейчас возвращаются после перерисовки.
- Дельты BR-009 — отдельные короткие distributaries: основной морской F4 — до1 рукава с F1–3, F5 — до2 с F1–4, возможны геометрические отказы. Не включать разветвление в обычный RIV-005 и не требовать создавать отсутствующий рукав при ручной правке.
- Crossings сохраняют kind; случайный reconcileRiverCrossings не годится для ручной операции. Брод допустим только F1–2; мост/переправа F1–5. Объекты notes/tags/toponyms уже сохраняются и входят в транзакции.
- MapSnapshot/DocumentSnapshot и commitManualMap дают общую историю. nextRiverId сейчас не сохраняется, новые ID берутся max+1. При удалении наибольшего ID это допускает повторное использование — E5 вводит счётчик, чтобы не присоединять старые признаки/теги к другой реке.

Источники НРИ: применимые требования карты из agent-work/market/rules и действующих доменных правил; E5 — запрос владельца о L1, не приписанное книге требование автоматического моделирования воды. Mythic Bastionland Core: сохранить область, POI/престол/уделы/мифы и препятствия, правка реки не восстанавливает случайные квоты. Generic Classic — собственная карта. D&D5e2014/2024, DW standalone, TOR2Core2e и FLCore2019 — потенциальная ручная адаптация готовой карты, конкретная полнота внешнего модуля/правил не проверена. Сценарные ранги из родительской2.3: MB develop14/create7, D&D develop1, DW develop4, TOR2 develop3, FL develop12; источник three-scenario-ranks-1.3-DW-FL-nonzero (процессная актуализация4ноября, без изменения AC). Они остаются экспертными; не выдавать их за измерения/поддержку top5/10/20. Нового сравнения игр для этой спецификации не требуется.

## E5-01. Выбор и компактное взаимодействие

Использовать общий Edit/Done, существующий блок «Рядом» и найденный через Find объект. В просмотре — прежнее имя/теги/признаки; нет постоянной панели инструментов или списка всех параметров. В Edit нажатие на строку реки либо её линию выбирает точный riverId и ребро рядом с текущим гексом. Выбранная река контрастно подсвечена без заливки карты. При нескольких совпавших hits показать явный список имён/географических концов и фокус/подсветку; не выбирать последний SVG или первый массивный элемент. Не применять правку к region.centerHex.

Под выбранной строкой появляются компактные строки того же шрифта/межстрочья: «Полноводность 2», «Направление →», «Русло», «Пороги Авто», «Водопад Авто», «Удалить реку». F относится к выбранному гидрологическому участку; пороги к выбранному физическому edgeKey; водопад к явно выбранной вершине. Если у гекса несколько участков/вершин — сначала короткий список мест, с подсветкой; технические ID не основной текст. Строки маркеров доступны только при выбранном ребре/вершине, иначе просьба выбрать место, а не изменение произвольной точки.

Значения пунктирно подчёркнуты только в Edit; нажатие сразу открывает native select или действие, без карандаша, отдельного Save/Apply, предварительного выбора «гекс/регион». F select=1…5, feature select=«Авто / Есть / Нет» (Auto/On/Off). Доступные значения F определяются полной подготовкой операции с fixed neighbours; недоступные сопровождаются текстовой причиной. Не использовать ползунок, обещающий все значения. Выбор валидного значения — одна транзакция; Escape закрывает поле без изменения. «Направление» предлагает именно «Развернуть реку» с предпросмотром стрелок всей River, а не косметический поворот стрелки.

«Добавить реку» находится в Edit в конце «Рядом» и доступно на созданной карте даже без соседней реки; не занимает место в просмотре. Путь строится в отдельном временном черновике поверх карты, без новой верхней панели. Подсказка в информации объясняет «Выберите начало и соседние вершины. Enter или конечная вершина — завершить. Escape — сбросить»; для touch — текстовое «Сбросить черновик». Это жизненный цикл многошагового пути, не локальные Save/Cancel у поля.

## E5-02. Создание и замена пути

Сначала завершить открытые поля/заметки текущим E2 контрактом, включая финальный символ IME. Захватить document identity+revision, riverId при замене, исходный path/F/контекст. Карта и стеки пока неизменны. Добавление начинается с подлинной вершины созданного сухопутного гекса, порта озера, допустимого river connection либо открытого конца. Выбор моря как истока запрещён. Каждый следующий шаг — соседняя вершина через реальное ребро текущего river graph; известная геометрия, без пропуска гексов, повторов вершины/ребра, чужого занятого ребра, петель и обходов по внутреннему морю. Не подменять выбранный путь shortest-path. Нажатие предпоследней вершины убирает последний шаг. Панорамирование/zoom/rotate не рисуют и не завершают путь.

При замене исходная река остаётся видна приглушённой; доступна для собственного нового пути, но не считается второй рекой. ID, имя RU/EN, теги и regionId сохраняются, пока прежний owner region остаётся смежен хотя бы одному ребру пути. Если прежний owner больше не смежен, выбрать регион владельца первого участка (явно показанный в предпросмотре), не менять riverId. ControlPoints, отсутствующие в новом пути, удалить, не оставлять висячие ссылки.

Направление нового пути — от первой вершины к последней, показано стрелками. Минимум два разных узла. Новый внутренний сухой исток F1, настоящее озеро-исток ограничено фактической площадью по RIV-008. Конец: море, совместимый вход в существующую реку/озеро или реальная граница с несозданной территорией. Закрытое внутреннее устье без достаточного озера недопустимо. Контакт с существующей рекой на конце создаёт проверяемый узел; промежуточное касание не продолжается насквозь автоматически: требуется закончить этот путь в точке связи. Нельзя создавать выход из середины обычной реки (1вход/2выхода), кроме уже помеченного BR-009 рукава.

Enter, повтор конечной вершины или общий Done готовят и проверяют черновик. При успехе — одна транзакция со всеми зависимостями; при ошибке — черновик остаётся для исправления, карта/история/redo/RNG неизменны. Escape/«Сбросить черновик» удаляют весь черновик и возвращают фокус инициатору. Выбор другого объекта/язык/Find/скрытие панели пытаются закончить валидный черновик; невалидный блокирует переход с причиной. Экспорт показывает подтверждённую карту и не завершает черновик; явно сообщает «Черновик не входит в выгрузку». Generation/import/reset/Undo/Redo и другая мутация запрещены до завершения/сброса; stale callback также проверяется, disabled DOM недостаточен.

## E5-03. RIV, геометрия и F

Применять RIV-001…018 без новых числовых послаблений. Привести путь к направленной сети событий source/continuation/confluence/lake/sea/open. Гидрологический участок между слияниями/озёрами/концами имеет одинаковое F даже через region_boundary/height; интерфейсная строка меняет весь такой участок, не один визуальный штрих. Явно подсветить его полный охват до выбора F. При неоднозначном разбиении исторического участка показать конфликт и отказ, а не исправлять невидимые места.

Разворот меняет весь vertexPath выбранной River и порядок/причины/направления её секторов. После разворота проверяются реальные истоки/устья и вся затронутая компонента; сохранившееся море на старом конце становится запрещённым истоком и даёт отказ. Не разворачивать связанные чужие реки автоматически. Сохранение F каждого физического участка — default разворота, если невозможно, отказ с конкретным узлом/причиной. Допустимый разворот должен быть реально достижим на open→open fixture, не только протестирован как ошибка.

При новом пути пользовательские F — жёсткие условия; остальные новые F решает существующее числовое ядро с фиксированными внешними рёбрами. Старые F/направления вне выбранной River не меняются. В выбранной River неизменённые участки вне заменяемого гидрологического охвата тоже фиксированы. RIV-005 симметричен; 3+1→4 запрещено,3+2→3/4 разрешено,5+любой→5. Высотные предпочтения не оправдывают переписывание фиксированного F. У нового сектора assignedRegionId выбирается из реально смежных регионов: у сохранённого ребра прежний, иначе регион инициатора если смежен, иначе минимальный числовой id смежного региона. Разбить при смене owner, но F не менять. Высота — region.heightLevel владельца, не biomeOverride/случайный сосед.

Проверять подлинность всех ключей/координат/соседств, no duplicate physical edges, отсутствие циклов включая полную сеть через озёра/старые связи, степени обычных узлов ≤3, слияние2→1, sea no out, open только на фактической текущей границе; повторный вход в то же озеро по уточнениюRIV-017. Озеро: все реальные порты всех рек, площадь уникальных гексов один раз, RIV-008/009/010/018. Не применять несколько раз ёмкость озера и не считать внутренние озёрные штрихи портами. Ядро limit5000/component возвращает «Проверка слишком сложна; упростите русло», не unsatisfiable и не частичный успех. Числовой расчёт/валидация детерминированы, geography/poi/names/visual streams не расходуются. Имя новой River создаётся существующим детерминированным synchronizeToponyms из toponymSeed и нового ID, не случайной ручной жеребьёвкой. Существующие имена и tag snapshots не перебрасываются.

Исторические структурно допустимые нарушения сохраняются при импорте, не исправляются автоматически. Новое/изменённое взаимодействие проверяется строго; неизменившийся независимый старый дефект не блокирует чужую правку. Для changed component сравнивать канонические до/после нарушения по физическим рёбрам/портам/направлениям, не transient sector IDs. Участок со старым нарушением можно исправить или удалить, но не увеличить/перенести его; если фиксированный сосед не позволяет валидную правку — отказ, сосед не исправляется скрыто. Полная проверка циклов обязана обнаружить новый цикл вне локального участка; общий отказ из-за любого старого дефекта не соответствует совместимости.

## E5-04. Зависимости и удаление

До разрушительной операции inline-предпросмотр: вся выделенная река, число/места изменённых переправ, дельт, ручных маркеров, наличие имени/тегов. Не перечислять несуществующие NPC/слухи. При простом безопасном select без разрушительных зависимостей отдельной кнопки нет. Для удаления/разворота/операции с удалением зависимостей применяется существующее inline подтверждение как E3; Enter/клик подтверждает, Escape/отказ возвращает фокус, без мутации. Это подтверждение действия пользователем приложения, не дополнительный gate владельца проекта.

Crossings: вычислить реальные пересечения новых рёбер с существующими road/trail; сохранить старый kind на том же ключе/ребре, удалить только исчезнувшие пересечения, добавить отсутствующие новым детерминированным bridge (без жеребьёвки). До окончания черновика можно поменять предложенный bridge на ferry/ford по E3. Если существующий брод стал F>=3 — не превращать молча: показать это место с выбором мост/переправа в том же черновике. Пока конфликт не решён — отказ. Дороги/тропы не сдвигать/не удалять; запрещённое препятствие на новом ребре блокирует путь. Сохранённое legacy-препятствие на неизменённом ребре не исчезает и не создаёт глобальный repair.

BR-009: отмеченные deltaParentRiverId рукава сохраняются по ID/parent. При редактировании родителя действующие рукава должны начинаться в существующей точке ветвления за1/2ребра до морского устья, заканчиваться на морском берегу, не перекрывать другие рёбра, не создавать цикл. ПриF4 не более1, F1–3; приF5 не более2, F1–4; приF<4 не допускаются. Не пересоздавать случайно/не требовать отсутствующие рукава. Если нынешний рукав стал несовместим — показать зависимость и отклонить; пользователь удаляет этот рукав отдельно либо корректирует родителя. Создание произвольного distributary не входит; существующий рукав можно заменить валидным коротким ребром/изменить F/удалить. Разворот рукава с выходом из моря запрещён. Непомеченную legacy-геометрию не объявлять delta только по близости, не переписывать при импорте.

Удаление: целая выбранная River, её crossings/feature overrides, toponym и tag owner удаляются одной транзакцией; остальные данные сохранены. При наличии помеченных дочерних рукавов предложить именно «Удалить реку с N рукавами», перечислить их; без подтверждения не удалять. После удаления всей группы остальная сеть должна оставаться допустимой: если приток лишился устья/нижележащая река стала незаконным истоком, отказ с именем/местом связанной реки, без каскадного удаления чужих рек или создания озёр. Нельзя удалять произвольные notes/POI/биомы/области. Undo возвращает те же имена, теги/кубы, crossings, IDs и обе истории; не бросает имена заново.

## E5-05. Пороги и водопады

Persisted feature overrides — отдельное состояние, не изменение вычисленного SVG. Для порогов ключ=riverId+canonical undirected edgeKey, для водопада ключ=physical vertexKey (одна общая отметка, не N наложенных на одну вершину). On/Off/Auto локальны; отсутствие записи=Auto, запись Auto канонически удаляется. Исходные вероятности и stable hashes в Auto сохранить буквально, не переносить их на новый RNG/не пересчитывать random stream при render. При сменеFAuto закономерно меняется по прежнему hash+таблице; ручные on/off остаются.

On для порога требует живого видимого речного ребра, не внутреннего озёрного/морского и без crossings. On водопада — живая видимая речная вершина, не начало любойRiver, не слияние, не контакт с озером или морем. Жёсткие запреты нельзя обходить ручнымOn, вероятность (даже0.1%) не жёсткий запрет. Off разрешено на соответствующей живой цели даже еслиAuto уже пусто: это сохраняемое намерение, не no-op. Повтор того жеOn/Off илиAuto при отсутствии override — no-op. Эффективное состояние в информации: «Нет (вручную)» либо«Есть (авто)» без технических key; редактирование native select показывает только3варианта.

Сохранять override на том жеriverId/edge при развороте/измененииF и на остающейсяphysical vertex для waterfall. Удалённая цель очищается только с показом количества зависимостей; если вершина принадлежит другой оставшейся реке, waterfall override сохраняется. ЕслиOn на сохранившейся цели становится запрещённым (новая переправа/исток/слияние), не удалять/скрывать молча: показать конфликт; пользователь выбирает Off/Auto в том же черновике до commit либо отменяет операцию. ВE3 создание переправы на ручномOn порога получает такой же guard/решение — совместимость обоих направлений мутации обязательна. Все пути изменения документа, включая обычную генерацию и восстановление checkpoint, соблюдают этот контракт: не фиксировать новый запрещённый On и не получать accepted save, который приложение откажется загрузить. При несовместимости — отказ до commit либо явное подтверждённое изменение в показанной транзакции. Не хранить on на несуществующей цели и не восстанавливать удалённое ребро ради его маркера.

## E5-06. Документ, v7 и миграция

Авторитетная геометрия/F остаются в map.rivers, не параллельный overriding слой. Сначала прежний валидатор принимает v2…6, затем общий preflight ссылок deltaParentRiverId: parent существует, не self, не цепь/цикл рукавов. Затем детерминированная подготовка: пустые overrides, nextRiverId=max(existing id)+1 либо1 при пустой карте. Геометрия/порядок рек/ID/F/имена/секторы/случайность/признакиAuto не меняются. Если river id MAX_SAFE_INTEGER и счётчик невозможен — атомарный отказ с указанием переполнения, не wraparound/renumber. Вv7 счётчик положительный safe integer, больше всехriver IDs; устаревший/неверный счётчик отклоняется явно (не исправлять его молча). Выдавать ID и увеличивать счётчик только при успешном создании, включая автоматические генерационные пути/рукава, не при начале черновика/ошибке/no-op. Удаление не уменьшает счётчик. Undo/Redo восстанавливают счётчик точно; новая ветка послеUndo может использовать отменённый ID только после удаления всей его отменённой redo-ветки. Разделять ID после явногоUndo и случайное переиспользование ID ранее удалённого объекта.

v7 структурно проверяет уникальность feature keys, строгие on/off, safe river IDs, ссылки на настоящие рёбра/вершины и допустимость ручного On по жёстким правилам. Auto требует отсутствия записи. Не требовать полной RIV-перевалидации неизменённой legacy-геометрии. Повреждённые vertices, потерянный parent delta и другая неверная структура отклоняются до замены документа; новую строгость старого формата нельзя объявлять «миграцией». При старом структурно допустимом неполном покрытии секторами не придумывать F: сохранить импорт/экспорт, а для затронутой операции требовать однозначного чтения либо возвращать ошибку.

Добавить поля во ВСЕ snapshot/clone/import/export/rollback/Undo/Redo paths. Отказ, exception и отмена chooser сохраняют карту, generationHistory, undo, redo, счётчики, seed/streams и выбор/камеру; UI ошибки может измениться. Подготовить целый map, toponyms/tags reconciliation с их ограничениями ёмкости, crossings/feature cleanup и clones до первого setter/history write. Двойное быстрое завершение — одна операция; obsolete revision/ID callback не действует на новую карту. No-op сохраняет redo. Ошибка программы не превращается в штатный отказ геометрии и не создаёт урочище.

Ручная правка не обещает вечный lock против явной перегенерации области или удаления регионов. Обычное добавление соседнего региона сохраняет старые отредактированные paths/F/feature overrides и использует их как fixed boundary conditions; если невозможно — штатный отказ. Старые generation checkpoints не переписывать задним числом: удаление/перегенерация последнего региона использует действующий контракт снимка и может восстановить его исходное состояние. Перед таким действием, если riverFeatures/правки будут потеряны, destructive preview обязан сообщить это; Undo возвращает точный передоперационный документ. Общее Undo и «удалить последний регион» — разные действия.
