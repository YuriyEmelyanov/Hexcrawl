## HX010-DEBUG — обычный и служебный режим
DEBUG01. В обычном URL блока отладки, пустой рамки и занимаемого им отступа нет, в том числе в DOM/Tab-порядке. Ошибки генерации/импорта и пользовательские сообщения остаются видимыми: скрывается технический details, не ошибки.
DEBUG02. Явный обратимый служебный доступ — query-параметр debug=1. Только точное значение1 включает доступность прежнего details; debug=0, false, отсутствующий параметр не включают его. Остальные URL-параметры не менять. Без нового пункта меню/постоянной кнопки в пользовательской панели.
DEBUG03. Служебный URL при загрузке показывает прежний details свёрнутым: debugRivers=false. Открытие details включает прежние визуализацию/логи, закрытие выключает. Подробная диагностика не работает только от присутствия параметра, пока пользователь её не открыл. Не переносить настройку в JSON, localStorage или карту. Служебный доступ не является авторизацией/защитой данных.
DEBUG04. Документировать URL и воспроизведение: открыть служебную вкладку, импортировать сохранённый JSON/seed, включить details. Не требовать перезагрузки текущей вкладки как шага обычного пользовательского сценария. Существующие поля диагностики, различие штатных отказов/ошибок, алгоритм, RNG, seed и контекст воспроизведения сохраняются. Нового dashboard/аналитики/логирования содержимого заметок не добавлять.

## HX010-FIND — выбор и фокус
FIND01. Положение «Найти объект» ниже информации/заметок, раскрытие, поиск сразу по RU+EN и фильтр типа сохраняются. Текущие пять типов: region, settlement, river, lake, kingdom. Формы, кегль, межстрочные интервалы и компактная структура не увеличиваются. Во всех режимах результат — кнопка навигации; в каталоге нет input редактирования, reroll и inline-name editor. Активное Edit/Done не переключается при переходе.
FIND02. До действия заново разрешить стабильный key по текущему документу, а не выполнять координаты из устаревшего замыкания. Выбрать реальный существующий гекс объекта, затем показать актуальную информацию и перенести фокус на существующий section информации (tabIndex=-1), чтобы следующий Tab достигал его кнопок. Список остаётся раскрытым, запрос/тип сохраняются. Нового постоянного тулбара «гекс/регион» нет. Не центрировать/масштабировать карту автоматически. Новое выделение может находиться вне текущего viewport; пользователь сохраняет обычные pan/zoom. Это известное ограничение данного объёма, не обещание автоматического наведения.
FIND03. Координаты показывать те же, которые будут выбраны. Сопоставление:

| Тип | Представляющий гекс |
|---|---|
| Регион | centerHex, если существует в его hexes |
| Поселение/POI с именем | существующие координаты из стабильного entity key |
| Река | существующий гекс, имеющий общее геометрическое ребро с её vertexPath; предпочесть прежний region.centerHex только если он действительно касается реки, иначе минимальный (q,r) в числовом порядке |
| Озеро | существующий terrainOverride=lake с данным lakeId, численно минимальный (q,r) |
| Королевство | anchor, если это существующий гекс в области; иначе первый существующий centerHex его региона по id; не выдумывать гекс |

Для реки информация выбранного гекса должна содержать эту реку в «Рядом». Для остальных — соответствующее существующее имя в информации. Разрешение геометрии использует существующие источники land/terrain/river edgeKey, не экранные SVG-координаты. Не менять геометрию/владельца ради навигации.
FIND04. Пустая карта, отсутствие совпадений и ошибка подготовки каталога используют прежние локализованные сообщения без новых модальных окон. Если key удалён/координаты больше не существуют/не удалось найти представляющий гекс: сохранить выбор, viewport, карту и историю; существующий status сообщает «Карта изменилась. Выберите объект заново» / “The map changed. Select the object again.” У строки без представляющего гекса видна недоступность, она не перенаправляет к произвольному региону.
FIND05. Guards выполняются до смены selectedHex/фокуса. Валидное имя завершается через существующий finishInlineName; невалидное оставляет ввод/фокус/выбор, без потери черновика. IME composition не форсировать преждевременно. Уже введённые заметки сохраняются и группа истории завершается по действующему контракту. Дорожный черновик проходит нынешний finishRoadDraft: успешное завершение — его собственная транзакция, отказ — выбор остаётся прежним. Незавершённое Add/Move препятствия отменяется как UI-черновик без применения цели, исходный объект остаётся. Порядок не должен отменить черновик, если более ранний guard запрещает переход. Никакого скрытого discard валидного/невалидного имени, частичной фиксации или новой обязательной кнопки согласования.
FIND06. Клавиатура Enter/Space выбирает результат, фокус видим; доступное имя различает одноимённые записи типом и координатами. Touch и pointer выполняют то же действие. Результат не меняет текущий язык или другое локализованное имя.

## HX010-SELECT — один выбранный гекс
SELECT01. Для существующего selectedHex показывать ровно один устойчивый контур в обоих режимах и после выбора через поиск/клавиатуру/карту. Изменение hover не снимает выбор. Без действительного выбора — без контура; candidate не выдаётся за созданный гекс. Выбор candidate сохраняет существующее поведение генерации; после успешной генерации обозначается действительный текущий selectedHex. После отказа не рисовать несуществующий выбранный объект.
SELECT02. UI1 предлагает тонкий сплошной голубой контур с тёмной подложкой контура, без заливки и анимации; не закрывать POI/тайл и не расширять информационный блок. Candidate остаётся пунктирным, hover/focus — отдельным обозначением. В Цвет/Тайлы/Эмодзи, на суше/озере/море выделение читается независимо от самой подложки. Геометрия соответствует ровно одному гексу при повороте, zoom и riverOffset. Толщина контура остаётся читаемой в CSSpx на существующем диапазоне zoom. Числовое «44px» здесь относится к элементам управления, не к толщине контура.
SELECT03. Overlay не перехватывает pointer/keyboard/hit targets путей/препятствий, не участвует в генерации и не добавляет историю/RNG draws. Создавать его вне дорогой memoized карты и её raster snapshot, не инвалидировать artwork/тайловый кэш при простой смене выбора. Pan/zoom/rotate сохраняют выбранный гекс, контур следует геометрии; во время raster navigation контур остаётся виден как отдельный overlay, без полного raster rebuild на каждый hover/выбор.
SELECT04. Слой помечен data-editor-only; PNG и используемая для PNG SVG-сериализация не содержат выделения/hover/hit targets. JSON продолжает существующий ui.selectedHex: новый слой/флаги в формат не добавлять. После import/Undo/Redo следовать восстановленному действительному selectedHex; не создавать отдельный второй источник выбора. Выбор сам по себе меняет только UI; map/counters/generation неизменны. Завершение разрешённого старого черновика имеет собственную уже существующую транзакцию, его нельзя считать изменением карты от навигации.
