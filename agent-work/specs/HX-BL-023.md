## Пользовательский результат и основание первого этапа

Ведущий доводит географию и именованные места под собственное приключение, сохраняет результат и продолжает карту без повреждения связанных объектов. Primary_scenario: develop_existing. Secondary: create_from_scratch; play_now этим редактором не обещается полностью. Пример: переименовать реку в Эринин, изменить местность, провести дорогу и мост, скорректировать русло/озеро, убрать препятствие, сохранить изменения между сессиями.

Первым выбран E1: **переименование — прямо запрошенная отсутствующая пользовательская возможность**, полезная при адаптации к своему миру без пересоздания карты; не ускорение восьми уже возможных щелчков. Она также задаёт общий выбор объекта/черновик/Apply/Undo для остальных инструментов. Приоритет — явный запрос и конкретный результат подготовки, наличие готового helper лишь уменьшает стоимость. Дороги/вода дают более широкое географическое управление, но требуют согласованной обработки пересечений и новых сохраняемых ручных признаков; они идут следующими, не исключаются из утверждённого объёма.

База: main a7a8cc58987e97c4495c405374c6a4145f3bc9ff. Инвентаризация — ../evidence/HX-BL-023-editor-v2/inventory.md. Текущий код показывает имена через renderToponym, не даёт их менять; renameToponym и его тесты уже существуют. Предыдущее упоминание доступного inline-редактора имён в audit v1 не подтверждено исходниками и исправлено этой инвентаризацией. POI-тип/добавление/удаление действительно существуют — повторной новой функцией их не считать.

## Приложение: E1 — пригодная спецификация

### Scope, объектная модель и совместимость

Переименовываются ровно существующие канонические сущности: region:<id> (включая kind forest/mountain/swamp), settlement:<regionId>:<q>,<r> для текущих именованных центральных/вторичных поселений, river:<id>, lake:<id>, и kingdoms[id].name (RU/EN). Для топонимов использовать getToponymEntities и существующий реестр, а не все произвольные ключи импортированного словаря; для королевств — отдельный путь с сохранением id/origin/anchor/color/regionIds. Каталог включает все эти живые сущности и только их, с типом/именем/расположением для различения. Отфильтровать по введённой подстроке имени без изменения данных. Пустой список объяснить, а не выдумывать объект.

Это **не переименование всех возможных будущих элементов**: море сейчас не имеет отдельной именованной сущности, дороги/прочие POI/препятствия/пороги/водопады — также вне текущего toponym-реестра. Они явно остаются в каталоге пробелов полного редактора; их идентичность/названия специфицируются в соответствующих E3–E8. Нельзя считать требование всех названий закрытым послеE1. Не превращать произвольный POI в settlement только ради имени.

Формат E1 без миграции: текущийJSONv4, прежниеv2/v3/v4 читаются как сейчас. Поля Toponym kind/model/revision и все ключи/id не менять; kingdom name хранить там, где сейчас. Никакого нового master seed/генерации имени/кнопки reroll (отдельный reroll уже имеет свою задачу, не входит в этот срез). Для старого документа без toponyms использовать обычную подготовку импорта; не «чинить» отсутствующие имена при каждом открытии формы. Все проверки импорта остаются действующими; UI-ограничения ниже не служат поводом задним числом отвергать ранее допустимые длинные kingdom names.

### Поведение формы

1. Кнопка «Изменить название» рядом с текущим именем открывает формуE1, тот же объект можно выбрать из каталога. Оба поля «Русское название» / «Английское название» сразу заполнены существующими значениями независимо от языкаUI. Технический ключ/JSON пользователю не нужен. Кнопки «Сохранить название» / «Отменить». Смена языка переводит подписи, не стирает оба введённых значения.
2. Поля — plain text, одна строка. По существующему renameToponym: trim внешних пробелов;1–80 UTF-16 code units в каждом поле послеtrim; пустое/слишком длинное недопустимо, строки не обрезать молча. Literal <b> и кавычки отображаются текстом, HTML не интерпретировать. Запретить CR/LF/управляющие C0/DEL при commit, без удаления произвольных печатных Unicode. Ошибка у конкретного поля через aria-describedby/aria-invalid, видимый focus. В подсказке достаточно «От1 до80 символов»; технический счёт оставить evidence, не productflow.
3. Для toponyms сохранять действующее правило уникальности каждого языкового имени в текущем реестре (trim+toLocaleLowerCase helper): дубликат даёт понятную ошибку без переименования второго объекта. Королевства сейчас отдельный namespace: не вводить новую глобальную уникальность, которой нет в модели; одинаковые kingdom names можно различить расположением. Уникальность kingdom↔toponym не требуется. Собственное прежнее имя не конфликт. Этот выбор сохраняет текущий контракт, не создаёт новое требование владельцу.
4. До «Сохранить» не писать в карту и историю. Cancel/Escape вне раскрытого native select закрывает форму, возвращает focus к инициатору. Переключение объекта/закрытие редактора при изменённом черновике спрашивает внутриUI «Сохранить / Отбросить / Остаться»; нет третьего согласования дизайна с владельцем. При отсутствии правок переход прямой. Сохраняются оба языка одной транзакцией. Послеtrim равенство обоих полей исходным = no-op, закрыть форму, сохранить redo.
5. Пока изменённый черновик открыт, остальные операции изменения карты (generation/reset/delete/import/seed/mode, POI, notes, другой rename иUndo/Redo) недоступны до save/discard. Навигация, просмотр/поиск каталога, экспорт применённой карты доступны; смена выбранного объекта проходит п4. Для export прямо указать «Неприменённое название не входит в выгрузку»; сам черновик/выделение не попадает в PNG/JSON. Реальные guards обязательны и для старых callback/горячих клавиш; disabled-кнопок недостаточно. Вход закрывает/завершает notes group обычным способом без потери последнего символа.
6. На save проверить live documentRevision, существование/тип сущности, актуальное исходное имя, документ не busy. Захватить revision+идентичность при открытии; stale объект после import/delete не переименовывается по одному лишь совпавшему ID. В случае нового документа закрыть устаревший черновик, показать «Карта изменилась. Выберите объект заново». Не восстанавливать старый map. Обычная ошибка валидации оставляет текст для исправления. Двойное быстроеSave — одна операция, повтор stale/no-op.
7. Сначала подготовить полный результат (renameToponym или новая kingdoms[].name), проверить данные, затем commit одной общей транзакцией. Не менять RNG, geometry, POI/roads/rivers/crossings/notes, counters/checkpoints, keys/kind/model/revision. Послеsave сообщение «Название сохранено», новое имя во всех местах панели/каталога, focus возвращён к имени. Undo/Redo возвращают точные пары имён и общий документ. Не менять камеру/выбор гекса вследствие rename. Черновик не восстанавливается как ещё открытая форма после Undo.
8. После export/import и следующей генерации/ручной правки/удаления последнего другого региона имя сохраняется, пока сущность существует. Регенерация самого объекта имеет действующий контракт удаления/пересоздания, не вводит вечный lock автоматически; этот предел указать в отчёте. Имена по-прежнему не рисуются на карте/PNG: текущий продукт показывает их в информации; расстановка картографических подписей не входит вE1.
