## Цель, границы и исходное поведение

Мастер называет море и сохраняет имя после изменения карты, JSON и Undo/Redo. Расширение не создаёт новый именованный объект; разделение/слияние не теряют авторский текст молча. Это L1, сценарий develop_existing; не новый режим генерации или экспедиций.

На baseline: App.tsx getSeaHexKeys(751), getConnectedSeaComponents(6224) выводят компоненты из terrainOverride=sea; временный getSeaComponentIds(5741) не является сохраняемым ID. manualWater.ts waterComponents сортирует координаты численно и использует 6 соседей по ребру; connectedWaterBody объединяет lake/sea для геометрического выбора. Sea не имеет своего постоянного ID. Морская строка App.tsx16274 не вызывает renderToponym. Внутри региона заголовок региона имеет приоритет: имя моря нельзя добавлять только в ветку внешнего моря. E8 editorNames/Find не включают sea:id. saveValidation.ts61 поддерживает v2…v8; map.editorNames доv8 запрещён. Снимки/генерация/экспорт сейчас переносят nextLakeId и editorNames, но не Sea.

Переиспользовать E6 WaterDraft, choices/loss preview, recordTransaction/captureMap/applyExactMap, generation/checkpoint guards, manualPois.ts name-pair validation, E8 name targets/Find, JSON validation. Новые морские имена не менять на произвольный seed и не объявлять изменением гидрологии.

Включено: стабильный Sea, имена, миграцияv9, ручная вода, генерация/восстановление, поиск, общий UI имени и точное сохранение.
Исключено: новые формы берегов, классификация океанов/заливов, морские теги/владение/маршруты, перевод названий, новые правила НРИ, нормализация legacy-географии, SVG-экспорт и полный WCAG-аудит. Географические ограничения E6/RIV/ROAD остаются прежними, включая запрет замкнутого нового моря и минимум2гекса для новых ручных компонентов. Присвоение ID старой воде не переклассифицирует её.

## SEA01 — сущность и схема

Экспорт hexcrawl-map v9; версия генератора/RNG не меняется. В map обязательны seas: SeaRecord[] и nextSeaId: safe integer>=1. SeaRecord={id:positive safe integer,hexKeys:string[]}. hexKeys — канонические q,r с safe integer координатами. Sea ID независим от region/lake/river ID; 1 в этих реестрах допустим одновременно.

Реестр покрывает ВСЕ явные terrainOverride=sea, включая внешние гексы без региона. Один Sea соответствует ровно одному максимальному компоненту только морских гексов по6рёбрам; контакт вершиной, озеро или неизвестная область не соединяют Sea. Для legacy сохраняется именно эта топология, даже если старый географический дефект ранее принимался. Реестр не исправляет воду. Ни один гекс не входит в два Sea, нет пустых/лишних/пропущенных членов; смежные морские компоненты не могут иметь разные ID. Порядок записей/координат при импорте семантически неважен; экспорт сортирует Sea поid, members численно(q,r).

Имена разрежены в существующем editorNames по locator sea:<id>; запись исчезает только при явной очистке либо подтверждённом удалении/retire. SeaRecord не дублирует имена. Не добавлять морской ключ на один выбранный/минимальный гекс. Минимальная координата может быть временным ключом формы/choice и порядком новых ID; она не идентичность.

nextSeaId строго больше всех живыхid; удаление не понижает floor. Новая запись использует floor, затем увеличивает на1; если для всех новых компонентов не хватает безопасных ID — весь переход отклоняется до setters. Полный reset создаёт новый пустой документ с floor1. Undo/Redo/импорт восстанавливают точный floor документа; не обещать глобальную уникальность между независимыми файлами или отброшенными redo-ветками.

## SEA02 — детерминированный переход

Сначала действующая E6 геометрия/тип воды/назначение регионов, затем расчёт Sea по итоговому candidate. Вся карта, а не только выделение: новый гекс может соединить далёкие моря. Сравниваются старые Sea и новые компоненты по непустому пересечению их членов. Никакой близости/первого найденного объекта. У неизменённых компонент сохранять ID независимо от порядка Map/JSON/обхода.

1. Для каждого старого ID определить новые компоненты с его старыми гексами. Нет частей — ID удаляется. Одна — кандидат-наследник того ID. Несколько — split: именованный Sea требует явного выбора одной части в preview; без ответа commit невозможен. Для неименованного по умолчанию выбрать наибольшее пересечение со старым Sea; при равенстве — численно минимальный(q,r) член части. Выбор также виден и может быть изменён. Остальным частям этот старый ID не присваивать.
2. Для каждой новой компоненты собрать ID, которые выбрали её наследником. Ноль — новый ID; один — сохранить его. Несколько — merge: если среди них ровно один именованный, по умолчанию сохранить его; если все безымянны, минимальныйid; если именованных>=2 — явный выбор сохраняемогоid, даже при одинаковом legacy-тексте. Выбор показывать для каждого слияния, разрешить выбрать другой живой кандидат; удаляемые имена затем защищены SEA03.
3. Компонентам без наследника присвоить новые ID в численном порядке их минимального(q,r); preview вычисляет IDs на копии, не расходует floor.
4. Имена остаются только с сохранившимися ID; новый Sea без имени. Не дублировать одно авторское имя всем детям, не склеивать пары RU/EN разных проигравших и не переименовывать фоновые сущности. В many-to-many сначала полная таблица split-наследников, затем merge-выборы; после изменения выбора заново вычислить кандидаты/потери на том же revision. Неподходящий/устаревший ответ — атомарный отказ.

Примеры (компоненты перечислены только для иллюстрации алгоритма; конечные fixtures должны быть допустимы по E6):

| До → действие | Подтверждённый результат |
|---|---|
| Sea7 {0,0;1,0}, имя Северное море → добавить2,0 | Sea7 {0,0;1,0;2,0}, та же пара имени и floor |
| Sea7 {0,0;1,0;2,0;3,0;4,0} → осушить2,0; наследник правая часть | Sea7 {3,0;4,0} с именем; Sea floor {0,0;1,0} без имени; floor+1 |
| Именованные Sea7 иSea12 → соединить; выбрать12 | Объединённый Sea12 с его парой; Sea7 retired, его имя удалено только после отдельного согласия |
| Sea7 разделился наA/B, Sea12 касаетсяB; выбрать7→A | A сохраняет7; B сохраняет12; это не merge7/12 и не потеря имени7 |
| Sea7/Sea12 разделились каждый наA/B; оба выбралиA | ДляA применить merge-выбор; B получает новыйID; все потери имён перечислены |
| Все гексы Sea7 стали озером/сушей | Sea7 retired; озеро проходит прежний E6 контракт, имя7 не копируется в озеро автоматически |

## SEA03 — авторские потери и атомарность

Loss preview перечисляет точный ID, локализованное имя (оба языка доступны), причину (удаление/слияние/смена вида) и итоговый объект. Для каждого удаляемого непустого sea имени нужен отдельный явный ответ удалить либо отменить операцию. Не выбирать destructive consent по умолчанию. Можно отменить черновик и заранее переименовать/очистить имя обычным редактором. Нельзя выдавать отсутствие имени/равные строки за согласие потери ID.

Сами гексовые GM notes/биомы, водные POI и их editorNames, озёрные toponyms/tags, чужие имена и все прежние зависимости E6 сохраняют свой исходный смысл/адреса. Имя Sea не заменяет заметки гексов и не переносит их на выбранного наследника. Нормализация Sea не разрешает ранее запрещённый геометрический переход. Сначала все choices и loss approvals совместно, затем проверка целого candidate, один recordTransaction и одна установка принятого документа. Исключение/invalid/stale/busy/double finish/отмена/no-op не меняют map, Sea, имена, все counters, RNG, Undo/Redo и selection по действующему контракту. Нельзя создать отдельный Undo для служебного пересчёта Sea.

## SEA04 — генерация и контрольные точки

Расширение Classic/Mythic и все изменения моря, включая convertLandlockedSeaComponentsToLakes, проходят тот же detached reconciler перед принятием результата. Обычная генерация без авторских потерь назначает IDs детерминированно без нового random draw. Если результат требует явного named split/merge или удаления имени и текущий generation UI не поддерживает такой preview — безопасно отклонить целое действие с причиной/путём ручного разрешения. Не удалять имя, не менять seed, не повторять генерацию тайно и не принимать полкарты; RNG/checkpoint восстанавливаются точно. Это ограничение согласованной безопасности, не новый алгоритм генерации.

Поддерживаемые E6/E8 checkpoint warnings расширяются именованными Sea; не подменять существующий warning вторым независимым согласованием. Согласованное восстановление возвращает весь снимок, включая Sea/floor/editorNames; отмена warning оставляет всё. Для snapshot,history,full reset,import,save,recordGenerated,restoreSnapshot и rollback провести явную wiring-инвентаризацию. При программно отсутствующем Sea в старом снимке мигрировать его на detached копии по SEA05, не смешивать текущий floor/имена со старой географией.

## SEA05 — совместимость

v2…v8: сначала весь существующий валидатор и миграции без ослабления; затем построить Sea из явных морских гексов. Сортировать компоненты по минимальному(q,r), выдать1…N, nextSeaId=N+1, имён Sea нет. Не выполнять random draws, hydrology repair, переименование или новый запрет из-за старой формы воды. Старые lake,river,region,poi,kingdom и их данные/номера остаются. Не превращать видимую пустоту карты в бесконечный Sea.

v9: требовать реестр и floor, полный bijection Sea↔компоненты, уникальныеid/члены и корректные морские ссылки editorNames; dangling sea имя, неверная связность, пропуск, лишний морскойid, небезопасная координата/ID/floor — отказ с путём и причиной до изменения документа. Непустая map.editorNames версииv2…v7 остаётся запрещённой. Правила имён остальных типов/старые локальные дубликаты не ужесточать этим срезом. v10+ — штатный atomic unsupported-version refusal. Генератор version и RNG streams сохраняются.

Экспорт v9 включает только accepted Sea/names/floor; preview,selection и ответы формы не сериализуются. PNG использует принятые данные/существующий стиль без полей, preview и service IDs; новые подписи поверх моря на карте не добавлять. Find выводит одну Sea запись на компонент, ищет по текущим E8 RU/EN правилам; выбор фокусирует живой член Sea и открывает панель, ID не меняется от панорамирования/поворота.

## SEA06 — имя и интерфейс

Переиспользовать существующий E8 редактор имён, валидацию и клавиатурный gate. Ручное имя — пара en/ru: trim, оба1…80 UTF-16 units, без управляющих знаков, escaped text и существующая case-insensitive проверка уникальности с toponyms/editorNames/kingdoms по языкам; self исключить. Оба пусты очищают override, один пустой — ошибка. Без записи показывать Sea/Море и ID только как fallback, не создавать имя автоматически. Первое создание использует уже существующий bilingual E8 flow, последующая правка текущего языка сохраняет второй. Не добавлять автоматический перевод.

В выбранном морском гексе (внешнем И региональном) показать одну строку Sea + подчеркиваемое имя/команда названия. Для регионального гекса сохранить заголовок региона и поместить имя моря рядом с существующим значением Вода; не дублировать один Sea в двух блоках. В Edit открыть тот же inline form; Enter сохраняет, Escape отменяет/возвращает focus, IME Enter не завершает composition. Done/переходы используют E8 Finish/Discard/Stay. RU/EN и стартEN сохранить; без постоянного пояснительного абзаца. Split/merge controls только в существующем водном preview: какие части, какое имя/ID сохраняется, явные checkboxes потерь, disabled Применить до завершения ответов, конкретная inline ошибка. Одна прокрутка панели, native select, перенос имён, effective targets44px, 1500/390/320 без horizontal overflow; wheel/pan/rotation не сбрасывают ответы и не расцепляют выбор от текущей матрицы.

UI SEA-UI1 — предложение на основе текущей опубликованной панели/CSS, отдельно от фактического снимка baseline. Состояния read/name/first/split/merge/error; desktop и390. Макет показывает варианты исходов, не работающий reconciler или импортv9. Показ не является третьим согласованием; отсутствие ответа не блокирует утверждённую разработку.
