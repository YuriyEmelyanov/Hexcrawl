# HX-BL-069 · Переброс последнего региона Classic
Черновик D1 для интервью. Старт согласован в [реестре решений](../approvals.json). Следующий исполнитель — интервьюер. Для разработки нужна чистовая версия после интервью.

## Пользовательский результат
Мастер правит первый регион, затем подбирает другой вариант последнего. Первый регион сохраняет авторское состояние, последний получает новый вариант. Используются существующая команда, существующий редактор и формат открытия карты. Новых элементов интерфейса нет. Произвольное выделение области и закрепление внутри неё относятся к HX-BL-075.

## Поведение
1. За точку сравнения взять карту непосредственно перед нажатием, включая изменения, сделанные после создания последнего региона. Исторический снимок до создания региона годится для генерации, но может содержать устаревший внешний мир.
2. Определить область заменяемого региона по его принадлежности на исходной карте. Близость к границе сама по себе не разрешает изменять внешнюю клетку. Изменившийся контур не должен поглотить уже занятую клетку соседнего региона.
3. Сохранить во внешних клетках ручной биом, авторские поля карточки и заметки. Для внешних POI сохранить существование, тип, положение, название и заполненные пользователем поля, поддерживаемые исходной версией. Это распространяется на создание, переименование, перемещение между внешними клетками и удаление. Удалённое после создания последнего региона место должно остаться удалённым. Полностью внешние дороги, водные объекты и ручные элементы их геометрии сохраняют связи и положение в той мере, в какой текущий редактор позволяет их менять.
4. Внутри заменяемого региона применяются обычные правила переброса. Защита пересекающего границу объекта требует отдельного решения ниже. Запись полурезультата запрещена. Для конфликта предложен отменяемый исход с полной сохранностью карты и понятной причиной через существующую обратную связь.
5. Успешный переброс — одно действие в истории. Отмена возвращает исходную карту с авторскими правками и прежним вторым регионом. Повтор возвращает именно уже полученный вариант. При повторном импорте JSON сравнить содержимое карты, включая удаления и привязки. Сохранение стека отмены между сессиями в задачу не входит.
6. Если на исходной карте команда недоступна, сохраняются существующие условия доступности. Для старых сохранений без необходимой истории нельзя реконструировать авторские правки по догадке. Не менять поведение прочих профилей, обычного создания и удаления региона.

## Пограничные случаи для интервью
| Случай | Предлагаемое поведение и последствие | Альтернатива, требующая решения |
|---|---|---|
| Ручная дорога или река входит снаружи, а после переброса внутри исчезает её продолжение | Зафиксировать внешний участок до точки стыка. Разрешить изменение внутреннего участка только при сохранении связного допустимого маршрута. При невозможности отменить переброс целиком | Сохранить внешний участок с допустимым открытым концом, если мастер допускает разрыв |
| Точка или многоклеточный объект перемещены через границу после создания региона | Учитывать состояние непосредственно перед командой. Целиком внешний объект сохранить со всеми ссылками. Смешанную геометрию отнести к конфликтам | Считать принадлежность по исходному региону создания. Это меняет судьбу перенесённого объекта |
| Старый JSON допускает переброс, но не позволяет надёжно определить область | Сохранить исходную карту и объяснить причину отказа | Разрешить переброс только при доказанном восстановлении границы из сохранённых данных |

## Приёмка
| ID | Действие | Проверяемый результат |
|---|---|---|
| AC1 | Classic, seed 1, два соседних региона по 8 гексов. После создания второго назначить внешнему гексу 0/1 снежные равнины. Перебросить последний регион | У второго появился другой вариант. Первый сохраняет назначенный биом. Сравнить семантические данные и показать тот же гекс на карте до и после |
| AC2 | Создать и назвать внешний POI, удалить другой внешний POI, поменять внешнюю заметку. Сделать два последовательных переброса | Новый POI остаётся в единственном экземпляре с теми же полями и координатами. Удалённый отсутствует. Текст заметки и внешние связи сохраняются |
| AC3 | После успешного AC1/AC2 выполнить отмену, повтор, экспорт и импорт | Отмена восстанавливает предыдущий вариант региона, повтор — идентичный принятый вариант. После импорта сохраняются оба региона, внешний биом, POI и заметка |
| AC4 | Взять дорогу или реку через границу и сценарий, где исходный стык нельзя сохранить. Зафиксировать исходные внешние участки и зависимости | Ожидаемый исход выбрать в интервью. Для любого решения обязательны сохранность внешних авторских данных, отсутствие висячих ссылок и частичной записи при отказе |
| AC5 | Открыть старую карту с достаточной историей, затем карту без достаточной истории. Сравнить доступность и данные до и после команды | Для поддерживаемой карты проверить AC1. При невозможности безопасного переброса исходное сохранение остаётся пригодным для повторного открытия |

## Влияние на оценку и передача
В модели 1.3-rc8 строка [SEED-07](../score/rules/S02-C01.md) имеет 0 из 10 по таблице строки. Условный остаток +1,48 L1. Доказательства — AC1–AC5 с внешними правками до и после. В [RER-16](../score/rules/S03-C02.md) принято 1,2 из 2,4 за новый вариант. За сохранение внешних правок возможны ещё 1,2 веса, или +0,59 L1. Для этой строки отдельно зафиксировать изменение второго региона и равенство авторских данных первого после загрузки. Потолок двух строк +2,07 L1. Общую строку RER-16 с HX-BL-075 учитывать один раз. Влияние на L2/L3 неизвестно. Исходный срез — PR511, b887422b6b05663124f0ce431953f863350e4a86. Предварительный расчёт проверяющего при приёмке, окончательный после сверки публикации.

Интервьюеру проверить весь D1, включая границы перечня внешних правок и варианты на стыке. Ответы привязать к AC4/AC5. Затем аналитик уточняет требования и передаёт чистовую версию программисту. Ориентир из утверждённого предложения — 6–10 запусков на весь путь при одном цикле исправлений, ожидание решений отдельно.
