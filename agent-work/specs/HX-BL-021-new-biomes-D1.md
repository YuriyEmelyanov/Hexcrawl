R04: ручной выбор и автогенерация используют одни ID/названия/высоты. Болотные/лесные/песчаные признаки требуется явно проверить во всех потребителях: forestFamily, terrainAsset,ground palette, feature classifiers, POI, Knave/Mythic. Не классифицировать джунгли как open_plains по fallback; неизвестный игровой профиль честно обозначать, не приписывать всем НРИ одинаковые правила.

## Сохранность, совместимость и ошибки
R08: новые ID валидируются всеми импортерами/редакторами/сериализаторами. Существующие поддерживаемые публичные форматы на текущей базе сохраняются; не копировать устаревшее «version3» из исторической сводки как единственный актуальный формат (публикация PR503 поддерживает16/physical4). Нужда в смене версии определяется после анализа импорта в чистовой спецификации.
R09: JSON roundtrip сохраняет конкретный ID, ручные fine-edits, названия, игровые данные и RNG. Не делать автоматическую миграцию старых biomeId. Старые приложения могут отвергнуть новый ID; не обещать обратную загрузку новых карт старой версией и не заменять неизвестное на равнину.
R10: старые карты не перегенерируются при открытии. Продолжение с Авто может измениться только по согласованной политике новых весов; это отдельная тема интервью о seed-совместимости. Одинаковые новые параметры/seed на одной версии должны давать одинаковый результат.
R11: отмена/повтор выбора или генерации восстанавливает биом, связанные данные и RNG одним штатным действием. Ошибка ассета/неподдерживаемый ID не должна приводить к частичной записи. Для собственного отсутствующего ассета не принимать выпуск с пустым/битым тайлом; допустимую деградацию старого неизвестного входа определить в действующем импортном контракте.
R12:PNG содержит тот же согласованный вид, масштаб, палитру и слои, что карта. Поворот/стиль не потребляют RNG географии, не изменяют биом и не создают историю.
