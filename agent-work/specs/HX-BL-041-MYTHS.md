# HX-BL-041 / MYTHS — дополнение: d6×d12, мифы, ориентиры, провидцы

Версия1.1 • 03.11.2026 • Учитывает последнее уточнение: сохранять у Провидца только имя и кубы. Аналитическое дополнение к TAGS1.0. Первый этап не переписывается. Реализация и публикация не запускались.

## 1. Прямое поручение владельца

«У нас на карте есть мифы. И их значение100% должно быть на карте. Также тегами. Тут сразу двойной куб показываться должен d6d12. Кроме того на странице каждого мифа есть Жилище, святилище, монумент, опасность, проклятие, руины. Это наши точки интереса на карте. Их при создании генератора тоже надо кидать сразу. Нужно вытянуть список со всех страниц и также показывать d6d12 описание. А у святилищ ещё провидцев добавить надо они по таблице рыцарей кидаются. Нужно на странице каждого рыцаря найти провидца».

Теперь в аналитический объём входят72 мифа,432 подсказки ориентиров и72 провидца. Автоматическое наполнение существующих типов карты становится требованием следующего среза. Сам каталог и эта спецификация не означают, что функции уже появились в приложении. Рыцари используются как индекс для получения Провидца; создание полноценных персонажей-рыцарей, их имущества, способностей и страстей в этот срез не входит.

Страница рыцаря=28+2×index0; страница мифа=29+2×index0. Числа каждой из72 пар дополнительно сверены с напечатанными кубами вверху соответствующей страницы рыцаря.

## 3. Две разные формы тега

В TAGS1.0 тег «Удел» содержит независимые значения разных столбцов. Например, [d12:1] Тёмный и [d12:2] Башня — два самостоятельных текста.

Здесь [d6:1][d12:2] — **единый составной индекс одной записи**. Результат — «Стена» для мифа, «Мирный пейзаж» для описания Святилища либо «Раздутый Провидец» для Провидца. Число1 не описывает отдельное свойство, число2 — другое: обе грани вместе определяют один результат. Это не сумма и не десятичное число12.

Общему механизму нужен дополнительный resolver `product_lookup` с разнородными diceSlots: `{id:'group',sides:6}` и `{id:'entry',sides:12}`. Ключ записи — упорядоченный tuple[1..6,1..12]; отображение/данные не объединяют его в сумму. Существующий resolver независимых компонентов не меняет поведение. Определение таблицы и текстовые данные остаются в пакете MB.

Пример контрактного расширения:

```ts
type ProductLookupTag = {
  definitionId: string;
  definitionVersion: number;
  resolver: 'product_lookup';
  diceValues: { group: number; entry: number };
  resolvedEntryId: string;
  resultSnapshot: { title: string; sourcePage: number };
  owner: TagOwnerRef;
  revision: number;
};
```

На практике имя типа и общий формат проектирует разработчик совместимо с TagState первого этапа. Важно сохранить discriminant resolver; нельзя заполнять поля двух независимых компонентов так, будто они означают два текста. Исходная версия каталога и snapshot сохраняются с картой.

## 4. Автоматическое наполнение объектов

| Объект MB | Обязательные теги после нового создания | Источник результата |
|---|---|---|
| Миф на карте | Миф: два видимых куба d6 иd12 + имя конкретного мифа |72 строки таблицы27/страницы29–171 |
| Жилище | Описание: пара + соответствующая подсказка | Столбец dwelling,72 варианта |
| Святилище | Описание: пара + подсказка; отдельно Провидец: собственная пара + только имя | sanctum из мифов; Провидец со страницы выбранного рыцаря |
| Монумент | Описание: пара + подсказка | monument |
| Опасность | Описание: пара + подсказка | hazard |
| Проклятие | Описание: пара + подсказка | curse |
| Руины | Описание: пара + подсказка | ruin; источник — одна из72 страниц мифов, без механической связи с активным мифом |

Броски выполняются после окончательной раскладки POI внутри транзакции генерации королевства. На завершённой новой MB-карте ни один объект этих типов не остаётся неопределённой кнопкой. Добавленный вручную объект получает соответствующие теги в транзакции добавления; сам факт выбора карточки не запускает генерацию. При откате создания восстанавливается всё предыдущее состояние тегов и географии.

**Пары независимы между объектами и назначениями.** Описание Святилища не обязано совпадать с активным мифом региона, ближайшим мифом или мифом всего королевства. Провидец также не обязан получаться по той же паре, что описание Святилища. Совпадение допустимо случайно, но не навязывается связью данных. Пример:

> Святилище: [d6:1][d12:1] Шепчущий ручей.  
> Провидец: [d6:1][d12:2] Раздутый Провидец.  
> Страница30 указана как ссылка в правила. Описание и статы не копируются.

Это пример из каталога, а не состояние уже работающей карты. Автоматически создавать рядом две новые сущности-рыцаря или мифа по этим парам нельзя: пара задаёт источник описания, не размещение дополнительных объектов.

## 5. Переброс составного индекса

1. Нажатие на d6 перебрасывает только group; d12 остаётся прежним. **Весь результат** разрешается заново по новой паре. Нажатие на d12 аналогично меняет entry.
2. Отдельная компактная кнопка «Перебросить оба» в контекстном меню тега бросает оба куба одним действием. Нажатие заголовка заполненного тега не должно скрыто бросать оба.
3. Анимация — только у выбранного куба либо у обоих для общего действия. Повтор числа или всей пары разрешён; он фиксируется как новый бросок без принудительного выбора другого результата.
4. Смена Провидца меняет одновременно имя, sourcePage и EntryId; характеристики и описание не хранятся. Изменение описания Святилища не меняет Провидца.
5. Данные и счётчики фиксируются атомарно при принятии команды, анимация не управляет записью. Вся защита от двойного клика, смены выделения, глобальных мутаций и reduced-motion наследуется от TAGS1.0.
6. Undo/Redo отдельного куба возвращает пару, полный snapshot, счётчики и связанные поля одной транзакцией. Повторный lookup при Redo не используется для подмены сохранённого snapshot новой версией словаря.

Раздельный RNG остаётся обязательным: броски мифов/ориентиров/Провидцев не изменяют географию, дороги, квоты и будущие географические random streams. Разные definitionId и ownerRef разделяют последовательности, даже когда оба тега используют одинаковые грани6/12.

## 6. Руины: только описание, без механической связи с мифом

Последнее уточнение владельца: «Никакой связи с мифом механически нет у руин, вроде».

По этому решению Руины получают только обычный тег: d6/d12 и выбранную подсказку из столбца ruin. Пара может быть любой из72, независимо от активных Мифов королевства. Никакого дополнительного mythId/hintMythId в состоянии карты, отдельного броска неактивного мифа, фильтрации активных записей, зависимостей, ограничений переброса или каскадных изменений не создаётся.

Книжное «намекают на Миф, который сейчас не активен в Королевстве» (русские правила, стр.14) — повествовательная рекомендация мастеру. В текущем продукте она не превращается в процедуру, автоматическую связь, валидацию или критерий приёмки.

Поле source_myth_id в плоском каталоге означает исключительно страницу происхождения текста. Это ключ записи справочника, а не ссылка на активный Миф карты. Изменение тега Мифа не влияет на Руины. Переброс описания Руин не влияет на Мифы.

## 7. Сохранение и исключения источника

Расширяется предложенный v6-контракт TAGS1.0 до реализации: resolver product_lookup и соответствующие snapshots входят в тот же map.tags. Если к моменту разработки v6 уже опубликован, формат нельзя поменять молча: поднять версию по действующему migration contract. Старые карты без конкретных мифов и описаний не получают случайные значения при простом открытии. Для их заполнения — явная отменяемая команда «Заполнить недостающие теги MB», которая не меняет существующие результаты, географию и квоты.

У Провидца сохраняются только имя и пара кубов; source_page и имя рыцаря допустимы как техническая навигация к правилам. Биография, описания, способности, характеристики и статблоки не входят в состояние карты, конечный каталог или UI этого среза. Нельзя подставлять вместо них краткий пересказ: уточнение владельца требует именно только названия.

Имена Провидцев восстановлены из mojibake PDF обратным преобразованием Latin1→CP1251; исходная кодировочная поломка не показывается мастеру. Орфография исходной русской версии не исправляется молча. Развалины→ruin — только нормализация типа;5 исходных подписей сохранены. Имена таблицы27 и заголовков страниц различаются в двух случаях, оба доступны. JSON не импортируется в состояние карты как исполняемый код.

## 9. Статус и граница следующей работы

Каталоги извлечены и структурно проверены; это не независимая проверка реализации. Не добавлялись автоматическое раскрытие Знамений, сезонная смена Мифов, награждение Славой, встречи, бой или механика советов Провидцев. Эти сведения не следует объявлять выполненными по одному каталогу имён/подсказок.

Score-модель1.2: возможная связь с S08-C04 и будущим наполнением режима, но исходный grade/прогноз/delta=unknown. Каталог не подтверждает S06-C02 как работающий движок развивающихся угроз. Баллы не начислять.

Следующая передача разработчику должна объединить TAGS1.0 и это дополнение, сохранив два resolver, таблицы применимости и порядок транзакций. В рамках текущего поручения подготовлены аналитические материалы; main, продукт и публикация не изменены.

## 10. Учтённые уточнения владельца

- Сохранять у Провидца только название и кубы; source_page служит навигации. Биографии, способности, описания и характеристики исключены.
- У Руин нет механической связи с Мифами. Источник подсказки — только библиографическое происхождение.
- Прежняя черновая попытка записи дополнения с отдельной связью Руин отклонена автоматической проверкой; в GitHub она не была создана. Настоящая1.1 убирает отменённые требования, а не обходит отказ.
