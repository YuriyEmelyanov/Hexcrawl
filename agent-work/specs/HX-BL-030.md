# HX-BL-030 — воспроизводимое продолжение карты

Версия спецификации 1.0; 24.10.2026. Статус: ready_for_development.
Основание: owner-approval-2026-10-24-HX-BL-030 в approvals.json, утверждённое предложение proposals/2026-10-24-HX-BL-030.md. Подробности ниже конкретизированы аналитиком внутри утверждённых границ; отдельное согласование реализации не требуется. Выпуск требует разрешения владельца на проверенный SHA.

## Цель, источники и границы

Мастер получает одинаковый мир при одинаковой версии генератора, seed, исходном документе, параметрах и упорядоченной последовательности действий. Непрерывное расширение совпадает с продолжением после JSON save/load; undo и rollback восстанавливают случайность. Обязательны classic и Mythic Bastionland, включая многошаговое построение королевства.

Исследован production main@6aaefa8896e7aac163cfcd5c2ca896ac60fc54d0. AGENTS.md и docs/index.md читать из main: операционная ветка исторически не содержит index. Действующие основания: docs/strategy/vision.md, score-model.md 1.1, development-workflow.md, region-generation.md, mythic-bastionland.md и spec HX-NEXT-001 1.0. Старое исключение RNG в HIST-08 последней спецификации заменяется этой задачей; остальные требования к безопасному импорту/истории сохраняются.

Наблюдения по исходникам, не результаты новых тестов: App.tsx использует Math.random в общей выборке, размерах/биомах/рельефе/воде/кандидатах; modes/obstacles.ts и pointsOfInterest.ts имеют собственные случайные вызовы; regionSize, riverCrossings, riverRapids, riverWaterfalls принимают random с fallback Math.random. MapSnapshot и JSON v2 не содержат RNG; generationDiagnostics выдаёт state=null. Подмена глобального Math.random в существующих тестах не является функцией продукта.

Входит: RNG-модуль, явная передача потоков в затронутые функции, минимальные UI seed, JSON/валидация/миграция, снимки и транзакции, диагностические метаданные и проверка реальных обработчиков. Не входит: новые правила географии, широкий вынос ядра из React, защищённые произвольные сущности, локальный reroll/новые кнопки перегенерации, история между перезапусками, облачный обмен, новые игровые истории и оптимизация. Статистические распределения, RIV/ROAD и правила Mythic не менять ради тестов. Иной результат случайных бросков после перехода на новый RNG допустим.

## Контракт случайности и данных

RNG-01. Состояние — часть документа мира, не глобальное состояние приложения/React-render. Чистый модуль без React экспортирует создание, draw, clone/restore и валидацию состояния. Запрещена глобальная подмена Math.random в production. Все вызовы, способные изменить сохраняемый мир, используют явный поток; fallback разрешён только вне production пути, с доказательством отсутствия вызова через обработчики.

RNG-02. Минимальный сериализуемый контракт верхнего поля `generation`:
`{ generatorVersion: string, rngVersion: "mulberry32-v1", masterSeed: uint32, streams: { geography: uint32, poi: uint32 } }`.
uint32 — целое число 0..4294967295 включительно; zero валиден. generatorVersion — отдельная версия алгоритмов, не SHA, не версия схемы. Обновить существующую GENERATION_ALGORITHM_VERSION на новое значение и использовать один источник истины в экспорте/диагностике. Точная строка фиксируется разработчиком до реализации тестовых векторов. Состояния потоков сохраняются непосредственно, не выводятся заново из seed при загрузке.

RNG-03. Для mulberry32-v1 фиксировать unsigned 32-bit арифметику: state=(state+0x6D2B79F5)>>>0; t=imul(state^(state>>>15),state|1); t^=t+imul(t^(t>>>7),t|61); результат=((t^(t>>>14))>>>0)/4294967296. Все приведения/переполнения JS задокументировать и закрепить известными векторами из отдельной эталонной реализации, включая seeds 0 и 4294967295. Инициализация geography=masterSeed>>>0, poi=(masterSeed^0x9E3779B9)>>>0. Это воспроизводимость, не криптография.

RNG-04. Geography: размер/освоенность/биом, форма/рельеф/вода, реки/озёра/полноводность/пороги/водопады, дороги/переправы, расположение королевств и препятствий. Poi: размещение/количество/вид центральных, обычных и водных POI, Mythic престол/уделы/мифы/ориентиры. Инвентаризировать также вложенные функции и fallback. При совмещённой функции передавать оба потока; не выбирать случайный результат дважды для UI и snapshot. POI не должны использовать geography. Существующие доменные зависимости географии от уже сохранённых объектов сохраняются: независимость потоков не означает независимость всех последующих бизнес-решений.

RNG-05. Топонимы остаются на существующем отдельном seed/модели. Для нового мира toponymSeed детерминированно получается из masterSeed без расхода geography/poi (например masterSeed XOR 0x85EBCA6B, закрепить векторы). Визуальные паттерны остаются отдельными детерминированными функциями; отрисовка, стили, RU/EN, zoom/pan/rotate, выбор гекса, экспорт JSON/PNG, открытие панелей и изменение имени не двигают ни один поток мира. Имена при импорте/undo/redo не регенерировать. Полный смысловой мир при одинаковых входах включает имена; только при проверке намеренного переименования исключать из географического сравнения сами имена.

RNG-06. Порядок обходов и tie-break должны быть детерминированы. Нет зависимости от времени, числа кадров, порядка React effects или неупорядоченного завершения async. Два открытых документа/изолированных генератора не влияют друг на друга. Системная энтропия допустима только для нового автоматически выбранного masterSeed; новый seed сразу виден пользователю и экспортируется.

## Пользовательское поведение

UI-01. В существующую панель генерации добавить подписанное поле «Seed мира» / «World seed»: десятичное uint32, значение видно и доступно для копирования. Ввод разрешён только для пустого мира вне мутации. Непустая карта показывает seed read-only; для смены используется существующий сброс. Не добавлять отдельный workflow подтверждений.
UI-02. Новый сеанс без seed выбирает его один раз; применение явно введённого seed и первой генерации не зависит от числа render/focus. Невалидный ввод (пустая строка при применении, знак минус, дробь, NaN, выход за uint32) блокирует генерацию с понятным сообщением, без мутации/расхода RNG. Смена валидного seed на пустой карте атомарно устанавливает оба начальных потока и seed имён; если меняется документ, это undo-транзакция, повтор значения — no-op.
UI-03. Существующий reset очищает документ и создаёт новый автоматически выбранный seed один раз в успешной транзакции; undo восстанавливает прежние карту и seed/потоки, redo — тот же сброс без новой энтропии. Reset уже пустого неизменённого документа остаётся no-op. Ввести конкретный seed после reset можно через UI-01. Не менять смысл текущих кнопок генерации.
UI-04. Параметры генерации берутся из текущих controls, а action записывается с пользовательскими категориями до случайного разрешения (включая размер auto/диапазон). При replay задаются те же controls, anchor, mode и последовательность. Сохранение всех несохраняемых настроек панели между сеансами не требуется: для сравнения следующего действия тест/пользователь явно выставляет одинаковые параметры.

## Транзакции, ошибки и перегенерация

TX-01. Копия generation входит в MapSnapshot, DocumentSnapshot, GenerationBackup, пользовательские undo/redo и генерационные checkpoints. Снимать before до первого случайного выбора, включая buildGenerationOptions и выбор anchor. Успешная генерация коммитит мир и окончательные состояния одновременно; все именования/переправы в after совпадают с видимой картой. Внутренние шаги Mythic работают на одном рабочем состоянии; целое королевство — одна пользовательская транзакция.
TX-02. Ошибка, constraint-rejection, исчерпание попыток без коммита и отмена восстанавливают точный before, оба потока, seed, обе истории, counters и UI. Повтор той же неуспешной операции допустимо снова даёт тот же отказ; скрытый reroll после отказа запрещён. Если штатный fallback действительно создал урочище/море и коммитнул карту, это успех с сохранением всех потраченных внутри попыток draw. Реальные внутренние retries потребляют рабочий поток; нельзя начинать каждую попытку с одной и той же копии.
TX-03. Undo→то же действие с теми же параметрами даёт тот же after и RNG; redo восстанавливает точный after без draw. Ручные правки с явным значением RNG не тратят; если существующая операция выбирает POI случайно, тратит только poi, и undo восстанавливает его. No-op/невалидный импорт/ошибка сохраняют redo.
TX-04. Delete last region/kingdom восстанавливает RNG генерационного checkpoint наряду с прежним смыслом удаления; общий undo/redo этой операции точен. Import/reset устанавливают прежнюю границу checkpoints. История сеанса не экспортируется; после загрузки delete-last/regenerate недоступны до новой генерации, как в HX-NEXT-001.
TX-05. Regenerate last остаётся запросом нового варианта, не синонимом undo→generate: география восстанавливается из генерационного checkpoint, но рабочие потоки начинаются с generation перед нажатием regenerate. Сам regenerate при успехе коммитит обновлённые потоки; новый checkpoint содержит восстановленный базовый мир и RNG на старте этого regenerate. Сохранять предусмотренные текущей логикой имена/границы удаления; не обещать обязательно иной мир при каждом броске. Undo regenerate возвращает точный заменённый мир с правками и его RNG; повтор regenerate после undo воспроизводит тот же вариант; ошибка восстанавливает полный before. Правило распространяется на целое Mythic-королевство и pendingRegen.
TX-06. Запретить экспорт промежуточного состояния при kingdomJob/pendingRegen/importInFlight и других незавершённых мутациях. Повторный клик/устаревший callback/StrictMode не потребляют RNG дважды и не коммитят устаревший документ. Не вводить глобальный активный поток, теряющий контекст между тиками Mythic.

## Формат и совместимость

SAVE-01. Новый экспорт — schema="hexcrawl-map", version=3, обязательное generation по RNG-02; остальные слои и гарантии HX-NEXT-001 сохраняются. Версия схемы отделена от generatorVersion и rngVersion. Поддерживаемый импорт: v2 с миграцией и v3 с текущими generatorVersion/rngVersion. Неподдерживаемые v1/v4+, generatorVersion или rngVersion отклоняются атомарно с конкретной причиной; не подменять текущей версией молча. Воспроизводимость гарантируется только на одинаковой поддерживаемой версии генератора, не через произвольные будущие релизы.
SAVE-02. У v3 проверять типы и диапазоны всех RNG полей до любых setter/истории. Отсутствующее/частичное generation, неизвестный поток вместо обязательного, неверный тип/диапазон/версия — отказ без мутации и draw. Дополнительные неизвестные поля не объявлять поддержанными и не обещать их round-trip. Для v2 без generation установить его миграцией; v2 с generation валидировать тем же контрактом, не игнорировать ошибочное известное поле.
SAVE-03. Старый v2 получает детерминированный seed продолжения: существующий валидный map.toponyms.seed как uint32; при отсутствии — существующий legacyToponymSeed по регионам, приведённый к uint32. Начальные потоки выводить по RNG-03. Регионы/terrain/реки/дороги/POI/kingdoms/obstacles/ID/имена не пересоздавать; прежние нормализации v2 (candidates, counters, selection и defaults) сохраняются. Повторный импорт того же v2 при одинаковых действиях имеет одинаковое продолжение; неизвестную историческую последовательность старого Math.random восстановить нельзя. Показать ненавязчивое уведомление «Старая карта: seed задан для дальнейшего продолжения» и английский эквивалент. Новый экспорт уже v3 с текущими состояниями, повторная загрузка не запускает миграцию снова.
SAVE-04. Зафиксировать до реализации manifest поддерживаемого корпуса: все v2 fixtures/варианты и exports classic/Mythic из HX-NEXT-001; новые v3 empty/classic/Mythic, варианты seed 0/max и продвинутых потоков. Записать происхождение, git SHA/хеш, ожидаемые нормализации и версию. Не удалять неудобный fixture после отказа. Новый формат может быть отклонён старой опубликованной версией приложения: явно указать в документации, не обещать чтение v3 старым клиентом.
SAVE-05. Сравнение воспроизводимости: полный canonical JSON (ключи объектов сортируются, массивы/порядок путей не меняются), включая generation, counters, candidates, names и сохранённые ui при одинаковых view/selection. Единственное исключение — savedAt. Для изолированного эксперимента со стилем/именем допускается отдельная явно названная проекция географии; она не заменяет полное сравнение основных сценариев.

## Диагностика и зависимости

DIAG-01. В существующее поколенческое diagnostic добавить generatorVersion, rngVersion, masterSeed и отстранённые копии потоков до/после, mode, anchor, исходные параметры action и исход операции. При rollback after соответствует восстановленному состоянию; состояние на момент ошибки можно отдельно пометить attempted. Никаких новых dashboard/аналитических отправок или содержимого закрытой карты. Не заявлять, что один seed воспроизводит ошибку на произвольной исходной карте: для продолжения нужен исходный JSON плюс записанное действие.
DEV-01. Продуктовая ветка от актуального main с base SHA; скопировать эту spec и обновить профильные docs/ADR формата и RNG в том же PR. Перенос всей agent-operations в main не нужен. Для географии/рек/дорог соблюдать AGENTS.md и действующие RIV/ROAD; настоящие изменения правил требуют уточнения задачи. Минимальные сигнатуры передачи RNG допустимы без широкого рефакторинга. Существующие API потребителей и тестовую инструментацию обновить явно, не маскировать отсутствующий RNG автоподменой глобального Math.random.
