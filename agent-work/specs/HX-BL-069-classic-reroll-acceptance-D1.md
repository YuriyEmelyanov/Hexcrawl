# Переброс региона Classic · контрольный пример для D1

Приложение к [черновику D1](HX-BL-069-classic-reroll-D1.md). Оно уточняет проверку AC1, заметки из AC2 и переходы истории и импорта из AC3/AC5. Варианты по объектам на границе остаются в [интервью](../interviews/HX-BL-069/REROLL/round-001.json).

## Как воспроизвести

На исходном коде `b887422b6b05663124f0ce431953f863350e4a86` использован штатный сценарный стенд `test/helpers/generation-harness.mjs` с настоящими обработчиками редактора. Создать чистую карту Classic с seed 1. Два раза вызвать `safelyAddRegionToMap` с размером 8 и `coastalPreference: 'mainland'`, сначала для (0,0), затем для (1,−1). После создания второго региона выбрать гекс (0,1) первого, назначить ему «Снежно-ледяная равнина» и записать «У старой переправы ждёт проводник.». Завершить ввод заметки. Выполнить штатный переброс последнего региона с текущими настройками размера, затем отмену и повтор. Сравнивать документ целиком за исключением времени экспорта. Для побайтово воспроизводимого сравнения упорядочить ключи объектов рекурсивно, сохраняя порядок массивов, и вычислить SHA-256 компактного JSON в UTF-8.

## AC2 · Создание и удаление мест целиком в первом регионе

Использовать ту же карту Classic с seed 1 в сессии создания. После генерации обоих регионов удалить статую первого региона на (0,0), создать руины на (1,0) и задать им имена «Старая застава» и «Old Watchpost».

На b887422 попытка переброса заблокирована предупреждением об утрате имени. Весь документ и длина истории сохранились. В контрольной ветви сценария очищены оба имени, геометрия и типы мест сохранены. Первый переброс вернул статую и убрал руины. Второй дал другой вариант второго региона и сохранил ошибочное состояние первого. Две отмены вернули в точности документ перед первым успешным перебросом.

Для приёмки исправления оба переброса должны завершиться при заполненных именах. После каждого сверить новый вариант второго региона, единственный экземпляр руин на (1,0), оба имени и отсутствие статуи на (0,0). Очистка имён использована только для диагностики текущего поведения. Оба гекса внешние, решения о пересечении границы для этого критерия не требуются. Привязка к оценке — SEED-07 и RER-16 по D1, та же проверка сохранности внешних правок.

## AC5 · Продолжение старой карты Classic

На SHA b887422 проверены три штатных JSON формата v2 из test/fixtures/import-v2: baseline-classic, manual-edit-map и legacy-optionals. Для каждого открыть карту в новой сессии. Приложение экспортирует её как v10. Пока пользователь не добавил регион, история генерации пуста. Попытка переброса оставляет документ и длину истории отмены без изменений.

На гексе (0,0) исходного региона назначить снежную равнину. Добавить регион из первой доступной клетки с targetSize 8 и coastalPreference mainland. Появляется одна контрольная точка генерации. Теперь сменить тот же внешний гекс на холмы и перебросить добавленный регион. Во всех трёх примерах второй регион изменился, а внешний гекс вернулся к снежной равнине. Одна отмена точно восстановила документ с холмами. После экспорта и открытия этого документа в новой сессии карта совпала, история генерации снова пуста.

**Критерий исправления.** До добавления региона сохранить текущую защиту. После добавления разрешить переброс этого региона и сохранить холмы на внешнем гексе. Сверять последнюю ручную правку перед командой. Проверки одного лишь наличия ручного биома недостаточно: при дефекте поле заполнено прежним значением. Одна отмена восстанавливает последний вариант обоих регионов. Прогноз SEED-07 и RER-16 указан в D1; текущий пример уточняет доказательство тех же строк.

## Внешняя переправа · контроль для AC4 и AC3

Classic, seed 1, два региона по 8 гексов, те же исходные настройки, что в AC1. Перед перебросом все три отрезка дороги №2 принадлежат первому региону. На отрезке (0,3)–(1,3) изменить мост через реку №1 на переправу. Зафиксировать тип и привязку к ребру реки, затем перебросить второй регион. На b887422 второй регион изменился; дорога №2 получила продолжение. Прежний отрезок, ребро реки и ключ пересечения сохранились, но тип вновь стал мостом. Одна отмена в точности вернула документ с переправой. Повтор и последующий импорт воспроизвели документ с мостом.

**Критерий приёмки.** Если прежний внешний отрезок и ребро реки сохранились, на них должна остаться одна переправа с выбранным мастером типом. Проверить привязку к обоим рёбрам, отсутствие второго пересечения под иным ключом и сохранность результата после повтора и импорта. Сравнивать защищённый участок дороги. Длина всей дороги может измениться за счёт продолжения. Этот сценарий не определяет поведение при исчезновении стыка на границе (RR-Q01). Для score-модели это дополнительное свидетельство тех же SEED-07 и RER-16.

## AC4 · Пример для решения RR-Q01 о конце дороги

На контрольной карте Classic (seed 1, два материковых региона по 8 гексов) дорога №1 идёт от (0,1) к статуе на (0,0) первого региона и далее к (1,−1) второго. Заменить мост на участке первого региона переправой и перебросить второй регион. На b887422 гекс (1,−1) остался во втором регионе, но ребро от статуи к нему исчезло из всех дорог. Дорога №1 закончилась у статуи. Статуя сохранилась; редактор путей учитывает обычный POI как допустимый пункт назначения. Тип ручной переправы на сохранившемся отрезке откатился к мосту. Отмена и повтор вернули точные документы до и после операции.

| Ответ по RR-Q01 | Ожидаемый результат для этой карты |
|---|---|
| A, отклонить вариант | Оба региона, оба отрезка, статуя, тип переправы и состояние генератора совпадают с документом до команды. Отказ не добавляет действие в историю. |
| B, разрешить допустимый конец | При соблюдении прочих ограничений принять новый второй регион. Дорога может закончиться у статуи. Сохранить внешний отрезок (0,1)–(0,0), его ручную переправу и ссылку на реку. Отмена возвращает всю исходную карту за один шаг. При недопустимом конце действует отказ. |

Варианты условны до ответа владельца. Тип переправы защищён при любом исходе. Пример иллюстрирует только дорогу; политику для рек владелец может определить отдельно. ## AC2 · Перенос места через границу (RR-Q02)

Исходная карта Classic с seed 1 и двумя регионами по 8 гексов. В двух отдельных сессиях вызвать штатную команду переноса наземной точки. После каждого переноса проверить, что исходная клетка пуста и точка нужного типа появилась в целевой. Затем перебросить только второй регион.

| Ручное действие | Результат на b887422 |
|---|---|
| Вынести статую из второго региона (1,1) в первый (1,0) | Перенос выполнен. После переброса пусты обе клетки, хотя (1,0) по-прежнему в первом регионе. |
| В первом регионе создать руины на (1,0) и перенести их во второй на (2,−1) | Перенос выполнен. После переброса руины отсутствуют на обеих клетках. |

В обоих случаях отмена переброса восстановила весь документ с уже перенесённым местом, повтор воспроизвёл документ после переброса. Сравнение исключает время экспорта. Примеры относятся к обычным наземным точкам без авторских имён.

**Условие для чистовой версии.** При выборе A из RR-Q02 считать принадлежность по положению перед командой: вынесенная статуя остаётся на (1,0) в одном экземпляре, внесённые руины подчиняются обычной генерации. При выборе B учитывать регион создания: статуя может исчезнуть, а для руин из первого региона проверить защиту после переноса. Если целевой гекс защищаемого места исчезает, конкретный исход требует согласования в рамках этого ответа. На контрольной карте оба целевых гекса существуют и после переброса. Текущее поведение не устанавливает правило.

## AC4 · Город на границе двух регионов (RR-Q03)

[Контрольная карта Classic](../evidence/HX-BL-069/acceptance-D1/city-border-map.json) открывается штатным импортом на b887422. В исходном гексе (2,0) региона №1 расположен один город, detail-poi:1. Его физический контур диаметром 2 мили занимает части семи одномильных клеток. Пересечение самого контура с гексами (2,0) и (3,0) имеет положительную площадь по обе стороны границы. Второй гекс принадлежит региону №2. Это один объект с одним идентификатором. Экспорт после импорта совпал с исходным документом без учёта времени сохранения.

Для приёмки классифицировать границу по площади фактического контура: касание границы в одной точке само по себе не создаёт смешанный объект. Для варианта A RR-Q03 сравнить весь контур и идентичность; при несовместимом новом варианте проверить полный отказ без записи в историю. Для варианта B проверить равенство части контура за пределами замены, связность всей площади и сохранение идентификатора, имён и действующих связей. Если условия выполнить нельзя, проверить отказ. У контрольного города нет связей с дорогами; этот файл проверяет геометрию и идентичность.

Исходная карта подготовлена через поддерживаемый формат сохранения. Сразу после открытия история генерации пуста. Пример подтверждает существование объекта и пригоден для проверки классификации; фактический переброс с таким городом требует сессии с историей. Ни один из вариантов RR-Q03 пока не принят. ## AC4 · Отказ после начала переброса при доступном повторе

На карте Classic из AC1 назначить на (0,1) снежную равнину, добавить заметку «У старой переправы ждёт проводник.» и отменить только ввод заметки. Зафиксировать обе версии документа. Перед перебросом видны два региона и снежная равнина, заметка отсутствует, доступен один повтор.

Для проверки отказа в стенде вызвать regenerateLastRegion, дождаться pendingRegen и убедиться, что промежуточное состояние содержит один регион. Через injectFunction временно вызвать исключение в __profileBeginClick во время finishPendingRegeneration. Это моделирует сбой после восстановления контрольной точки, до построения нового региона. Убрать подмену.

Критерий для любого отказа на этой стадии: в состоянии приложения есть сообщение об ошибке; документ совпадает с исходным, включая оба региона, выбор (0,1), ручной биом и состояние генератора. Содержимое истории генерации, отмен и повторов совпадает целиком. Нажатие «Повторить» возвращает заметку и весь ранее сохранённый вариант с ней; следующая отмена возвращает исходный вариант без заметки. При сравнении экспортов исключить только время сохранения.

На исходном SHA b887422 этот сценарий выполнен: три доступных отмены и один повтор сохранены, проверено действие повтора. Это контроль уже работающего восстановления при техническом сбое. ## Источник внешних правок для AC1–AC3

На одной карте Classic с seed 1 мастером изменены тип именованного объекта на (0,0) и биом на (0,1), добавлена заметка. На b887422 резервная копия перед перебросом содержит все четыре правки. Для успешного результата сравнивать внешние объекты и клетки с документом перед командой. Снимок до создания региона определяет исходные условия генерации; его поля типа места и ручного биома устаревают при последующем редактировании. Для отказа эталоном остаётся весь документ перед командой с историей. Промежуточная стадия измерена через обработчики и не является требованием к отображению интерфейса. ## Один запуск для проверки внешних правок · AC1–AC3

[Сценарий external-fields.mjs](../evidence/HX-BL-069/acceptance-D1/external-fields/external-fields.mjs) запускается с Node 24. В проверяемой копии приложения должны быть установлены зависимости из lock-файла. Передать путь к этой копии. При запуске из корня ветки agent-operations команда выглядит так:

```sh
node agent-work/evidence/HX-BL-069/acceptance-D1/external-fields/external-fields.mjs /path/to/Hexcrawl
```

Сценарий создаёт два региона Classic на seed 1 и меняет три поля гекса (0,0) первого региона: тип места на руины, биом на снежно-ледяную равнину и заметку на две строки. Перед перебросом он проверяет наличие всех трёх правок. После завершения штатного переброса проверяет новый контур второго региона, единственный экземпляр точки, тип, биом и дословную заметку. Затем сравнивает оба полных документа с результатами отмены, повтора и повторного открытия, исключая время экспорта. Для сохранения двух карт передать вторым аргументом существующую папку.

Код завершения 0 означает, что все условия этого примера выполнены. При расхождении полей итоговый JSON перечисляет их в `failed`, код завершения 1. Ошибка создания исходной карты или выполнения сценария также завершает процесс с ошибкой и выводит диагностику.

На [main 94f24f6](../evidence/HX-BL-069/acceptance-D1/external-fields/main.json) и [сборке PR №513 192aa57](../evidence/HX-BL-069/acceptance-D1/external-fields/pr513.json) расхождения одинаковы: вместо руин осталась статуя, ручной биом исчез. Заметка сохранилась; Undo, Redo и импорт точно воспроизвели соответствующие состояния, включая потерю правок. Пример охватывает одно внешнее место на одной карте и дополняет отдельные проверки пограничных объектов.
