# Переброс региона Classic · контрольный пример для D1

Приложение к [черновику D1](HX-BL-069-classic-reroll-D1.md). Оно уточняет проверку AC1, заметки из AC2 и переходы истории и импорта из AC3/AC5. Варианты по объектам на границе остаются в [интервью](../interviews/HX-BL-069/REROLL/round-001.json).

## Как воспроизвести

На исходном коде `b887422b6b05663124f0ce431953f863350e4a86` использован штатный сценарный стенд `test/helpers/generation-harness.mjs` с настоящими обработчиками редактора. Создать чистую карту Classic с seed 1. Два раза вызвать `safelyAddRegionToMap` с размером 8 и `coastalPreference: 'mainland'`, сначала для (0,0), затем для (1,−1). После создания второго региона выбрать гекс (0,1) первого, назначить ему «Снежно-ледяная равнина» и записать «У старой переправы ждёт проводник.». Завершить ввод заметки. Выполнить штатный переброс последнего региона с текущими настройками размера, затем отмену и повтор. Сравнивать документ целиком за исключением времени экспорта. Для побайтово воспроизводимого сравнения упорядочить ключи объектов рекурсивно, сохраняя порядок массивов, и вычислить SHA-256 компактного JSON в UTF-8.

| Шаг | Наблюдение на исходном SHA | Требование к исправлению |
|---|---|---|
| Перед перебросом | Во втором регионе 8 гексов. На (0,1) сохранены ручной биом и заметка | Эта версия карты служит эталоном внешних правок |
| Переброс | Второй регион вырос до 60 гексов. Заметка на (0,1) сохранилась, ручной биом исчез. Слой карты отобразил хвойный лес | Второй регион получает новый вариант. На (0,1) остаются ручной биом и точный текст заметки. Число 60 описывает этот прогон |
| Отмена | Весь исходный документ восстановлен, включая обе правки и 8 гексов | Одна отмена возвращает исходный документ |
| Повтор | Документ совпал с полученным после переброса, включая утрату биома | Один повтор возвращает именно исправленный вариант со всеми внешними правками |
| Открытие каждого из двух JSON в новой сессии | Оба документа совпали со своими экспортами. История генерации пуста. Вызов переброса оставил документ прежним | Сравнить сохранность правок и карту с экспортом. Проверять сам переброс в сессии создания двух регионов |

## AC2 · Создание и удаление мест целиком в первом регионе

Использовать ту же карту Classic с seed 1 в сессии создания. После генерации обоих регионов удалить статую первого региона на (0,0), создать руины на (1,0) и задать им имена «Старая застава» и «Old Watchpost».

На b887422 попытка переброса заблокирована предупреждением об утрате имени. Весь документ и длина истории сохранились. В контрольной ветви сценария очищены оба имени, геометрия и типы мест сохранены. Первый переброс вернул статую и убрал руины. Второй дал другой вариант второго региона и сохранил ошибочное состояние первого. Две отмены вернули в точности документ перед первым успешным перебросом.

Для приёмки исправления оба переброса должны завершиться при заполненных именах. После каждого сверить новый вариант второго региона, единственный экземпляр руин на (1,0), оба имени и отсутствие статуи на (0,0). Очистка имён использована только для диагностики текущего поведения. Оба гекса внешние, решения о пересечении границы для этого критерия не требуются. Привязка к оценке — SEED-07 и RER-16 по D1, та же проверка сохранности внешних правок.

## AC5 · Продолжение старой карты Classic

На SHA b887422 проверены три штатных JSON формата v2 из test/fixtures/import-v2: baseline-classic, manual-edit-map и legacy-optionals. Для каждого открыть карту в новой сессии. Приложение экспортирует её как v10. Пока пользователь не добавил регион, история генерации пуста. Попытка переброса оставляет документ и длину истории отмены без изменений.

На гексе (0,0) исходного региона назначить снежную равнину. Добавить регион из первой доступной клетки с targetSize 8 и coastalPreference mainland. Появляется одна контрольная точка генерации. Теперь сменить тот же внешний гекс на холмы и перебросить добавленный регион. Во всех трёх примерах второй регион изменился, а внешний гекс вернулся к снежной равнине. Одна отмена точно восстановила документ с холмами. После экспорта и открытия этого документа в новой сессии карта совпала, история генерации снова пуста.

**Критерий исправления.** До добавления региона сохранить текущую защиту. После добавления разрешить переброс этого региона и сохранить холмы на внешнем гексе. Сверять последнюю ручную правку перед командой. Проверки одного лишь наличия ручного биома недостаточно: при дефекте поле заполнено прежним значением. Одна отмена восстанавливает последний вариант обоих регионов. Прогноз SEED-07 и RER-16 указан в D1; текущий пример уточняет доказательство тех же строк.

## Внешняя переправа · контроль для AC4 и AC3

Classic, seed 1, два региона по 8 гексов, те же исходные настройки, что в AC1. Перед перебросом все три отрезка дороги №2 принадлежат первому региону. На отрезке (0,3)–(1,3) изменить мост через реку №1 на переправу. Зафиксировать тип и привязку к ребру реки, затем перебросить второй регион. На b887422 второй регион изменился; дорога №2 получила продолжение. Прежний отрезок, ребро реки и ключ пересечения сохранились, но тип вновь стал мостом. Одна отмена в точности вернула документ с переправой. Повтор и последующий импорт воспроизвели документ с мостом.

**Критерий приёмки.** Если прежний внешний отрезок и ребро реки сохранились, на них должна остаться одна переправа с выбранным мастером типом. Проверить привязку к обоим рёбрам, отсутствие второго пересечения под иным ключом и сохранность результата после повтора и импорта. Сравнивать защищённый участок дороги. Длина всей дороги может измениться за счёт продолжения. Этот сценарий не определяет поведение при исчезновении стыка на границе (RR-Q01). Для score-модели это дополнительное свидетельство тех же SEED-07 и RER-16.

## AC4 · Пример для решения RR-Q01 о конце дороги

На контрольной карте Classic (seed 1, два материковых региона по 8 гексов) дорога №1 идёт от (0,1) к статуе на (0,0) первого региона и далее к (1,−1) второго. Заменить мост на участке первого региона переправой и перебросить второй регион. На b887422 гекс (1,−1) остался во втором регионе, но ребро от статуи к нему исчезло из всех дорог. Дорога №1 закончилась у статуи. Статуя сохранилась; редактор путей учитывает обычный POI как допустимый пункт назначения. Тип ручной переправы на сохранившемся отрезке откатился к мосту. Отмена и повтор вернули точные документы до и после операции.

| Ответ по RR-Q01 | Ожидаемый результат для этой карты |
|---|---|
| A, отклонить вариант | Оба региона, оба отрезка, статуя, тип переправы и состояние генератора совпадают с документом до команды. Отказ не добавляет действие в историю. |
| B, разрешить допустимый конец | При соблюдении прочих ограничений принять новый второй регион. Дорога может закончиться у статуи. Сохранить внешний отрезок (0,1)–(0,0), его ручную переправу и ссылку на реку. Отмена возвращает всю исходную карту за один шаг. При недопустимом конце действует отказ. |

Варианты условны до ответа владельца. Тип переправы защищён при любом исходе. Пример иллюстрирует только дорогу; политику для рек владелец может определить отдельно.
