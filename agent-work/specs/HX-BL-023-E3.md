# HX-BL-023 / E3 — дороги, тропы и переправы

Версия E3-1.0, 31.10.2026. Статус: пригодная спецификация утверждённого этапа; реализация и публикация ещё не выполнены. База defaa5c24d546e4283430573c2d4e4f3b6194dc0. Родитель HX-BL-023v2.3, owner-decision-2026-10-28-editor-additional-functions-approved. Выпуск требует независимого review нового SHA и отдельного разрешения владельца. Предлагаемый вид E3-UI1 — evidence/HX-BL-023-E3-spec/desktop.png и narrow.png, в той же ветке agent-operations.

## Цель и границы

Ведущий вручную связывает места подготовленной карты, меняет дорогу на тропу, убирает лишний участок и выбирает вид переправы. Primary: develop_existing; secondary:create_from_scratch. Пример до/после: есть сгенерированная тропа к деревне; ведущий делает её дорогой и заменяет брод мостом, сохраняет JSON и возвращает исходный вариант через Undo.

Входит: соседние сухопутные сегменты road/trail, создание последовательности, удаление участка/выделенного пути, смена типа участка, добавление и изменение связанных переправ, безопасное удаление. Classic и Mythic. Не входит: вода/русло/высоты/препятствия/перенос POI, travel time/движение партии, новый генератор маршрутов, платные сервисы, новая числовая норма дорог, исправление всего исторического ROAD-аудита. Родительские E4–E8 остаются отдельными этапами.

## Фактическая база и применимые источники

Прочитаны docs/road-model.md, road-model-audit.md, src/riverCrossings.ts, App.tsx и saveValidation.ts на указанном SHA. ROAD-аудит — датированное evidence, не список новых дефектов. Требования RIV и Mythic для затрагиваемых пересечений/препятствий сохраняются.

- App.tsx:268–277: Road{id,regionId,segments}; segment{from,to,kind}; RiverCrossing{key,roadId,roadSegmentKey,riverId,riverEdgeKey,kind}. Тип принадлежит сегменту, один Road может иметь смешанные типы и проходить несколько регионов.
- App.tsx:8376–8429: ключ переправы roadId:normalizedSegment:riverId; reconcileRiverCrossings сохраняет существующий kind, удаляет исчезнувшие пересечения и случайно выбирает недостающие. Нельзя вызывать его как неограниченный глобальный ремонт при ручной правке.
- getSettledMainRoadLimit:2 либо3 для размеров «Большой регион», «Край», «Обширный край»; getRoadBuildCountForSettledRegion считает записи владельца с road-сегментом. Это существующая проверка минимума, не универсальное измерение связности.
- canAddRoadPath проверяет соседство/сушу/повторы/принадлежность внутренних гексов региону. Нельзя использовать его ограничение одним новым регионом как запрет вручную соединять уже созданные регионы.
- saveValidation.ts:117–165 проверяет ID, соседство, ссылки сегментов/переправ; v2/v3/v4 импортируются без перекладки. Существующий importer не является полным геометрическим ROAD-валидатором.
- src/modes/obstacles.ts исключает roadPairs/воду/речные рёбра при создании препятствий. E3 также не прокладывает путь через существующее препятствие и не удаляет его скрыто.
- В текущем UI список selectedHexCrossings только показывает тип; прямой редактор геометрии путей отсутствует. Транзакции документа и E2 busy/revision guards переиспользуются.

## UI и сценарии

### E3-01 Выбор и изменение
Одна существующая кнопка «Редактировать/Готово» в информации. В просмотре — обычное выделение; в Edit путь и переправа получают нажатие и видимый focus. Нажатие выбирает точный normalized segment и Road.id; переправа — точный ключ. При совпадающих legacy-слоях показать перечень объектов в информации с подсветкой каждого, не менять первый найденный молча. Участок подсвечен на карте, соседние свойства не переписываются.

В существующем блоке информации строка «Участок: Дорога» / «Segment: Road» — синий текст с близким пунктирным подчёркиванием; нажать открывает native select «Дорога/Тропа». Переправа аналогично «Мост/Переправа/Брод». Изменение валидного select записывается сразу одной транзакцией. Escape закрывает select без изменения. Нет карандашей, дополнительной панели, локальных Save/Apply/Cancel или предварительного выбора режима «дорога/регион».

«Удалить участок» и «Удалить весь выделенный путь» — явные действия в этом же блоке, не жест случайного нажатия на карте. Второе предварительно подсвечивает ВСЕ segments данного Road.id, включая другие регионы, и перечисляет число затрагиваемых переправ. Это определение «весь путь»; оно не означает всю связанную сеть. Перед разрушительным действием показывается компактное подтверждение с последствиями; отмена подтверждения — no-op. Действие не меняет другие Road.id. Это подтверждение операции внутри приложения, не согласование этапа владельцем.

### E3-02 Создание
В Edit выбранного сухопутного гекса строка «Пути: Начать путь отсюда» / «Paths: Start here». Это действие по конкретному объекту, не отдельная панель инструментов. Далее нажимать соседние сухопутные гексы; видна пунктирная линия-черновик, последний узел и число участков. Тип по умолчанию «Тропа», непосредственно в той же строке меняется на «Дорога» и применяется ко всему новому черновику. Нажатие предпоследнего узла убирает последний шаг; повтор других узлов/замыкание кольца в этом первом срезе отклоняется с объяснением. Прокладка через несколько регионов разрешена; через неизвестные гексы/море/озеро — нет. Можно закончить на существующем гексе границы, открытой к неизвестной территории (ROAD-03), но не записывать сегмент в несуществующий гекс.

Enter или повторное нажатие конечного узла завершает валидный маршрут; общая «Готово» также завершает и выходит. Подсказка при черновике явно сообщает оба способа. Конец и начало должны быть POI/поселением, узлом существующей сети или допустимым открытым выходом. Промежуточные точки могут быть пустыми. Внутреннее касание существующего пути становится окончанием нового пути; не рисовать поверх уже существующего сегмента. Отдельный новый путь можно продолжить от этого узла. Не заменять нажатую последовательность автоматически кратчайшим маршрутом.

Escape отменяет целый черновик, без изменения документа, RNG, counters и redo. Для touch доступно текстовое действие «Сбросить черновик» в подсказке черновика; оно не является локальным Save/Cancel для полей. Pan/zoom/rotate сохраняют черновик и только меняют вид; не добавляют сегменты. Выбор другого объекта/язык/скрытие панели/экспорт сначала пытается завершить валидный черновик; невалидный оставляет выбор/состояние прежним и показывает ошибку. Пока черновик активен, generation/import/reset/Undo/Redo и другие мутации недоступны; сначала завершить или сбросить его. Pending file read/generation/stale callback запрещают начало и commit. Уже открытые E2 поля и notes сначала завершаются своим текущим контрактом; ошибочное имя блокирует начало пути.

### E3-03 Переправы
Новый пересекающий реку участок не может записаться без переправы. Все затронутые реальные river edges перечисляются в информации; при нескольких riverId на одном ребре учитывается каждый ключ. По умолчанию новый ручной переход — мост; пользователь может изменить тип перед завершением пути. Никакой жеребьёвки, изменения geography/names/visual RNG или скрытой генерации остальных переправ.

Ручной выбор bridge/ferry допустим при F1–5; ford только при F1–2. F берётся из max fullness соответствующего river edge по секторам, как в getRiverCrossingFullnessByEdge, с существующим fallback. Вероятности getBridgeChance относятся к генерации, не запрещают осознанный ручной выбор; жёсткий запрет брода F>=3 сохраняется. Это явно описанная ручная матрица, не изменение вероятностей генератора. Height/biome/roadKind не пересчитывают уже выбранный kind. При неоднозначном/отсутствующем live контексте отказаться с объяснением, не подставлять чужой регион.

Добавить переправу отдельно можно только на реальном пересечении существующего сегмента и ребра реки, где запись отсутствует: строка «Переправа: Не задана» открывает выбор. Рисовать мост посреди суши нельзя. Удаление переправы при сохранении пересечения отклоняется: «Этот путь пересекает реку. Измените тип переправы или удалите участок пути». Предложенное удаление участка проходит обычную проверку сети и удаляет зависимые crossings одной операцией. Нет сохраняемого состояния «нет переправы» на действующем пересечении.

## E3-04 Геометрия и сохранность

Нормализованный сегмент — неориентированная пара соседних axial hex. Новые сегменты уникальны по всей карте вне зависимости от Road.id/kind. Соседство без сегмента не является соединением. Новый маршрут не содержит повторов узлов; использует реальную сушу и свободные от obstacles рёбра. Это топологические ограничения; генераторские эстетические предпочтения BFS/near-self не применяются как новые запреты ручного рисования.

ROAD-02 запрещает генератору менять старую карту; явное ручное редактирование старых участков разрешено родительской задачей. После ручной правки последующее расширение сохраняет полученные старые сегменты и переправы. Rivers, регионы, POI/имена, заметки, biome overrides, obstacles и вода буквально неизменны. Разрешённые изменения: выбранные roads/crossings и nextRoadId при создании, общая история и выбор UI.

Удаление/смена типа проверяется на подготовленном результате. Не создавать новых внутренних тупиков без POI/назначения, не закрывать существующий допустимый выход, не разрывать ранее связанную пару обязательных POI/сетевых узлов в затронутом компоненте. Концы у неизвестной территории допустимы. Весь мир не требуется соединять через несуществующие регионы. Старые независимые нарушения импортированной карты не исправляются и не объявляются новыми дефектами; сравнить до/после, отказать при новом/ухудшенном нарушении в затронутом компоненте.

Числовая защита обычного освоенного региона: countAfter >= min(countBefore, getSettledMainRoadLimit(region)); считать сохранённые записи существующим helper, ДОПОЛНИТЕЛЬНО проверять реальную геометрическую связность и назначения. Нельзя раздробить ID ради прохождения минимума. Дикие тропы: существующее число попыток генератора не объявлять гарантированным минимумом. Для аварийного урочища новая числовая квота не назначается (ROAD-AUD-05); топологические проверки и продолжение старых выходов обязательны. Это сохраняет известные нормы без расширения нерешённого правила; изменение норм — отдельное решение владельца.

## E3-05 ID, данные и транзакции

Формат JSON остаётсяv4: существующие roads/crossings достаточны. Новому законченному пути выделить один nextRoadId, regionId = регион стартового гекса; +1 только на успешном commit, проверка safe integer/overflow. Не создавать отдельные IDs каждому сегменту/региону. Редактирование/удаление части сохраняет Road.id,regionId, порядок и литеральные данные незатронутых сегментов. Если остаются несколько геометрических компонентов, это всё ещё контейнер одного Road.id; каждый компонент обязан пройти проверки концов/связности. Пустую запись удалить, счётчик не уменьшать и ID не переиспользовать. No-op не расходует ID и сохраняет redo.

Crossing key сохраняет текущий формат; существующие ключи не переименовывать. Для изменяемой пары сохранять все остальные поля; при удалении сегмента удалить только его зависимые crossings. При добавлении подготовить все ключи/riverEdgeKey до записи. Незатронутые crossings копировать буквально; не запускать глобальный reconcile с fallback RNG. Рендер и SVG/PNG используют записанные kind, без повторного выбора. Визуальный черновик/выделение не входит в экспорт.

Все шаги построения — ephemeral UI до завершения. Проверить revision, существование/идентичность выбранного Road/river, импорт/busy, полную подготовку копии и invariants до первого setter. Одна операция = один snapshot history с roads+crossings+counters и прежним RNG. Ошибка подготовки/валидации оставляет документ, выбор, undo/redo прежними. Undo/Redo возвращает точные данные, не вызывает генератор/жеребьёвку. Старые callbacks после import/reset никогда не применяются к новому объекту с совпавшим ID.

Импортv2/v3/v4 не получает новых глобальных запретов существующих форм и не нормализует дороги; новый E3 документ проходит текущую структурную валидацию. При необходимости ремонта structural validator требуется конкретное воспроизведение, не расширение корпуса по умолчанию. Существующий генератор продолжает из одинаково изменённых копий детерминированно.
