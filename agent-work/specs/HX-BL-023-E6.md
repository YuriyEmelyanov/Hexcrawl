# HX-BL-023 E6 — озёра, море и возвращение суши

Версия **E6-1.0**, 5 ноября 2026. Статус: пригодная спецификация для разработки; UI-v1 — предложение, а не реализация. Родитель: [HX-BL-023](HX-BL-023.md), строка E6. Основание: утверждённый набор редактора от28.10 и [передача аналитическому этапу](../handoffs/2026-11-05-HX-BL-023-E6-analysis.json); прямое текущее поручение владельца «Запускай аналитика вне очереди». Анализ опирается на опубликованный **27b230fc5fc5ac2f998141626fa091e1085d7a47**, PR486. Новое разрешение старта E6 не требуется; выпуск конкретного проверенного SHA разрешается отдельно.

## Цель и границы

Ведущий изменяет берег уже созданной карты: суша→озеро/море, вода→суша, озеро↔море; добавляет/убирает отдельные клетки или выбранный связный водоём. Получает валидную географию, видит последствия для именованных объектов и сохраняет принятую правку одной отменяемой операцией. Основной сценарий develop_existing, дополнительный create_from_scratch, уровень L1. Пример: расширить «Серебряное озеро» на соседний луг, сохранив его имя и описание; если новый берег закроет дорогу, сначала исправить путь существующим E3, затем повторить правку воды.

Входит: зарегистрированные клетки существующих регионов и зарегистрированная вода вне регионов; конечное выделение клеток; топология/ID озёр, возврат владения и биома, источники/устья и F, дороги/переправы/препятствия, POI, имена/теги/заметки, JSON/история/продолжение генерации. Вне: рисование в неизвестной территории, создание нового региона, произвольная передача сухой клетки другому региону/смена высоты (E7), перенос POI/центра/anchor (E8), морские маршруты, новые игры/механики L2/L3, новый генератор, новые пределы производительности и платные сервисы. Операция воды не исправляет автоматически все старые нарушения карты.

## Инвентаризация точной базы

* `src/App.tsx`: `Region.hexes` включает озёрные клетки; вода — разреженный `terrainByHexKey`/runtime `hexTerrainByKey` с `terrainOverride:'lake'|'sea'` и `lakeId`. Море может находиться вне регионов. Отсутствие water override у региональной клетки означает сушу. Морской сущности с именем/ID нет.
* `nextLakeId` уже сохраняется; импорт использует максимум сохранённого floor и максимального живого ID+1. `getLakesForRegions` объединяет уникальные гексы одного ID сквозь регионы. `convertLandlockedSeaComponentsToLakes` классифицирует море, полностью окружённое созданной сушей; `getSolitarySeaHexKeys` выявляет одиночные морские артефакты. Эти генераторные helpers не являются готовой транзакцией ручного редактирования.
* `biomeOverrideByHexKey` допускает запись для любой клетки региона, в том числе скрытую водой; UI её не редактирует под водой. Это пригодная память локального биома; отдельный новый provenance-layer не нужен.
* Реки — физические рёбра/вершины, F/сектора, delta/BR-009; E5 содержит геометрический контекст, полную подготовку зависимостей и сравнение legacy. Дороги — физические сегменты; crossing связан с реальным сегментом и рекой. `riverFeatures` имеет ручные On/Off и отсутствие=Auto. Редактор воды должен использовать ту же физическую геометрию, не отдельную приближённую модель.
* POI суши — `centerHex`/`centralPoiKind`, `pointsOfInterest`/`pointOfInterestKinds`; водные — `waterPoiByHexKey`. Заметки — `gmNotesByHexKey`, имена — `toponyms`, теги — `map.tags` с owner-ссылками. Shared tags не являются новой функцией E6.
* Схема v7 достаточна: все необходимые данные уже представлены. E6 не добавляет поля и **не повышает версию**. При обнаружении невозможности выразить контракт в v7 разработчик сохраняет конкретный пример и возвращает аналитику; не вводит тихий новый формат.

Доменные источники: `docs/river-model.md` RIV-001…018 и уточнения reentry; `docs/road-model.md` ROAD-02/03/05/08/10; `docs/natural-lakes.md`; E3/E5 specs. ROAD-02 защищает старые пути при генерации, не отменяет явно запрошенные ручные команды E3. E6 не меняет эти правила.

## E6-W01. Выделение и жизненный цикл

Общий Edit остаётся единственным режимом. В строке местности выбранного гекса добавить редактируемое значение «Суша / Озеро / Море». У озера/моря в том же информационном блоке доступно «Изменить берег». Выбор нового состояния начинает временный WaterDraft с начальной клеткой и `revision`, `draftId`; изменение ещё не записано. Клетки добавляются/убираются явным кликом/тапом или клавиатурным выбором, на карте видна конечная маска. Один гекс не добавляется дважды. Движение камеры/drag/pinch/zoom/rotation не добавляет клетки и не завершает операцию.

Команда «Весь водоём» добавляет текущую компоненту воды по6 соседям, включая переходы через регионы; море означает только конечные зарегистрированные клетки, не бесконечный океан. Для озера компонента определяется фактической геометрией, а не всем произвольным множеством одинакового legacy-ID. Нет неявного flood-fill суши. Объём/затронутые объекты показываются до завершения; конечное выделение может быть несвязным, результат проверяется покомпонентно.

Enter или общая Done завершают маску и готовят detached candidate. Если нет потерь/слияния/разделения/нового назначения региона и ошибок, безопасная правка коммитится сразу одной операцией. Иначе внутри текущего блока появляется preview; локальное «Подтвердить изменение» разрешено только для последствий, как в E3/E5, и не является дополнительным глобальным Save/Apply. Escape/«Сбросить» уничтожают черновик/preview, не карту. Done не обходит неразрешённый конфликт.

Пока WaterDraft/preview открыт: посторонние writers, generation/reset/import/Undo/Redo, правки имён/тегов/заметок/другие инструменты блокируются на уровне handlers/ref, не только DOM. Перед входом завершить текущую группу заметок с последним введённым символом. Выбор другого объекта/Find/смена языка/закрытие панели пытаются завершить текущую операцию; ошибка оставляет её на месте, доступен явный сброс. Навигация и экспорт доступны. Экспорт не завершает draft и содержит только подтверждённую карту; сообщить это рядом с действием. Выделение не входит в JSON/PNG.

## E6-W02. Владение сушей, биом и метаданные региона

Вода внутри существующего региона **не удаляет** гекс из `Region.hexes`: ID региона/королевства, высота, базовый биом, локальный biome override и порядок существующих клеток сохраняются. Возврат в сушу удаляет water override/lakeId, но оставляет тот же регион и буквальный локальный override; при отсутствии override используется **текущий** биом региона. Нельзя заново выбирать случайный биом или возвращать историческую копию всего региона. Скрытый биом остаётся в JSON и становится видимым после осушения.

Для зарегистрированной морской клетки вне регионов, превращаемой в сушу **или озеро**, в preview обязателен выбор существующего региона по имени. Кандидат — регион, связанный с добавляемой компонентой по стороне после операции; путь связи может идти через другие клетки той же возвращаемой компоненты. Если соприкасаются несколько регионов, выбор не подразумевается; если ни одного — отказ «Сначала создайте соседний регион». Новые клетки компоненты присоединяются к одному выбранному региону; не переносятся клетки чужого региона. Наследуются его биом/высота/освоенность/kingdom membership, локальный override отсутствует. Это ограниченное возвращение водных клеток, не произвольный редактор границ E7. Прямое создание озера вне любого региона запрещено.

Клетки центра и anchor должны остаться сухими; нельзя опустошить регион или разорвать его шестисоседнюю территорию. Их затопление даёт именованный blocker «Здесь центр/опорный гекс региона; измените выделение»; не удаляет центральный POI и не переносит его самовольно. Ограничение остаётся даже при suppressCentralPoi. Внешние имена/цвета/ID/центры/anchors/targetSize/sizeCategory не пересоздаются. `finalSize` равен числу уникальных `Region.hexes` (включая озёра); при присоединении дописать новые клетки каноническим порядком q, затем r. `isCoastal` затронутого региона пересчитать по фактическому контакту его клеток с морем после операции, не по озёрам. Обновить производные границы/candidates по реальной геометрии, сохранив возможность продолжения и защищённые выходы путей. Не трогать сохранённые случайные потоки.

## E6-W03. Классификация воды и озёрная идентичность

Соседство воды/компонент — по общей стороне, контакт в вершине не объединяет водоёмы. Считать по полному набору созданных региональных и зарегистрированных водных клеток, без двойного счёта одного гекса.

Новый/изменённый морской компонент имеет не менее2клеток и хотя бы одну сторону к неизвестной территории за пределами зарегистрированных клеток; конечный полностью окружённый известной сушей водоём классифицируется озером, а не внутренним морем. Одинокий морской гекс недопустим. Озеро имеет ≥1клетки, все принадлежат регионам, единый ID на связную компоненту; не обязано иметь реку. Озеро допустимо у границы неизвестного; это явное озеро, а не обещание выхода в океан. Два соседних по стороне озёрных компонента объединяются; смесь lake/sea в одном непрерывном водном теле не остаётся в финале.

При выборе «Море», замыкающем воду в суше, preview объясняет «Получится замкнутое озеро» и требует явно выбрать озеро либо изменить маску. При соединении озера с морем показать **весь** затронутый компонент и требовать явное преобразование в море, либо изменить маску; нельзя переименовать/превратить остальную воду скрыто. До подтверждения ни один lakeId не исчезает.

* Расширение/сокращение без разделения: сохраняются lakeId, имя RU/EN, tags/revisions/rollCounters и сохранённые данные живого озера; площадь N меняется. Новый компонент без старого ID получает ID от `nextLakeId`; обход новых компонент по минимальному q,r. Не повторно использовать освобождённые ID. При overflow — атомарный отказ.
* Разделение: компонент с минимальным прежним выжившим q,r по умолчанию сохраняет старый ID, **preview позволяет явно выбрать другой**. Он один сохраняет имя и все lake-tags; другие получают новые ID/имена без копирования бросков/тегов. Пользователь видит имена/состав наследника до commit. Не создавать дубликаты авторских тегов.
* Слияние нескольких старых озёр: обязательно выбрать одно сохраняемое озеро по имени. Его ID/имя/теги остаются буквально. Все прочие old-ID исчезают; каждое имя RU/EN и каждый tag с ручными текстами/значениями перечислить как теряемый bundle с отдельным подтверждением удаления. По умолчанию удаления не выбраны, commit недоступен. Нет незаметного выбора минимального ID или повторного reroll. Сохранить все данные можно отменив операцию/изменив маску; автоматическое объединение tag owners/rollCounters не входит в E6.
* Полное удаление озера или перевод в море: показать его имя RU/EN и tags как явно удаляемые; нужны такие же подтверждения. Ссылки owner/toponym/rollCounter исчезнувшего lake удаляются только в этой подтверждённой транзакции. Сохраняемые соседние сущности не перенумеровывать. Морю не создавать фиктивный lakeId/новую toponym-сущность; всеобщие имена E8 отдельно.
* Новые имена — существующий детерминированный `synchronizeToponyms`/hash только для действительно новых lake-entities; прежние живые записи битово сохранить. Не расходовать geography/poi/tag RNG, не запускать генерацию MB-тегов для нового водоёма: водные теги остаются по запросу, как TAGS1.1. Коллизия/невозможность подобрать имя отклоняет весь candidate.

## E6-W04. Реки и числовые ограничения

Сначала построить финальную водную геометрию в clone, затем заново получить физические lake-порты, морские вершины, открытые границы/сектора/eligible markers и проверить всю затронутую сеть **при фиксированных прежних руслах, направлениях и F**. WaterDraft не прокладывает и не удаляет реки, не запускает solver произвольных F/авторегион/генератор. Если нужна такая правка, точная ошибка направляет в существующий E5, после явного сброса воды; это безопасная зависимость, не ожидание решения владельца.

RIV-007: сухой закрытый исток только F1. RIV-008: озеро-исток N≥F−1. RIV-009: один вход/выход |Fout−Fin|≤N. RIV-010: бессточное N≥суммы входов. RIV-018: многопортовое |ΣFin−ΣFout|≤N, N учитывается единожды для всего lakeId, каждое F1…5. Море принимает F1…5 и не является истоком (RIV-012). Настоящая неизвестная граница, а не наличие старого candidate, определяет открытый конец (RIV-017). Покрыть озёра сквозь регионы/обходящие берега/скрытые внутренние штрихи; внутреннее ребро не является дополнительным портом.

Изменившаяся форма озера запускает reentry-проверку всех взаимодействующих рек по окончательной геометрии. Проверить направленные циклы с озёрными связями, новые береговые ограничения и delta-parent/BR-009. Нельзя прятать новый дефект за старым общим флагом. Для legacy сравнивать фактические incident edges/F/направления/owner/площадь и геометрию взаимодействия как E5; неизменённый удалённый дефект не блокирует корректную правку. Переименование ID само по себе не «новая геометрия», изменение формы/сумм — новая проверка. Импорт не чинит автоматически старые нарушения.

Невалидное устье после удаления воды, слишком малое озеро, морской исток, новый цикл/reentry/несогласованная delta = blocker с именем реки, координатой, текущими и требуемыми N/F и доступным действием. Preview не предлагает «игнорировать». Готовые valid river vertices/controlPoints/ID/имена/теги не меняются; только производные сектора/reasons/видимость пересчитываются согласованно. Не выдавать успешную чистую числовую проверку за полную географическую подготовку.

## E6-W05. Пути, переправы, препятствия и ручные маркеры

Вода не переносит/обрезает дороги и тропы. После candidate все существующие физические сегменты и их действительные выходы должны оставаться допустимыми по ROAD/E3: нет сегмента через водную клетку, нового тупика или закрытого водой выхода без продолжения/назначения. Для конфликта показать имя/номер пути и затронутые клетки; предложить сбросить маску и использовать E3. Изменение берега не превращает сухопутный маршрут в морской ferry. Импортированный старый дефект сравнивать по условиям/физическому сегменту, не требовать глобального аудита.

Переправы пересчитать по тем же реальным river/road intersections; прежний kind для сохранившегося пересечения сохранить. Если утрачивается crossing, показать его тип/путь/реку, запросить явное подтверждение удаления. Новый реальный crossing не может появиться с молча назначенным видом; показать тот же выбор bridge/ford/ferry и ограничения F, что E3/E5. Весь список проверяется совместно. Не удалять путь ради того, чтобы пропустить crossing.

Препятствие, ставшее недопустимым из-за воды, — явный пункт удаления по ID/типу/ребру либо отмена; перемещения E4 не делать автоматически. Ручной rapid/waterfall On, ставший недопустимым у воды/истока/пересечения, требует **Off или Auto**, как E5; скрытый On не сохранять. Допустимый Off сохранять, Auto остаётся отсутствием записи. Невалидную ссылку override удалять только как явно показанную потерю. Auto markers пересчитываются stable hash без RNG. Валидаторы финального crossing/feature списка запускаются после всех ответов, а не по одному промежуточному ответу.

## E6-W06. POI, имена, теги и заметки

Заметка привязана к существующей координате: при затоплении/осушении **всегда сохраняется буквально**, включая пробелы/языки/HTML-like текст. Не перемещать и не превращать её в описание водоёма. Любая зарегистрированная внешняя морская клетка при осушении присоединяется к региону, а не исчезает из карты, поэтому её заметка остаётся валидной. Пустое/неизменное поле не заменять шаблоном.

Совместимый водный POI при lake↔sea сохраняет тип/координату без броска, если тип разрешён целевым текущим profile pool; если несовместим — тот же явный loss item, не «ближайший» тип. Обычный наземный POI при затоплении и водный при осушении либо явно удаляется после показа, либо блокирует commit до изменения маски. Центральный POI/center/anchor нельзя удалить через E6 (W02). Автопереноса и автоматического water↔land преобразования POI нет; E8 отдельно. В Mythic не добавлять несуществующий новый pool водных POI, однако ранее допустимые импортированные записи не стирать при открытии.

В loss item перечислить тип/координату и все прикреплённые settlement-name RU/EN, POI-tags, независимые dice/text overrides и counters. Подтверждение относится к конкретному bundle и revision, по умолчанию unchecked. После подтверждённого удаления очистить только ссылки исчезнувшего POI, без изменения tags других POI того же региона. Для сохранившегося POI owner-key и содержимое остаются прежними. Смена владеющего региона запрещена для уже региональной клетки, поэтому не нужен выдуманный transfer settlement-key. Region-tags, river-tags, мифы/соседние landmarks и прочее содержимое не reroll. Проверить лимиты существующих validators (включая tag capacity) до любого setter; отказ не частично удаляет содержимое.

## E6-W07. Атомарность, ошибки и продолжение

Одна команда подготовки получает снимок документа, ожидаемую revision/draft identity, точный набор клеток, целевую воду/сушу, назначения регионов и конкретные ответы preview. Возвращает no-op, полный candidate+dependencies, expected error либо prepared transaction. Все clone/allocation/имена/проверки/копии before-after до записи; один commit добавляет одну запись в существующую100-операционную историю и очищает Redo. No-op проверяется до попытки нормализовать старые дефекты и оставляет Redo. Undo/Redo возвращают буквально map/RNG/ID-floor/имена/все tags+counters/заметки/kingdoms/obstacles/riverFeatures; метка `savedAt` при экспорте не часть географического равенства.

Commit повторно проверяет live revision, draft identity, клетки/owners/все зависимости/ответы, не доверяет старому preview. stale, busy, double Enter, удалённая клетка, некорректная координата, overflow, невозможная топология/вместимость, исключение подготовки/копирования — ни одного live setter/изменения стеков/счётчика/RNG. Stale закрывает неактуальный preview с сообщением и возможностью заново выбрать клетки; не переигрывает ответы на другую карту. Busy показывает временную причину. Ожидаемые ошибки локализованы RU/EN, доступны через aria-describedby/live region и фокус; неожиданные ошибки сохраняются технически и дают «Карта не изменена» без ложного успешного статуса.

После commit обычная генерация продолжает **подтверждённую** новую географию; существующие пути/имена защищены прежними правилами. Не сохранять старый lakeId/кеш контура после его удаления. Удаление последнего региона/restore generation checkpoint не равнозначно обычному Undo: действующее предупреждение о потере ручных правок перечисляет также изменённую воду/прикреплённые данные. Cancel предупреждения ничего не меняет; согласованное восстановление возвращает полный checkpoint, не смесь старой воды с новыми тегами. Испытать через реальные обработчики, не только helper.

## E6-W08. Файлы, legacy и отображение

Экспорт v7, прежние поддержанныеv2…v6 мигрируются действующим путём до v7 без бросков и автоматической переклассификации/переименования. В7 сохраняет floor nextLakeId при удалении наибольшего ID; следующее ручное/генерируемое озеро берёт ID≥floor. Не вводить новый retroactive structural отказ для ранее допустимого legacy только из-за новых правил создания воды. Для новой операции строже проверять изменённые компоненты; legacy-disconnected одинаковый lakeId не распространять в другие части карты: если операция затрагивает такую неоднозначную идентичность, отказ с конкретными компонентами до нормализации отдельной задачей. Не «чинить» её новым ID при чтении.

Round-trip экспорт→импорт сохраняет полный документ, в том числе скрытый biome override и note у внешнего sea. Будущая версия/ошибочный импорт атомарно отклоняются как сейчас. Никаких черновиков/выделения/ответов preview в JSON. Natural Color берег строится от нового lakeId+клеток+seed и правильных river mouths; Tiles/Emoji показывают целые водные клетки, как существующий контракт. Кеш инвалидируется при смене формы/устья, не заставляет менять соседние контуры. PNG содержит подтверждённую воду/видимые POI/markers в выбранном стиле и повороте, без draft/подсветки/служебного текста. Полноту SVG-экспорта этим срезом не объявлять.
