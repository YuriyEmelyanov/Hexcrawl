# HX-BL-073 · Разделение несвязных регионов при открытии карты Classic

Черновик D2 · 24 ноября 2026 года

## Поведение при открытии

Прямое решение владельца: «Загружать. Присваивать тогда, допустим, вместо 7 7.1 и 7.2, рассматривать как отдельные регионы не сбивая общую номерацию».

При открытии JSON в Classic каждый несвязный регион разделяется на группы гексов, соединённых общими рёбрами внутри исходного региона. Каждый гекс остаётся на исходной координате. Водный гекс учитывается, если входит в состав региона. Путь через соседний регион связности не даёт.

Карта открывается с самостоятельным регионом для каждой части. Если регион №7 распался на две части, в интерфейсе они получают номера 7.1 и 7.2. Для трёх частей получаются 7.1, 7.2 и 7.3. Соседние регионы сохраняют номера. Очередная обычная генерация получает следующий номер по прежним правилам, как если бы исходный №7 занимал одно место в общей нумерации. Например, если следующим был №9, он и создаётся.

Номер с точкой — отображаемая метка. Внутренний идентификатор каждой части должен быть уникальным и совместимым со ссылками карты. После сохранения и повторного открытия метки, самостоятельность частей и нумерация воспроизводятся. Номер части присваивается детерминированно. Порядок частей нужно уточнить на интервью.

Связи, привязанные к гексам, передаются части, где расположены эти гексы. Маршруты и объекты с геометрией в нескольких частях должны сохранить пространственные связи. На интервью уточнить, как назначать первичный центр и якорь каждой части и как переносить общие свойства исходного региона, например имя, в остальные части. Обычные проверки структуры JSON, включая дублирование владельца гекса, продолжают действовать.

## Приёмка

| Сценарий | Ожидаемый результат |
|---|---|
| Открыть исходную карту Classic с seed 42. | Связные регионы открываются с теми же гексами и номерами. |
| Добавить изолированный девятый гекс 500/500 к региону из восьми гексов. | JSON открывается. Исходный регион представлен двумя самостоятельными регионами с суффиксами .1 и .2. Восемь гексов остаются вместе, девятый образует одногексовый регион. Другие регионы сохраняют номера. |
| Открыть карту с тремя несвязными частями одного региона и регионом, где соединение проходит по входящему в него водному гексу. | Первая область даёт три региона с суффиксами .1, .2 и .3. Вторая открывается одним регионом. |
| Сохранить исправленную карту, открыть её и создать ещё один регион. | Номера и границы частей совпадают до и после открытия. Новый регион получает прежний следующий целый номер. |
| Выбрать гекс каждой части и проверить карту с привязанными объектами. | Открывается карточка соответствующего региона. Объекты остаются на исходных координатах, ссылки действительны. |
| Открыть файл с гексом, записанным в два региона. | Срабатывает существующая проверка дублирования владельца. |

## Дополнение · Удаление последнего региона

При удалении последнего региона на карте 5–6 миль исчезновение малого озера на одномильной карте не должно вызывать отдельного предупреждения, добавлять строку про малые озёра в общий диалог или само по себе открывать диалог. Малые озёра, потерявшие опору после удаления региона, удаляются вместе с регионом. Остальные малые озёра сохраняются. Undo восстанавливает регион и его озёра, Redo повторяет удаление. Подтверждения, вызванные другими правками, работают по прежним правилам.

Приёмка. В Classic создать два региона. На одномильной карте разместить малое озеро в последнем регионе и ещё одно в первом. Возвратиться на 5–6 миль и нажать «Удалить последний регион». Проверить отсутствие предупреждения о малом озере, затем в масштабе 1 миля сверить оба озера после удаления, Undo и Redo. Если на принятой сборке сценарий уже проходит, зафиксировать результат без правки кода для этого пункта.
