## 2. Границы

Входят: раскрытие материала существующего `mb.myth` выбранного POI; упорядоченные сцены-знамения; исходные блоки ролей с общим вступлением, если оно есть; справочные характеристики внутри текстовых блоков; происхождение/язык; недоступный материал и ошибки; работа в RU/EN, Mythic и Classic с существующим MB-тегом; клавиатура и узкая панель.

Не входят: новые кубы или броски внутри карточки, особые таблицы мифа, автоматическое раскрытие/продвижение знамений, время/сезоны/Слава, боевые/болезненные/предметные эффекты, новые сущности NPC, статистическая модель персонажей, изменение географии/квот, новые заметки/редактор корпуса, внешние загрузчики и платные API. Провидец остаётся только именем/кубами. У руин не создаётся связи с активным мифом. Карточка не появляется у жилища/руин/святилища только из-за происхождения их подсказки из той же страницы.

## 3. Привязка к фактическому состоянию карты

На базе тип `TagInstance` определён в src/tags/engine.ts: definitionId, definitionVersion, owner, resolver, revision, sides, values, entryIds, texts и отдельные overrides. Не вводить вымышленное поле resolvedEntryId/resultSnapshot из старого эскиза; фактический snapshot — texts/entryIds.

Условия известного материала:

1. Текущий выбранный объект имеет фактический POI-тип `myth` и действующего владельца `{kind:'poi',regionId,hexKey}`. Использовать тот же owner, которым App.renderTags отображает строку. Не выбирать первый тег региона, ближайший миф или запись по названию.
2. У этого owner есть `definitionId='mb.myth'`, известная definitionVersion1, resolver product, sides `[6,12]`, values `[[g],[e]]`, целые g=1…6, e=1…12 и единственный entryId `mb.myth:${(g-1)*12+(e-1)}`. Строго сверить согласованность; `[1,12]` → index11, `[2,1]` → index12. Это произведение индексов, не сумма.
3. Справочник материала содержит запись ровно этого entryId для совместимых definitionVersion/edition/materialVersion. Название и отображаемый язык не являются ключом.

Определить чистую функцию выбора с явными результатами `absent`, `ready`, `unavailable(reason)` или `error`. Она не вызывает rollTag/editTag/reconcileTags/commitManualMap и не изменяет входы. Неверная или неизвестная версия/несогласованная пара/ID дают unavailable; не вычислять альтернативный миф «на всякий случай». Ошибка материала не отменяет уже принятую карту и не меняет её импортную валидацию.

`overrides` меняют только авторский текст строки. При переименовании мифа карточка остаётся материалом исходного entryId. Если override присутствует для показываемого имени, внутри раскрытого материала один компактный контекст: «Материал исходного мифа: <texts[0] с обычным fallback>». Не подменять справочник другим мифом по похожему имени и не стирать override.

Нет тега → нет отдельного управляющего элемента карточки; существующий «Миф +» продолжает прежнее поведение. Не-миф POI → карточки нет, даже если сохранён посторонний старый mb.myth snapshot. Неизвестный/несовместимый snapshot сохраняется и отображается общим механизмом тегов; карточка сообщает недоступность без активных бросков/починки. В Classic материал существующего валидного MB-тега доступен внутри существующей группы Mythic Bastionland; открытие группы ничего не генерирует. Возврат в Mythic сохраняет данные.

## 4. Справочник и данные

Материал не помещается в TagInstance.texts с лимитом256 символов и не дробится на дополнительные теги. Нужен отдельный статический справочник, не состояние карты. Предлагаемая семантика записи (имена TS типов может уточнить программист):

- definitionId, definitionVersion, entryId; materialVersion; sourceEdition, sourcePage;
- локализованное содержание: omens[] как упорядоченные `{id, ordinal, text}`, rolePreamble? и roles[] как `{id,title,text}`;
- references[] с типом resolved/unresolved и библиографическим описанием. Нет автоматического перехода к другой сущности или выполнения ссылки.

Идентичность блоков локальна записи/версии, уникальна и стабильна. Порядок источника сохраняется, ordinal положителен и уникален. У ролей сохранять исходные групповые блоки: «группа из нескольких участников» не превращается в несколько NPC. Общее вступление относится ко всей коллекции ролей. Характеристики — escaped plain text, без кнопок бросков/урона.

Шесть знамений/три роли наблюдались только в трёх образцах и не становятся глобальными ограничениями схемы. Массивы переменной длины. Технические защитные пределы: максимум128 блоков на коллекцию, строка блока до16384 Unicode code points, суммарно до262144 на запись; это предел памяти/защиты, не утверждение о книге. При превышении не обрезать: запись считается ошибочной/недоступной, карта сохраняется. Дубликаты ключа записи, ordinal/id, неверные типы, пустые обязательные строки, недопустимая страница — ошибки справочника. На уровне реестра ошибочная запись не подменяет соседнюю; отказ изолирован по entryId. Частичное отсутствие секции явно показывается только по проверенным данным; иначе unavailable, а не фиктивное «в этом мифе нет ролей».

Только текст: React escaping/textContent, без dangerouslySetInnerHTML/Markdown с исполняемым HTML/URL схемами. Нет выполнения строк, импортируемого JS или сетевого обращения к книге. Bundle может быть ленивым модулем; повторные открытия переиспользуют его, но успех загрузки сам по себе не доказывает валидность записи.

Совместимость задаётся явным manifest: `(mb.myth, definitionVersion1, sourceEdition)` → один опубликованный materialVersion1. Опубликованное соответствие и содержимое этой версии неизменяемы; дополнение ещё не публиковавшегося корпуса допустимо до приёмки. Будущая замена уже опубликованных текстов требует отдельного версионного контракта; не выбирать «последнюю версию» по сетевому времени и не переименовывать источники молча. Старый сохранённый тег не получает другое смысловое содержимое из-за обновления bundle.

Язык UI RU/EN переключается независимо. Перевод материала брать только из того же entryId/версии. Нет EN материала → показать полный RU блок с единственной подписью «Русский источник / Russian source»; не переводить автоматически и не выдавать RU за проверенный EN. Это допустимый начальный вариант при честном обозначении; полный английский корпус не предоставлен/не сверялся. Не смешивать роли одного entryId с EN-текстом другого. SourcePage — маленькая библиографическая подпись внутри раскрытого материала, без лишней строки технических ID в основной панели.

### Готовность корпуса и публичная граница

Для первого полного пользовательского выпуска нужны72 уникальных ID `mb.myth:0`…`:71`, пары и страницы из готового каталога v1, все применимые знамения/роли, provenance и отдельный ledger проверки каждого текста/неоднозначности. Проверить не только количество: порядок, групповые блоки/вступления, отсутствие скрытого обрезания и подмены соседних страниц. Переписывать существующие72имени/432ориентира/72имени Провидцев не нужно. Ссылки, не разрешённые исходником, остаются явно unresolved; для справочного отображения не требуется изобретать их исполнение.

Выполненная выборка29/101/171 подтверждает только структурные риски. В текущем ограниченном этапе полного извлечения/валидации72страниц нет. Разработчик оболочки использует специально вымышленные, маркированные test-only данные; они не попадают в production bundle/default registry. Не добавлять в публичные evidence raw-тексты/страницы/восстановленный корпус. В отсутствии совместимой записи production-путь показывает unavailable; это проверяемое безопасное поведение, но не приёмка полноценного наполнения.

Предложение MYTH-CARD-UI2: agent-work/ui/HX-BL-041-MYTH-CARD-UI2/preview.html. Это уточнение уже показанного UI1, а не согласованный или реализованный интерфейс. Ниже существующей строки мифа — компактная текстовая кнопка «Материал мифа / Myth material» со стрелкой и aria-expanded/aria-controls. По умолчанию закрыта. При раскрытии — секции «Знамения / Omens», «Роли / Roles», раскрываемые строки сцен/ролей; все сцены изначально закрыты. Для наглядности на макете открыта первая сцена — это только показ содержимого. Роли и общий пролог не смешивать; заголовок роли не терять при длинном тексте. Открытость нескольких блоков допустима, автоматически прокручивать карту/панель к ним нельзя. Изображение карты/схема в макете не добавляется в продукт.

Одна существующая вертикальная прокрутка панели, без вложенной прокрутки каждого абзаца/модального окна/новой колонки. На320/390px длинные слова переносятся, карточка не выходит за viewport. По клавиатуре Tab → кнопка, Enter/Space раскрывает; фокус остаётся на кнопке, скрытые блоки не получают tab-stop. Использовать реальные button с доступным именем, focus-visible и достаточной эффективной областью нажатия; визуальный размер текста/кубов не увеличивать. При потере целевого объекта фокус перемещается в существующий заголовок информации, не в body/старую удалённую сцену. Нет новой анимации; reduced-motion не нарушается.

Открытие/закрытие не вызывает историю, RNG, сохранение, регенерацию, смену выбранного гекса или автоисправление snapshot. Авторские заметки остаются отдельным существующим блоком без переноса/новых полей. В режиме редактирования карточка тоже только справочная; она не становится редактором источника.

**Защита активного текстового черновика обязательна.** На базе TagRow хранит editing/draft локально и commit на blur, поэтому простого «карточка read-only» недостаточно. Пока открыт незавершённый редактируемый текст карты/тега, кнопки карточки нативно disabled, существующее поле остаётся в фокусе; попытка мышью не должна вызывать blur→commit. Разработчик может передать состояние редактирования из TagRow/App через узкий callback, не меняя семантику onBlur/Enter/Escape самого редактора. По завершении или отмене обычным существующим способом кнопки снова доступны. Пользовательский Tab, который отдельно завершил редактор по прежнему контракту, отличается от принятия команды карточки; не приписывать старое onBlur карточке. Не переносить неопубликованное исправление no-op из NATURE2 как часть этой задачи.

При иных активных черновиках/занятости (river/road/water/region/POI/obstacle, import, generation) не давать новым кнопкам инициировать переход/commit/cancel или отбирать фокус инструмента: новое раскрытие/смена раскрытия disabled, уже видимый текст можно читать. Текст всегда соответствует принятому selected owner; незавершённый candidate не является источником. Повторное разрешение кнопок после завершения операции не выполняет отложенное нажатие.

## 6. Переходы и отсутствие сохранений UI

Состояние раскрытия transient. Ключ представления включает ownerKey, definitionId/version, instance.revision, entryId, materialVersion и текущий язык. При смене любого ключа сбросить раскрытие и старую ошибку; после выбора/Undo/Redo пользователь раскрывает актуальный материал заново. Это консервативно закрывает карточку и при авторской правке имени; история карты не меняется. Обновление материалов и заголовка синхронно привязано к актуальному ключу: не показывать предыдущий текст даже на кадр при новой паре.

Если загрузка модуля асинхронна, применять результат только для всё ещё текущего ключа/request token. A→B→A, удаление/перенос owner, импорт и смена языка не разрешают устаревшему callback раскрыть или заполнить другую карточку. Уходящий запрос не пишет карту или UI другого объекта. Успешное открытие может показать короткое локализованное состояние загрузки, но не заменяет строку имени/кубов.

Карточка не добавляет новых map fields, не меняет TagState schemaVersion1, definitionVersion существующих тегов или JSON v9. JSON экспортируется как прежде; UI-open flags/справочный корпус в сохранение не попадают. JSON round-trip после чтения не содержит дополнительных полей и не меняет теги, counters, notes, имена морей, revision документа/undo/redo. Отсутствующий внешний в bundle материал не является ошибкой импорта карты. Будущий/неизвестный map format по-прежнему отвергает существующий импорт, данная функция не вводит обход.

PNG/карта печати используют прежний map-only путь, не панель с текстами. Справочный материал не раскрывается на карте/в player export через эту задачу. Нет новой отдельной карты игроков и нет заявления полной защиты всей будущей системы секретов.

## 7. Состояния ошибок

- Нет тега/не тот POI: карточки нет; нет скрытого создания тега.
- Неизвестная версия/несогласованная идентичность/неполный совместимый корпус: компактно «Материал этого мифа пока недоступен / Material for this myth is not available». Не подставлять соседний/первый миф.
- Ошибка структуры/загрузки: «Не удалось показать материал мифа / Could not show myth material», локально role=status; карта, черновик, counters и redo сохраняются. Никакого raw stack/текстов справочника в UI/телеметрии.
- Нет нужного перевода: RU fallback того же материала с одной языковой подписью.
- Двойное раскрытие, закрытие, отменённый/устаревший запрос: только конечное состояние UI; не добавлять debounce/замки мутаций в генератор.

## 9. Стратегия проверок и передача

Перед постоянным новым тестом указать защищаемый MC1-риск, найти существующее покрытие и выбрать расширение существующего test/tags.test.mjs и test/browser/tags.smoke.mjs. Пограничная привязка/неизменность документа и настоящий blur/draft — разные полезные уровни; не копировать полный RNG/историю/все source строки в новый runner. Нужен минимальный набор, чувствительный к неправильному entryId, побочному commit и stale callback; случайные fixtures и count ради роста не требуются. Исходную таблицу и реальный полный корпус не помещать в публичные тесты без разрешения.

Обязательны Node24 `npm run check`, сборка и относящийся к карточке реальный браузерный сценарий после неё; предусмотренный проектом общий browser прогон не отменён. Генерацию менять не требуется. Если выбранная реализация затрагивает её, нужны связанные доменные требования и обязательные дополнительные проверки AGENTS, без расширения поведения ради теста. В evidence — точные base/head/tree SHA, независимые suites и executed/passed/skipped; test_change_summary logical cases с источником diff, а не строки или число запусков. Не заявлять полный продукт доказанным конечным набором.

Передача разработчика: ветка/PR или local-only причина, exact SHA, MC1→evidence, готовность справочника отдельно, UI actual до/после, known limits, данные provenance/permissions, минимальный test diff, score evidence. Один активный programmer task. Проверяющий — отдельный свежий контекст/агент, если доступен; сверяет реальный SHA, necessity тестов, источник данных и достаточность частичного/full acceptance. Отсутствие ответа на UI2 не препятствует разработке; публикация любого конкретного пакета отдельно.
