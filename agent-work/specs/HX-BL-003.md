## Цель и границы
Выяснить, где мастер ждёт при расширении заполненной карты, и устранить одно подтверждённое узкое место без изменения результата генерации, качества изображения и сохранности данных. При отсутствии подтверждённой проблемы допустим отрицательный результат.
Основной сценарий Mythic + Цвет; classic + Эмоджи — контроль. Измерять реальное добавление через штатные UI handlers, последующую отрисовку и zoom/pan раздельно, по числу уникальных заполненных гексов N, а не числу королевств.
Один фиксированный профиль, одно узкое место, один продуктовый PR. Допустимы узкие изменения вычисления/кэширования/планирования представления, если результат и порядок RNG неизменны. Новые редакторы, игровые правила, форматы/миграции, широкое разделение App, переписывание географических алгоритмов, сторонние платные средства и реальный Android вне пакета. Если исправление требует этого — остановка с причиной, без расширения.

## Предварительно фиксируемый протокол P1
Это внутренние критерии сравнения пакета, не SLA продукта, не нормативы G4.
До получения baseline timing разработчик коммитит manifest и harness в отдельной рабочей ветке. Manifest содержит точный baseline SHA, lock SHA, Node24 (полный номер), Playwright1.62.1 и фактический Chromium из него (полный номер/путь), OS/CPU/RAM/vCPU, runner ID, параметры, список файлов с SHA256, кандидаты и порядок действий. Browser отсутствует — использовать доступный CI с его явной средой; не подменять замер выдуманным. Если среда меняется, обе серии повторяются парой, прежние результаты сохраняются.
Среда: один Linux runner/выделенный процесс, headless Chromium, viewport1500x1000, DPR1, scale1.5, без ротации/CPU throttling, RU. Аналитика блокируется одинаково. Ассеты/шрифты дожидаются завершения; ошибки загрузки записываются. Никакой параллельной нагрузки от тестов или другой версии. Метрики сравниваются только в одинаковой среде и сборках production; профилирующая инструментированная сборка отдельно, её цифры не смешиваются с основной серией.

### Корпус до замеров
9 checkpoints: Mythic seeds0 и123456789 × ориентиры400/1200/2400; classic seed1 × те же ориентиры. Генерация исходников только baseline через UI от пустой карты; defaults baseline фиксируются в manifest. Для classic явно locality/mainland, остальные значения записать; Mythic defaults без скрытой смены настроек.
Порядок кандидатов: числовая сортировка q, затем r. На каждом шаге первый доступный; при штатном отказе следующий ещё не испробованный в том же состоянии. Не более100 попыток на seed/mode и180с на действие. Checkpoint — первое успешное состояние, достигшее N>=ориентира; N может превысить ориентир на один штатный шаг. Сохраняются реальный N, шаги, параметры и composition: распределение биомов/воды, числа рек/дорог/POI/регионов/королевств и игровые данные. Не клонировать лесные клетки для достижения N.
Для checkpoint заранее выбрать первый кандидат этой сортировки, сохранить anchor и входной JSON/streams. Следующее действие измеряется даже при отказе; запрещено отбирать только быстрые/успешные seeds. Сохранить все отказы и недостигнутые размеры. Если хотя бы один размер недостижим в пределах — остановить расширение этого seed, сохранить частичный корпус и явное ограничение; не заменять seed/размер постфактум. Достаточный минимум для оптимизации: два разных достигнутых размера основного режима на обоих seeds и минимум один classic checkpoint. Иначе blocked_insufficient_corpus, без продуктовой оптимизации.
JSON files, SHA256, baseline outputs и manifest создаются до baseline timing. Их подготовка — часть разрешённой технической реализации, аналитик в этом запуске не выдаёт ещё не созданные файлы за evidence.

### Одна серия для каждого checkpoint
Один cold run в новом browser context с пустым HTTP cache; импорт не включать в latency расширения, но измерить отдельно. Cold означает холодный browser/cache, а не гарантированно холодный OS cache.
Один явно помеченный прогрев; затем5 warm runs, каждый с повторным импортом исходного JSON и восстановлением тех же UI/options. Ни один измеряемый не удалять. В before/after попарно чередовать AB/BA на одном runner; исходный корпус неизменен. Сохранять порядок, timestamps, сырые события и оба SHA.
Для каждого run:
1. Импорт; дождаться полной карты и assets/fonts; зафиксировать N и hash полного документа.
2. Выполнить ровно одно add/expansion выбранного anchor реальным событием.
3. Отдельно t0 handler start, t1 завершение вычисления/подготовки результата, t2 commit подробного artwork, t3 два requestAnimationFrame после него. generation=t1-t0, render=t3-t1, end-to-end=t3-t0. Для async Mythic generation включает ожидание ticks. Если базовый/подробный этапы различны — оба отметить. DOM disabled сам по себе не доказательство конца вычисления. Узкая одинаковая performance.mark инструментализация допустима на обоих SHA; проверить ненаблюдаемое влияние и убрать/отключить в обычном runtime.
4. Зафиксировать outcome success/expected_rejection/exhausted/error/timeout, Nbefore/Nafter/deltaN, RNG, diagnostics и полный выходной JSON. Для отказа t1/t3 соответственно rollback/восстановление представления; не выдавать его за успешную генерацию.
5. На исходном checkpoint независимо от исхода расширения: восстановить фиксированную позицию scroll(500,300), подождать700ms;24 wheel событий deltaY -12/+12 (12 каждого), затем24 drag шагов4px/2px через настоящие listeners, один шаг на rAF. Перед drag пауза220ms. Записать все интервалы frame, долю>50ms и p95 отдельно zoom/pan; buffer state и heap — диагностика. Выбор4 видимых гексов измерить отдельно, не смешивать с drag.
Timeout180s обрабатывается снаружи browser callback, чтобы зависший main thread не скрыл событие. Timeout не число180000 в успешном latency: отдельно count/rate, censored lower bound и список. JS errors/dialogs/отказы не отбрасываются.
По каждой группе seed/N/mode — median,min,max и nearest-rank p95 (при5 warm это max, назвать малую выборку); cold отдельно. Не объединять всеN в один «средний FPS». Отдельно success rate и число запусков. Profiling trace/CDP с long tasks для одного медленного основного checkpoint и контрольного малого; не весь корпус с дорогим trace.

## Выбор одного узкого места и правило остановки
До baseline замера фиксируется P1 выше; после него, до изменения продукта, коммитится diagnosis.json: затронутый этап, evidence trace, воспроизводимые шаги, один целевой metric и checkpoint, гипотеза и узкая правка.
Подтверждение: на обоих Mythic seeds одного размера задержка end-to-end median>=500ms либо zoom/pan p95>=50ms; trace показывает один повторяющийся участок с долей>=20% выбранного этапа на3/5 warm действий. Если навигационные frame samples показывают паузы, привязать trace к тем же движениям. Это порог выбора работы, не утверждение, что продукт обязан быть быстрее универсального лимита.
При отсутствии такого основания сохранить negative_result, исходные данные и закончить без оптимизации. Не менять порог/seed/корпус для поиска победы. Если причина не локализована за один профиль и одну trace-пару — inconclusive, без бессрочного исследования.
Успех узкой оптимизации: на обоих seeds целевого размера median выбранного generation/render/end-to-end metric снижается >=20% и >=50ms; для zoom/pan p95 >=20% и >=10ms. Не менее4/5 paired runs улучшаются; показать все ratios и разброс. На каждой остальной группе warm median e2e и navigation p95 не ухудшается одновременно более10% и50ms (для frame10ms); cold e2e не ухудшается одновременно >20% и100ms. Нет новых ошибок/timeout/ухудшения success rate. Вариативность не позволяет вывод — inconclusive, не «ускорено». Одно исправление не достигло условия — сохранить результат и вернуть проверяющему как непрошедший, не брать второе узкое место.

## Данные, визуал и риски
Полное семантическое равенство baseline/candidate JSON на каждом исходнике и действии: все поля документа, generation streams, география, ID/references, реки/дороги/crossings, вода/POI, имена и UI. Сортировать только ключи объектов; порядок массивов и числовые значения сохранять. Любые известные нестабильные presentation поля перечислить и обосновать до сравнения, не игнорировать карты/Map/Set. Для внутренних snapshots использовать native structuredClone/deep comparison либо явную tagged сериализацию Map/Set; JSON.stringify(Map) не evidence.
Для каждого успешного расширения undo возвращает полный предшествующий документ, redo — полный последующий; повтор после undo и продолжение после export/import совпадают. История сессии не обязана экспортироваться в JSON. Штатные отказы сохраняют предыдущий документ/RNG/историю; повторные/stale callbacks не исполняют уже потреблённое действие (регрессии R1–R5 HX-BL-030).
Для9 checkpoint и успешных outputs сверить полный vector SVG и full-map PNG после settle и загрузки assets: декодированные пиксели, не только байты файла; идентичные размеры/пиксели. Для navigation существующие buffer tolerances из large-navigation suite сохраняются без ослабления, обычный SVG после остановки возвращается; ротация/смена режима инвалидируют cache. Если PNG слишком велик для среды — explicit blocked, без утверждения полной визуальной приёмки.
Не вводить unbounded cache или фоновые tasks, способные записать результат поверх новой карты. Ключи cache зависят от всех влияющих данных, память очищается/ограничена; import/reset/undo/redo/regenerate проверяются отдельно при cache/async правке.

## Проверяемая приёмка
AC01: manifest P1 и input corpus имеют commit до baseline timing, полный протокол/размеры/ошибки; минимум корпуса соблюдён либо явный blocked.
AC02: реальные handlers, production streams, раздельные метрики и сырые результаты всех исходов;10минутный workflow timeout не маскирует180s per-action timeout (серии разбивать на jobs, одинаковая среда пары).
AC03: diagnosis ровно одного подтверждённого участка до продуктовой правки; иначе negative/inconclusive отчёт с остановкой.
AC04: парное сравнение соответствует порогам выше, без подбора удачных запусков; отрицательный вывод не называется улучшением.
AC05: полный JSON/RNG, rollback/undo/redo/continuation и R1–R5 сохранены; ошибки не скрыты.
AC06: SVG/PNG и artwork/navigation соответствуют правилам выше, без деградации качества.
AC07: на конечном SHA Node24 npm run check, npm run test:browser и npm run test:browser:rng; соответствующие профильные invariants, если затронуты. Exact SHA, команды, версии, exit codes и полные логи. Локальная недоступность браузера явно отделена от CI evidence на том же дереве.
AC08: независимый reviewer перепроверяет конкретный SHA, воспроизводит целевой paired профиль и safety сценарии; score_assessment и ограничения обязательны. При negative_result достаточно independently verified отчёта/harness без продуктовой правки и без обещания ускорения.

## Передача и завершение
Разработчик начинает от указанного baseline в отдельной ветке, проверяет свежий main: при изменении продукта корпус/протокол явно перебазируются до измерений, не смешиваются версии. Основная работа следующего запуска — программист: сначала подготовить/закрепить corpus+manifest, затем профиль, diagnosis и максимум одну правку. Один активный claim; существующий чужой не перехватывать.
Результат содержит task/status, spec1.0, branch/PR/head SHA, manifest/corpus/log/trace links, outcome, acceptance table, ограничения, следующий шаг. Negative/inconclusive/blocked — полноценные явные исходы, не повод отключать постоянную команду.
Для каждой роли start/end actual automations.peek обязательны с automation_health; latest.json обновлять последним. Ни main, ни сайт в рамках этой спецификации не публикуются.
