## Границы результата

Входит: профиль классической генерации; сохранённые 6 mile/hex без выдуманной геометрической конвенции; наполнение новых POI данными Knave; независимая проходимость выбранного гекса; подготовочные уровни обнаружения POI и текст улики секрета; save/load, Undo/Redo, прежние редакторы и RNG; RU/EN оболочка; actual desktop/narrow показ и exact-SHA ревью.

Отсутствие этих будущих функций не является дефектом данного L1-среза.

## KNC01 — включение и физический профиль

В Classic под текущим select режима добавить одну компактную строку: checkbox «Knave 2e» и справа приглушённое «6 миль / гекс» (EN: 6 miles / hex). Отдельной секции, большого заголовка, постоянного поясняющего блока не создавать. В Mythic строку не показывать. Начальный язык остаётся существующим EN; макет RU для владельца.

На пустой карте флажок меняет профиль будущей генерации без RNG и без истории документа. При первом принятом регионе профиль закрепляется для всей карты; на непустой карте checkbox read-only/disabled с доступной клавиатурой/касанием подсказкой «Профиль выбран при создании карты. Для другого профиля начните новую карту». Отдельного преобразования старой карты не делать. Обычный явный reset очищает карту по существующему flow и снова разрешает выбор; отмена reset/Undo восстанавливает прежний полный документ и профиль. Импорт восстанавливает профиль из файла, а не из последнего UI-флажка. Смена в Mythic на непустой карте подчиняется нынешнему подтверждению сброса, не обходя его.

Сохранённый профиль: id classic.knave2, version1. Физический масштаб length=6, unit=mile, measurementConvention=null/unknown. Это размер, употребляемый книгой, а не обещание вычисления площадей или расстояния между вершинами/сторонами. Zoom/rotate/resize не меняют масштаб. Общий Classic и Mythic не получают 6 миль автоматически. Геометрический выбор из PF2/WWN не переносить. Общий произвольный редактор масштаба HX-BL-042 не включать скрыто.

## KNC02 — наполнение новых POI

Плотность и расположение сохранить из classic: центральные поселения остаются, остальные допустимые позиции выбираются нынешним механизмом (обычные POI: floor(eligible/6)..floor(eligible/4), отдельно существующие водные правила). Это политика HexCrawl, не правило Knave. Существующие размеры регионов, вероятность освоенности, высоты, биомы, водная и дорожная геометрия остаются прежними. ROAD/RIV инварианты не ослаблять. Не обещать побитово тот же граф дорог при изменении типов, если нынешний алгоритм учитывает тип: допустимы лишь прежние правила связности/переправ на новой карте; старые регионы не перерисовывать.

Контентный профиль включает «Локации» (печатная10), «Постройки», «Свойства мест» (11), «Подземелья» (16). Последние уточняют тип места, не создают комнаты. Опасности/механизмы и все рекурсивные таблицы не включать в первый пакет. Для сохранённых поселений не менять класс city/town/village случайной постройкой; оставить прежнюю идентичность/название, свойства Knave — дополнительное описание. Водные POI сохраняют нынешние допустимые виды; генератор не помещает сухопутное аббатство в море.

Для не-поселений на суше продуктовая политика: три категории — локальное природное место, постройка, вход/место подземелья. Выбирать равновероятно среди категорий с непустым совместимым пулом. Категории и равные веса — явное решение генератора, не предписание книги. В выбранной категории равномерно выбрать строку из заранее определённого совместимого пула. Полные 100 исходных строк каждой из трёх таблиц должны иметь стабильный индекс, локатор и решение пригодности: eligible с условиями либо excluded с конкретной причиной. Не создавать новый тип биома по каждому слову таблицы. Линейные/площадные результаты «река», «дорога», «лесной массив» сами по себе не создают геометрию; строки, не представимые локальным POI без новой геометрии, исключить из пула и сохранить причину в source-free mapping ledger. Фактические реки/дороги остаются делом существующих генераторов. Для локальных воды/пещеры/вершины/переправы использовать явные проверки текущего контекста; не выводить радиус, климат или русло из названия. Соответствие строки уже имеющемуся значку и биому — деталь реализации внутри этих ограничений, отражённая в ledger до ревью.

Выбор из отфильтрованного пула записывать selection=compatible_pool, sourceRow=1..100; не изображать его честным исходным d100-броском. Затем один обычный d100 по «Свойствам мест»: строка100 соответствует печатной00. Сохранить значение броска и строку. Это два основных описательных компонента, без автоматического сочинения причин/эффектов. Ссылку на таблицу вне четырёх включённых каталогов показать как нерешённую справочную ссылку; не устраивать скрытую рекурсию и бесконечные перебросы. Неподдержанные ссылки не должны падать или превращаться в выдуманный факт.

В обычном просмотре показывать существующий значок и компактное название; рядом/ниже короткие чипы строк и свойства, источник — tooltip/раскрытие, а не постоянный справочник. Не добавлять самостоятельную панель генератора подсказок KNAVE2-PLACE1. Существующий редактор имени и заметки ведущего переиспользовать; авторский текст не затирается при сохранении/загрузке/смене языка. Автоматический reroll по открытию панели запрещён. Специальную кнопку переброса этого пакета не добавлять: это отдельное необязательное действие, не необходимое для создания карты. Уже работающие MB теги/перебросы остаются прежними.

Контентные результаты фиксируются в принятом документе вместе с catalogVersion/sourceId/row и отображаемым RU значением: обновление каталога не подменяет старый результат. EN оболочка не делает обратный перевод RU: контент без проверенного EN показывается с компактной отметкой RU, источник сохраняет RU-редакцию. Короткие названия/свойства хранить через пригодный существующий механизм; архитектуру второго движка таблиц не строить. Общий слот тегов MB нельзя заполнять частично невалидными Knave-записями.

Для случайности использовать отдельный детерминированный профильный поток/счётчик по существующим правилам streams; контентные броски не расходуют geography/names/visual и не используют Math.random/Date.now. Ключи, версия и состояние должны переживать save/load/Undo. Выбор категории/пула/trait на настоящем generation handler воспроизводим. Ошибка загрузки контентного каталога, пустой допустимый пул или исчерпание ID — явный отказ до commit с восстановлением всех streams/истории, не частично созданный регион. Legacy Classic без флажка сохраняет прежний путь RNG буквально.

## KNC03 — проходимость гекса

Разреженный атрибут по координатам гекса: unspecified | normal | difficult. Отсутствие означает unspecified. Книга не задаёт таблицу «биом → сложность», поэтому новые гексы первоначально unspecified; лес не становится difficult автоматически. В просмотре одно короткое значение «Проходимость: Не задана/Обычная/Трудная», при редактировании native select с этими тремя значениями. Контрол появляется для профиля Knave и суши; на воде прежнее сухопутное значение сохраняется скрытым, подобно локальному biome override. После обратного превращения в сушу оно восстанавливается. Смена биома/высоты не сбрасывает значение.

Координатный атрибут остаётся на месте при E7 переносе гекса между регионами; не следует за перемещаемым POI. Менять проходимость можно без POI. Одна Undo возвращает прежнее значение; no-op не создаёт истории и не расходует RNG. Это подготовительные данные, расчёта замедления/стека погоды/темноты нет. Ограничить редактор выбранным гексом; массовую кисть/области не добавлять.

## KNC04 — обнаружение POI и улика

На POI три режима: passage (заметен при прохождении), exploration (находится исследованием гекса), interaction (секрет, находится взаимодействием). Новые автоматически созданные места по умолчанию passage: это консервативная политика, не случайная норма книги. Случайную долю секретов и автоматические связанные сюжеты не изобретать. Ведущий меняет режим в общем редактировании. Никаких бросков поиска или автоматического раскрытия при клике.

Для interaction обязательно отдельное поле clueText: непустой trim, максимум512 UTF-16 единиц. Улика находится в том же гексе и открывается исследованием; она связана со своим POI устойчивым владельцем/адресом, а не свободным названием. Это отдельное поле с собственным смыслом, не заголовок секрета и не заменяющая его gmNote. Пример авторский: у скрытого входа улика «Следы обрываются у скалы». Не нужна отдельная случайная координата/POI на каждую улику. Для passage/exploration улику можно сохранить, но она не обязательна и не удаляется автоматически при переключении режима. Пустая улика секрета запрещает «Готово», показывает короткую ошибку у поля и оставляет принятый документ/историю без изменений. Пользователь может исправить или отменить.

Проходимость и обнаружение — разные данные. E8 перенос POI переносит его content/discovery/clue вместе с именем/тегами; проходимость исходного и целевого гексов не меняется. E7 меняет owner regionId соответствующих POI-данных по нынешним правилам. При удалении/затоплении POI новые авторские поля входят в существующий список потерь и подтверждение; отмена возвращает всё. Не создавать висячих связей. Если legacy неоднозначность адресов уже известна, новый редактируемый payload не навешивать на «один из» объектов.

Это GM-данные подготовки. Нынешняя карта/PNG остаются видом ведущего; значки секретов могут присутствовать. Новый игрокобезопасный экспорт, скрытие объектов и автоматическая симуляция открытия в этот этап не входят; явно назвать ограничение при показе перед выпуском. Одними этими полями не объявлять полную поддержку KNAVE2-010/map.audience_views.

## KNC05 — документ, совместимость и операции

Новый экспорт hexcrawl-map v10; вводить только нужные необязательные слои: игровой профиль/физический масштаб, проходимость по координатам, контент и discovery/clue у уникального живого POI. Конкретные имена полей согласовать с текущим saveValidation без второго общего документа. Версии2..9 импортировать по старым правилам с отсутствующими новыми слоями: никакого автоматического Knave по языку/seed/биому. В старой версии непустые новые поля отклонять, не терять молча. Неизвестный profile/catalog version, неверная единица/length, null вместо слоя, массив вместо record, NaN/дубли/висячие ссылки — ошибка до изменения документа. Старая программа v9 не обязана читать v10; сообщить это как ограничение формата.

Новые данные входят во все capture/clone/restore, generation backup, reset/удаление последнего региона, checkpoint, импорт/экспорт и общую Undo/Redo. Черновик редактирования отделён от принятого документа, защищён revision+document identity+ref. Смена объекта/режима/импорт использует действующий draft gate завершить/отбросить/вернуться. PNG/JSON экспортируют принятую карту без автокоммита и без временных рамок черновика. Поля отображаются escaped text, без HTML и исполнения исходных «эффектов». Нельзя полагаться на совпадение локализованного имени вместо ID.

На новой Knave карте продление/перегенерация создаёт новые контентные поля только для затронутых новых POI; прошлые регионы и авторские данные остаются буквальными. Вся generation transaction атомарна. Неподдержанное изменение географии, которое потеряет авторский payload, отклонить или провести через существующее явное подтверждение потерь; молчаливого удаления нет.
