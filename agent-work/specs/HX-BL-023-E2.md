# HX-BL-023 / E2 — биомы гекса и региона

Версия E2-1.0, 29.10.2026. Статус: ready_for_development после сохранения передачи и предъявления макета в текущем чате. Родительская спецификация HX-BL-023 v2.1 сохраняет E1 и дорожную карту E3–E8; этот документ является подробным контрактом только E2. База реализации: опубликованный main `8f7d17266c53e31428da7c0da6dbbf1afe01d035`, дерево `bd37f23271b33547f65b62c2af242bb3e8e11f00`.

## 1. Полномочия, цель и границы

Начало E2 уже разрешено owner-decision-2026-10-28-editor-functional-scope и owner-decision-2026-10-28-editor-additional-functions-approved. L1 — подготовка карты, develop_existing; также create_from_scratch. Ведущий меняет местность существующей территории без пересоздания имён, заметок и географии. Отдельное разрешение на публикацию проверенного SHA обязательно. Показ макета не третий блокирующий этап.

Сохранить существующую локальную правку биома одного гекса; добавить смену базового биома региона с явным решением по локальным правкам. Размер M, один продуктовый PR; зависимости: общая история и безопасные операции опубликованного E1/024. Генераторы MB041 идут следующим продуктовым приоритетом после редактора, не входят в этот PR.

Не входят: изменение высоты/границ/принадлежности, суша↔вода, построение дорог/рек, новый lock/pin, reroll, новые биомы, изменение весов/матрицы генерации, локализованные заметки, автоперевод, глобальный режим «Редактировать». HX-FB-005 — актуальное предложение владельца, но его новый единый режим и одностороннее переименование ещё не утверждены. E2 не добавляет карандаши к каждой строке: один текстовый вход «Изменить местность» заменяет существующий вход редактора биома. Остальные работающие редакторы E1/POI/заметок этим срезом не перестраивать.

До/после: сейчас можно назначить исключение одному гексу, но нет целостной операции региона. После E2 — выбрать регион Хогланд, сменить его базовую местность и осознанно оставить три локальные правки либо снять их; одна Undo возвращает точный прежний документ.

## 2. Проверенная база и действующие правила

Аудит: `../evidence/HX-BL-023-E2-spec-v1/source-audit.md`, все ссылки относятся к точному base SHA. В App.tsx уже есть 24 BIOMES, Region.biomeId/heightLevel/biomeLandType и сохраняемый biomeOverrideByHexKey. Локальный selector показывает все 24, setSelectedHexBiomeOverride/resetSelectedHexBiomeOverride используют общую manual transaction. Региональный setter отсутствует. saveValidation допускает override только для гекса существующего региона, в том числе под озером; отдельное море регионом не является.

Генерационные веса не являются разрешениями ручного ввода: docs/region-generation.md явно разрешает ручной выбор независимо от веса. Высота региона — отдельные данные для гидрологии, не автоматически меняется от визуального исключения гекса. Строгая матрица соседства при генерации может ослабляться в fallback; E2 не меняет эту генерацию и не чинит старые карты скрыто.

## 3. Данные и разрешённые варианты

### E2-D01. Эффективный биом и область

Для гекса региона эффективный биом = сохранённый override по ключу q,r, иначе Region.biomeId. Озеро/море сохраняет свою водную поверхность. Изменение базового биома не переводит воду в сушу. Новый постоянный слой/версия JSON не нужны: используются существующие Region и override map. UI-черновик и решение keep/clear не экспортируются.

### E2-D02. Гекс

Локально выбирать все 24 действующих BiomeId. Не менять Region.heightLevel/biomeId/biomeLandType и речные высоты. Это прежняя локальная местность/отображение, не операция изменения высоты региона; в форме явно «Высота региона не изменится». Вода, candidate и пустой выбор не дают локальную наземную правку. Действия: назначить override либо «Использовать биом региона» (удалить ключ). Существующее явное исключение, даже равное базе, не нормализовать автоматически: keep сохраняет сохранённые записи без изменений. Назначение текущего базового значения без записи создаёт явную локальную запись как прежний обработчик; это изменение данных, хотя видимая местность может совпадать. UI показывает «локальная правка» и позволяет сбросить её.

### E2-D03. Регион и высота

Региональный выбор определяется устойчивым region.id, не текущим порядковым индексом и не последним выбранным гексом. Выбирается существующий непустой регион через его гекс. В озёрном гексе этого региона региональная операция доступна; отдельный морской/candidate/пустой гекс — нет. Высота остаётся исходной: допустимы все BIOMES с heightLevel равным сохранённому Region.heightLevel, включая биомы с нулевым settledWeight. biomesLandType wild/settled не меняется; не пересчитывать POI под новую растительность. Пример: swamp/dead_forest разрешены вручную на высоте1 даже в освоенном регионе. Mountains нельзя назначить региону высоты1 в E2: пояснить, что изменение высоты — другой этап редактора.

Полные ID по высоте (порядок UI — порядок BIOMES, локализованные метки из getBiomeLabel):

- 1: plain_deciduous_forest, plain_mixed_forest, plain_coniferous_forest, open_plains, swamp_forest, swamp, deciduous_woodland, mixed_woodland, coniferous_woodland, semi_desert, dead_forest, dead_woodland.
- 2: deciduous_forested_hills, mixed_forested_hills, coniferous_forested_hills, open_hills, hilly_woodland, dead_forested_hills.
- 3: coniferous_mountain_forest, mixed_mountain_forest, deciduous_mountain_forest, mountains, mountain_woodland, dead_mountain_forest.

### E2-D04. Соседство региона

При смене базового ID нового региона проверять соседние регионы с общей стороной: новый canonical biome должен быть совместим с canonical biome каждого соседа через существующий isBiomesCompatible/BIOME_COMPATIBILITY_MATRIX, включая симметричные исключения dead forest. Совпадение биомов соседних регионов разрешено вручную: генерационное предпочтение разнообразия не ограничение E2. Не подменять канонический биом соседа его локальным визуальным override; локальные исключения сохраняют прежнюю область действия.

Недопустимый новый ID виден недоступным с причиной либо отдельно перечислен под selector; server/handler повторно проверяет ту же причину до commit. Сообщение указывает регион-сосед по текущему отображаемому имени, без мутации имени. Нет fallback, случайного другого биома, silent force или автоматического изменения соседа.

Старые противоречия не заставляют ремонтировать всю карту: отмена/просмотр разрешены, исходный ID можно оставить; проверка соседства применяется при изменении base ID. Операция «та же база + снять overrides» не создаёт нового нарушения canonical соседства и разрешена при корректной высоте целевого ID. Если высота/регион в старом документе невалидны по действующему importer, сам importer отказывает; E2 не обходит его. После валидного импорта не вычислять региональную высоту заново по локальному override.

### E2-D05. Локальные правки при региональной операции

Считать N всех сохранённых biomeOverrideByHexKey в Region.hexes, включая равные базе и под озёрами. По умолчанию «Сохранить N локальных правок». Альтернатива «Снять N локальных правок» удаляет только эти ключи, не чужие регионы. При N=0 не показывать лишний переключатель. Снятие требует явного выбора, Apply является подтверждением показанного последствия; отдельный модальный третий gate не нужен.

Предпросмотр различает размер региона, число удаляемых/сохраняемых записей и число гексов, чей эффективный биом реально изменится. Если есть вода, отдельно указать неизменность поверхности и число подводных локальных записей, которых касается снятие. Не обещать N визуально изменённых гексов только потому, что N записей снято. Демонстрационный макет 8/3/5 — пример без водных гексов, не измерение карты владельца.

### E2-D06. Атомарная запись и инварианты

Изменить у выбранного региона только biomeId и канонические biomeLabel/biomePrimaryEmoji/biomeSecondaryEmojis/biomeEmojiLabel из того же BIOMES; label/emojiLabel хранятся в принятом внутреннем формате текущего построителя, а не в языке UI. При clear дополнительно изменить только выбранные override keys. Сохранить id, hexes/center/anchor, размер/target, heightLevel, biomeLandType, woodlandStyle, generationMode/kingdomId, coastal/slope/river metadata, все остальные поля, POI/types/names, toponyms/kingdom names, дороги, тропы, crossings, реки, вода, препятствия, notes, counters, RNG, candidates и generation checkpoints. Для гекса — меняется только его override key. Производная отрисовка леса/редколесья может измениться вслед за биомом; сохранённый woodlandStyle не reroll-ить. Старое поле может оставаться инертным у не-редколесья.

Подготовить целый новый snapshot, metadata и проверки до первой записи. Сверить revision и target identity при Apply; busy/import/kingdom/pending regen отказывает. Один успешный Apply — одна общая transaction, один Undo/Redo восстанавливает точные map/document values. Если существующий commitManualMap синхронизирует toponyms, проверить, что для биомной правки это не меняет registry; не считать автоматическую замену имени допустимой. Никаких вызовов генератора/случайного выбора.

No-op — точное равенство сохраняемых значений и ключей: регион +keep с прежним ID/metadata, clear без существующих ключей, повторная установка уже существующего такого же override, reset отсутствующего override. No-op/Cancel/неудача сохраняют обе стопки истории и revision документа, не очищают redo. Создание/снятие явной записи, даже с равным визуальным результатом, не no-op. Исключение при подготовке не оставляет частичный регион/слой/историю; ошибку показать, черновик сохранить.

## 4. UI и жизненный цикл

Вход — один текстовый «Изменить местность» / «Edit terrain» на месте существующей кнопки биома. По умолчанию форма скрыта; она появляется только после этого нажатия. Макет намеренно показывает раскрытое состояние. Форма остаётся рядом с информацией, не большой блок над ней. Название/заметки и «Найти объект» остаются на своих местах. Никакого нового карандаша для каждого региона. Из озёрного гекса название входа «Изменить биом региона»; локальный target отсутствует.

Форма: «Где изменить» (гекс/именованный регион), «Новый биом», неизменяемая высота, решение по локальным правкам для региона, компактное описание результата, «Применить / Отмена». Дополнительный reset локального биома виден для существующего override. Неподходящие варианты имеют объяснение высоты/соседства; отсутствие вариантов не подставляет auto. При выборе «Использовать биом региона» показывается унаследованный ID и точное последствие удаления ключа.

Выбор в selector меняет только черновик. Это намеренное уточнение прежнего немедленного commit hex selector под общий цикл E2; сам набор локальных вариантов/данные сохраняются. Apply — единственная запись. Пока нет отличия от исходного intent, Apply disabled, за исключением выбора явно создать/снять запись. Cancel всегда доступна вне busy-commit.

Открытие flush-ит существующую группу заметок без потери текущего текста и сохраняет target identity/revision. После открытия просмотр другого существующего гекса, pan/zoom/rotation разрешены; форма остаётся привязана к исходному объекту, её заголовок это показывает. Не перевязывать draft к текущему выбору. Смена target внутри формы или закрытие при dirty предлагает «Продолжить редактирование / Отбросить»; без изменений закрывается сразу. Undo/Redo, генерация, импорт, другой редактор, заметки и прочие мутации при dirty E2 используют общий guard с видимой причиной/решением, не пишут поверх него. У существующего dirty E1 сохраняется его нынешнее разрешение Stay/Discard/Save, E2 не обходит этот guard. Export сохраняет текущую committed map без draft. Переключение RU/EN переводит подписи, но сохраняет draft IDs/target/policy; не редактирует никакие названия. Заметки не переводятся на новую Save-кнопку.

Фокус: вход→первый элемент target/selector, Escape→обычное закрытие с dirty guard, после Cancel/Apply→существующий вход; Stay→поле формы. Валидация рядом с selector, role=alert/aria-invalid по ситуации. Busy disabled-контролы с понятным состоянием; stale сообщение «Карта изменилась. Откройте форму заново», никаких поздних writes в новую карту. Клавиатура и touch без hover, эффективные targets ≥44px. На390px всё в один столбец, кнопки переносятся, горизонтального overflow нет. На широком экране target choices могут быть в строке.

Тексты RU/EN, краткий минимум: Новый биом/New biome; Только этот гекс/This hex only; Весь регион/Whole region; Сохранить локальные правки/Keep local edits; Снять локальные правки/Clear local edits; Использовать биом региона/Use region biome; Высота региона не изменится/Region elevation stays unchanged; Несовместимо с соседним регионом/Incompatible with neighbouring region; Не удалось применить/Changes could not be applied; Карта изменилась. Откройте форму заново/The map changed. Reopen the editor.

## 5. Совместимость, продолжение, ошибки

Текущий поддерживаемый JSON/schema и corpus остаются прежними; новые поля отсутствуют. Round-trip сохраняет точные base IDs/metadata и override map; no-overrides legacy save загружается как пустой слой без перезаписи других данных. Не удалять подводные overrides при импорте только потому, что UI их не редактирует напрямую. Некорректные/неизвестные IDs, dangling keys и невалидные heights обрабатываются существующей структурной валидацией, атомарно без изменения открытого мира. Старые сохранения с известным ID нулевого веса не отвергать.

Продолжение после редактирования использует новую базу и прежнее сохранённое RNG-состояние. Не обещать тождество следующей генерации старому НЕредактированному миру: изменение биома может законно повлиять на окружение. Требование — две копии ОДНОГО отредактированного сохранения дают одинаковое продолжение, а отмена продолжения возвращает отредактированный мир; отмена самой правки — исходный. Никакой новой генерации в Apply.

Видимые отказы: invalid biome, missing/stale target, invalid height, incompatible neighbour, busy, precommit failure. Отсутствие региона/вода для hex не порождает редактор случайного последнего региона. Вновь выбранная карта не получает отложенный callback старой формы. Пояснение не требует открытия Debug.
