## 1. Вид и непосредственное действие — обязательный контракт

### DE-01. Один общий режим

Одна кнопка «Редактировать» / «Edit» справа сверху информационной карточки включает режим; та же кнопка «Готово» / «Done» его выключает. Это единственный переключатель режима, а не отдельные режимы у каждой сущности. Начальное состояние — просмотр. Выбор другого существующего гекса сохраняет включённый режим; импорт/reset закрывает старые активные поля и не переносит их callbacks в новый мир. Панорама/zoom/rotation остаются навигацией.

В просмотре обычная информация и читаемые заметки, без карандашей. В режиме выделять только реально изменяемые значения: тонкое пунктирное подчёркивание/спокойная подложка плюс доступное имя. Координаты, вычисляемые и ещё не поддержанные свойства не подсвечивать как редактируемые. Touch/клавиатура без hover, эффективные цели44px, native focus. Подсветка не становится россыпью рамок/иконок/подписей «изменить».

### DE-02. Нажатие сразу на значение

Название → один input вместо этого названия. Биом или тип POI → обычный inline select на месте значения. Заметка → textarea на месте текста. Не показывать промежуточный выбор инструмента, новый диалог или панель действий.

Регион/гекс определяется тем, **какое информационное значение нажато**. Базовая местность региона расположена непосредственно под именем региона. В части выбранного гекса — «Местность: как в регионе» либо его локальное значение. Нажатие первого меняет регион, второго — гекс. Это два значения предметных данных, не радиокнопки/вкладки выбора области. При наследовании не дублировать название биома: показать «как в регионе». Если override явно равен базе, показать локальное значение с ненавязчивым признаком локальности.

Для поселения название и тип — отдельные смысловые значения: нажатие на имя вводит имя, на тип выбирает тип. Не делать два карандаша у одной строки. Нажатие на имя реки/озера редактирует только имя; не обещает ещё не реализованное изменение геометрии/гидрологии. У королевства та же возможность изменения имени в его информации/каталоге. Существующее добавление/удаление POI не терять: пустое редактируемое место POI открывает список типов, значение «Нет точки» в списке обычного/водного POI вызывает прежнее удаление без отдельной иконки корзины. У центрального POI не предлагать ранее неподдержанное удаление. Это перенос существующих действий в прямое взаимодействие, не новая географическая функция.

**В продукте не должно быть новых кнопок/форм «Сохранить», «Отмена», «Применить», «Выбрать гекс/регион», отдельной «Изменить местность», keep/clear-переключателя и постоянного предпросмотра операции.** Старую парную форму E1 и её Save/Cancel/Stay/Discard/Save-and-continue удалить из этого нового прямого цикла. Риски решаются валидацией поля, общей историей и атомарностью, не обязательным диалогом каждого щелчка.

«Найти объект» под информацией/заметками сохраняется как уже утверждённая навигация к объектам вне текущего гекса. Поиск не новый режим редактирования: в просмотре строки выбирают объект, во включённом общем режиме его именованное значение доступно так же напрямую. Не возвращать парную RU/EN-форму или карандаши внутри каталога. Выбор объекта из каталога не превращается в обязательный шаг для видимых полей.

### DE-03. Автоматическое применение

Select применяет валидный выбор сразу, одной общей transaction. Input названия подтверждается Enter или blur, без кнопки. Нажатие «Готово», смена выбранного объекта/языка и другое действие сначала синхронно завершают валидное активное поле. Одно завершение поля — одна запись истории, не запись на каждый символ. IME composition не подтверждать преждевременно. Escape закрывает незавершённое поле, возвращая committed значение; уже применённые другие правки остаются. Дальнейшая отмена — существующие общие Undo/Redo, без новых локальных панелей.

Заметки мастера сохраняют опубликованное immediate-input поведение и500ms/blur grouping общей истории; переключатель режима не добавляет им Save-кнопку. В режиме просмотра текст читается, но не раскрывает редактирование кликом. В режиме изменения пустая заметка представлена одним доступным текстовым местом «Добавить заметку»; никакого карандаша. Текст заметок один, без новой RU/EN-схемы/перевода.

Ошибочный ввод не применяется: сообщение непосредственно у поля, оно остаётся открытым и получает фокус. Другой объект/язык/режим не принимает этот текст скрыто; действие отклоняется с тем же локальным сообщением. Исправить или Escape — без обязательного Save/Discard-диалога. Busy/stale/fault показывают причину, не затирают новый документ. Восстановление фокуса в исходное значение или, если оно исчезло, в стабильную информационную область.

## 2. Имена — только выбранный язык

### DE-04. Одноязычная запись без скрытой коррекции второго языка

Открываемый input содержит только значение языка интерфейса. Зафиксировать key/type/language/revision и исходное значение на открытии. В ToponymRegistry меняется только поле ru или en; в kingdom.name — только соответствующий ключ ru/en. Второй язык сохраняется **буквально**, включая существующую длинную legacy строку: не trim, не переводить, не копировать и не «исправлять» её при сохранении первого языка. Метаданные model/revision/kind/identity и остальные сущности сохраняются. При переключении языка сначала подтвердить старое поле на захваченном старом языке, затем отобразить новый; callback не выбирает язык из нового React state.

Валидация изменяемого имени: trim его краёв,1–80символов, одна строка без управляющих символов, прежняя проверка дубликатов в этом языке среди иных toponyms; для kingdom сохраняется прежняя политика отсутствия глобальной уникальности. Не валидировать неизменяемый язык как новое обязательное поле. Если старое изменяемое значение legacy длиннее80, его просмотр/no-op допустим; новое изменённое значение должно пройти правила. Exact no-op не расходует историю/redo. Не вызывать старый paired rename helper так, чтобы он trim-ил/отклонял/менял другое поле; использовать адаптер/узкую операцию с проверенным контрактом.

Проверить все5 существующих именованных типов: регион, поселение, река, озеро, королевство. JSON/Undo/Redo/продолжение восстанавливают точные пары имён, вторая локализация после каждой одноязычной операции deep-equal baseline.

## 3. Биомы — функциональные правила E2 без лишнего выбора

### DE-05. Локальная местность гекса

Эффективное значение = biomeOverrideByHexKey[key] либо Region.biomeId. В inline списке существующего наземного гекса — все24 действующих ID и вариант «Как в регионе» (удалить его override). Выбор записывает/удаляет только этот ключ. Region.heightLevel/base/landType остаются прежними; локальная местность не изменение региональной высоты. Вода/candidate/пустой выбор не получают наземный hex selector. Озёрный гекс региона всё ещё позволяет региональную правку через его региональную информацию, вода остаётся водой.

Явная запись, равная базе, может существовать и сохраняется как локальная правка; не нормализовать её при других действиях. Создание/снятие такой записи — изменение данных даже при том же изображении. Повторная установка уже существующего того же значения/reset отсутствующего ключа — no-op.

### DE-06. Базовая местность региона

Нажатие регионального биома даёт только подходящие BiomeId текущей сохранённой Region.heightLevel:12/6/6до проверки соседства. Нулевой wildWeight/settledWeight не запрет ручного выбора: docs/region-generation.md разрешает ручной выбор независимо от веса. Не менять wild/settled, высоту, POI, воду, топологию или имена. Иная высота не предлагается как свободный выбор; краткое объяснение доступно по месту, без обязательной отдельной формы.

По высотам1/2/3 использовать canonical BIOMES, без копии весов:

- 1: plain_deciduous_forest, plain_mixed_forest, plain_coniferous_forest, open_plains, swamp_forest, swamp, deciduous_woodland, mixed_woodland, coniferous_woodland, semi_desert, dead_forest, dead_woodland.
- 2: deciduous_forested_hills, mixed_forested_hills, coniferous_forested_hills, open_hills, hilly_woodland, dead_forested_hills.
- 3: coniferous_mountain_forest, mixed_mountain_forest, deciduous_mountain_forest, mountains, mountain_woodland, dead_mountain_forest.

Для нового base ID проверить canonical биомы всех соседних регионов с общей стороной через текущий isBiomesCompatible/матрицу и симметричные dead-forest exceptions. Тот же биом соседа допустим вручную: предпочтение генерации разнообразия сюда не переносить. Локальные override соседей не подменяют их canonical региональную высоту/биом. Несовместимый вариант недоступен с короткой причиной, callback повторно валидирует до записи. Нет fallback/reroll/скрытого изменения соседа. Старые противоречия не ремонтируются автоматически, no-op просмотр допустим.

**Региональная смена всегда сохраняет все локальные override entries.** Никакого keep/clear chooser и скрытого массового снятия. Снятие отдельной правки — «Как в регионе» непосредственно в списке этого гекса. Массовый clear из E2-1.0 в этом выпуске не реализовать; это убранная из текущего UI-среза операция, а не новое условие согласования. Подводные записи, равные базе записи и чужие регионы сохраняются буквально.

Изменить только biomeId и4метаданных Region: biomeLabel=BIOMES[id].label, biomePrimaryEmoji, копия biomeSecondaryEmojis, biomeEmojiLabel=primary+secondary.join(''). Сохранённые labels — canonical внутренние, не язык UI. Сохранить все прочие поля Region, включая woodlandStyle: производная отрисовка может следовать новому биому, но стиль/RNG не reroll-ить. Единичный гекс меняет только override map.

## 4. Общие гарантии, совместимость и ошибки

### DE-07. Безопасность без диалоговой бюрократии

Каждое завершённое прямое действие готовит и валидирует целый snapshot до первой записи state/history/revision. Проверка stable key/target/current value/revision/busy остаётся обязательной. Изменение одного поля/один выбор — одна общая transaction. Подготовка может throw: документ, RNG, обе стопки и другие поля остаются прежними; ошибка рядом с объектом. No-op и Escape незавершённого имени не очищают redo. Названия/биомы не переназначают notes/POI/дороги/реки/переправы/воду/препятствия/candidates/counters/generation checkpoints. Успешная операция не оставляет частичную запись имени или metadata.

Общая модель активного inline поля не должна обходить защиту E1 от устаревшего closure и опубликованное объединение заметок. Валидный input завершается до навигации/другой мутации; неверный остаётся с локальной ошибкой. Import/reset после явного действия не получает поздние callbacks старого target, старый mode/поле не воскресают. Не сохранять UI-mode или draft в JSON. Export должен сначала синхронно подтвердить валидное активное имя/группу notes либо явно отказать при ошибке, а не молча выгрузить не тот текст. Готово завершает поле и выключает подсветку, не отдельная команда batch-save.

Продолжение: две копии одного ОТРЕДАКТИРОВАННОГО сохранения дают одинаковый следующий результат при одинаковых действиях. Не сравнивать с неизменённым прежним миром: новая региональная местность может законно повлиять на окружение. Изменение языка UI само не меняет данные. Существующая схема JSON/legacy corpus сохраняются, новая schema не требуется; importer атомарно отклоняет неизвестные IDs/dangling overrides как прежде.

После включения режима информация не разрастается в редактор-панель: только подсветка и один активный input/select/textarea в нажатом месте. На390px нет горизонтального overflow/перекрывающихся целей. Не добавлять новые группы действий, постоянные сообщения о transaction/JSON/revision, модальные Save/Cancel, функционально пустые будущие инструменты. Existing Undo/Redo и Find object сохраняются на уже отведённых местах, без дублей.
