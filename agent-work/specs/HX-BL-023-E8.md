## Фактические владельцы данных

| Данные | Где сейчас | При переносе |
|---|---|---|
| Обычный наземный POI | Region.pointsOfInterest + pointOfInterestKinds[hexKey] | Перенести одну запись, тип без преобразования; удалить только старую запись этого объекта |
| Центральный POI | centralPoiKind на centerHex; suppressCentralPoi/isTract влияют на наличие | В E8 не перемещается: отделение POI от защищённого центра требует отдельного контракта модели. Смена типа на месте сохраняется |
| Водный POI | waterPoiByKey[hexKey], без отдельного числового ID | Перенести тип и ручное имя; вода/lakeId не перемещаются |
| Существующее имя поселения | toponyms[`settlement:regionId:q,r`] = en/ru/kind/model/revision | Полный объект буквально мигрирует на новый адрес; генератор имени не вызывается |
| Теги наземного POI | owner {kind:'poi',regionId,hexKey}; rollCounters с префиксом poi:region:q,r\| | Переписать адрес владельца и весь префикс счётчиков, сохранив результаты/overrides/revision/definitionVersion и значения counters |
| Заметки мастера, локальный биом, вода | gmNotesByHexKey, biomeOverrideByHexKey, hexTerrainByKey | Оба гекса сохраняют прежние значения буквально, включая пустую строку/отсутствие |
| Дороги/тропы/переправы | Road.id, физические segments; Crossing.key/riverEdgeKey | E8.1 не меняет; зависимый перенос отклоняется до commit |
| Регион/королевство | id, centerHex, anchorHex, hexes, kingdomId и область | Геометрия/членство не меняются; меняется лишь владелец обычного POI при допустимом переходе |

Адрес `settlement:...`/tag owner не является независимым глобальным ID POI. E8 сохраняет логическую идентичность через однозначную миграцию полного payload, не обещает выполнение всего S02-C02. Отдельный реестр глобальных ID этим срезом не вводится. Сейчас для водного POI нет tag owner: не создавать фиктивный наземный owner или новые теги.

### M01. Источник и назначение

Источник — ровно одна существующая точка на выбранном гексе. При неоднозначном наложении наземного, водного и центрального объекта отказ `ambiguous_poi`; не выбирать первый элемент. Непоказанный/подавленный центр не превращается в переносимую точку. Центральный объект показывает пояснение «Центральная точка связана с центром региона; здесь можно изменить её тип и имя». Новый центр не создаётся. Anchor без центрального POI не запрещает перенос обычного POI: геометрия anchor остаётся прежней.

Наземное назначение — существующий гекс ровно одного региона, фактически суша, не занятый любым POI и не центр с реально существующей центральной точкой. Center без центрального объекта допустим. Существующий занятый гекс не заменяется и не обменивается местами. Водное назначение — существующее море/озеро без POI; перенести воду или преобразовать тип нельзя. Пустое место карты/гекс-кандидат не является назначением. Нулевое расстояние — точный no-op даже при старой несовместимости, без новых ошибок/истории/расхода RNG и без очистки redo.

Land→water и water→land отклонять `poi_environment_mismatch`; не подбирать «похожий» тип. Для Classic тип должен входить в фактический набор назначения (`editablePoiKinds`; water: sea/settled/wild через getWaterPoiKindPool). Морской shipwreck нельзя перенести в озеро, где он отсутствует в наборе. Legacy-объект с неизвестным типом можно читать/оставить на месте; перенос отклоняется с типом/местом, без нормализации. Использовать существующие наборы и эффективную воду, не эмоджи/цвет/скрытый layer.

Между наземными регионами Classic перенос разрешён при совместимости типа; kingdomId не переносится вместе с POI. В Mythic обычные ориентиры переносимы в том же королевстве, в тип региона, разрешённый существующим mythicPoiChoices. Миф: только дикий регион, внутри фактической области его королевства, в целевом регионе нет другого Мифа (центральный также учитывать). Между королевствами, из/в незакреплённую область Mythic отказ `poi_kingdom_mismatch`; это сохраняет смысл квот/владельца. Престол/Удел в центре защищены правилом выше. Водный POI старой импортированной Classic-карты при текущем Mythic не становится новым допустимым объектом: перенос только в Classic. Смена режима не удаляет старые данные. Ручной перенос не запускает перебалансировку квот, как прямо установлено docs/mythic-bastionland.md.

### M02. Данные и коллизии

Готовить отделённый кандидат. В исходном массиве заменить координату на новую с сохранением порядка; при межрегиональном переносе удалить исходный элемент и добавить в конец pointsOfInterest цели. Остальные объекты/порядок неизменны. Полностью мигрировать существующий pointOfInterestKinds, settlement toponym, editorNames и теги/все rollCounter-префиксы. Если явного типа/имени не было, отсутствие не заполняется новым случайным значением. После переноса не должно одновременно остаться два ключа одного объекта. Тип/парное имя/текстовые overrides/числа тегов сравниваются до/после буквально, а не только видимая RU-строка.

Целевой stale name/tag/counter/editorName, даже если POI визуально не показан, — `poi_identity_conflict` с видом конфликта. Нельзя перезаписывать «похожую» запись, удалять чужую, объединять теги или перебрасывать имя ради уникальности. Несуществующий/удалённый источник и изменившийся снимок — `stale_poi_move`; показать «Карта изменилась, выберите точку заново». Проверять collision до синхронизации toponyms; общая синхронизация не должна удалить переносимую запись или заново создать её.

RNG географии/POI/visual, toponym seed, tag counter values и все next-ID counters сохраняются. Последующая намеренная жеребьёвка тегов после переноса продолжает сохранённый counter; адрес seed тега сейчас меняется вместе с owner, поэтому одинаковое следующее значение на разных координатах не обещается. Последующее расширение карты и export→import→то же расширение после перемещения должны совпадать между собой.

### M03. Связи и отказ

Никакого автоматического поиска пути/переноса segment/переправы/препятствия. Если любой реальный road/trail segment касается исходного гекса, перенос отклонить `poi_path_dependency`, перечислить Road.id, типы и участок; фокусируемая ссылка выбирает затронутый путь через существующий E3. Консервативный отказ действует и на проходной участок, где логическое назначение не сохранено отдельно: нельзя угадывать, что путь никак не связан с точкой. Без удаления/изменения пути продолжить перенос невозможно; пользователь может завершить/отменить перенос и явно отредактировать путь, затем повторить. Не обещать, что удаление одного сегмента всегда допустимо: E3 сохраняет ROAD-05/07/08/10 и может отклонить его. Нужный в будущем совмещённый reroute — не часть E8.1.

Путь у назначения не переносится и не перепривязывается; соседство POI с существующим путём допустимо. Вода, реки, их F, русла, переправы, препятствия неизменны. Заметки обоих гексов показать в preview как «Остаются на местах», не копировать текст в сообщения ошибок. Объектные теги/имя показать как «Перенесутся с точкой». В текущем коде нет структурированных NPC/rumor/quest refs: отсутствие такого слоя не является доказательством их полной поддержки. Если разработчик обнаружит новый сохраняемый owner/reference POI сверх инвентаря, зависимый перенос заблокировать до адресного дополнения spec, не терять неизвестный payload.

### M04. Транзакция, отмена и переходы

Draft хранит источник, выбранную цель, документный token/revision, собственную identity; preview/selection не входят в карту/экспорт/history. Начало доступно из общего режима Edit, после штатного закрытия/фиксации редактируемой заметки. Поле «Расположение» в карточке POI начинает выбор цели; карта продолжает pan/zoom/rotate, drag никогда не выбирает цель. Пин источника и рамка цели различимы по подписи и форме, не только цвету. Клик/тап по явному гексу либо ввод q/r выбирают цель; неоднозначное попадание требует явного выбора, без first-hit fallback. Пока выбирается цель, обычный клик не запускает генерацию и не меняет источник. q/r — канонические безопасные целые, реальные координаты проверяются по документу.

Единственная фиксация — существующее «Готово» общего режима. Пока цели нет/ошибка, оно недоступно с читаемой причиной. После выбора допустимой цели preview показывает откуда→куда, имя/тип/теги и сохранность гексов; «Готово» выполняет одну транзакцию и возвращает обычный просмотр на целевом гексе. Двойной вызов — один commit. Esc отменяет только перенос и возвращает общий Edit на источнике; следующий Esc ведёт себя по существующему контракту режима. Не добавлять Save/Apply/Cancel-панель, третье согласование или отдельный выбор инструмента.

Уход на другой объект/Undo/Redo/import/reset/generation/mode switch при draft идёт через существующий общий переходный gate: закончить допустимый перенос / отбросить / остаться. Invalid draft нельзя закончить, можно отбросить/остаться. Устаревший обработчик не применяет перенос в новом документе, даже если revision совпал; нужны token документа и identity draft. Export отдаёт только принятый документ, без ghost/стрелок/служебных подсказок, не фиксирует draft автоматически.

Подготовка whole candidate, имён/тегов, validation, clone/history и error-prone steps до первого setter/history write. Fault/exception/collision/отмена оставляют документ, generation checkpoints, undo/redo, RNG/counters и выбранную карту без изменений; ошибка может изменить UI. Отмена draft возвращает исходный selection, не откатывает pan/zoom пользователя. Одна Undo возвращает точные записи/имя/теги/положение; Redo повторяет снимок, не вычисляет заново.

## E8.2 — ручные имена оставшихся объектов

Второй последовательный срез той же утверждённой задачи, не начинать одновременно с E8.1. Он использует поле editorNames из v8; отдельной второй миграции только ради этапа не нужно. Общий каталог имён E1 остаётся после информации и заметок, открывается только «Найти объект». Названия/координаты/тип видны в результатах. В общем Edit именуемое значение открывает существующие парные RU/EN поля; отдельную боковую панель не вводить. После изменения предмета/геометрии однозначная идентичность определяет перенос имени, не близость на карте.

| Тип / фактическая идентичность | Контракт имени и жизненного цикла |
|---|---|
| Регион, река, озеро; королевство | Существующие E1 toponyms/kingdom.name остаются источником. Перенос POI их не меняет. Forest/mountain/swamp — имя того же region:id, не новая сущность |
| Наземный POI любого типа, включая не-поселение | editorNames на locator `poi:regionId:q,r`; существующее settlement имя остаётся fallback. При явном ручном имени оно имеет приоритет; rename поселения без override использует старую ветку. Два поля не показывать как два объекта. При превращении типа имя сохраняется; новый settlement fallback не должен подменить ручное имя |
| Водный POI | editorNames `waterPoi:q,r`; перемещается с точкой, не с озером/морем. Тип остаётся прежним |
| Дорога и тропа | `road:id` — имя всей записи Road, включая смешанные road/trail segments. Не присваивать по имени каждому физическому отрезку. При изменении типа сегмента имя неизменно; удалён последний сегмент — удалить имя в той же Undo-транзакции |
| Препятствие | `obstacle:id`; E4 move сохраняет имя при смене edgeKey. Удаление удаляет имя атомарно |
| Мост/брод/паром | `crossing:<Crossing.key>`; изменение kind сохраняет имя. При удалении/замене физического crossing его имя — авторская зависимость, требуется явное подтверждение либо отказ по действующему E3/E5/E6 gate. Не приклеивать имя ближайшей переправе |
| Пороги | `rapid:<riverId>:<canonical edgeKey>`; имя относится к фактически видимому On/Auto маркеру. Auto→On на том же месте сохраняет. Off/перемещение/удаление русла: показать потерю имени в dependency preview, подтверждение либо отказ, Undo возвращает |
| Водопад | `waterfall:<canonical vertexKey>`; физический узел общий для сходящихся рек, одна запись/одно имя. Аналогичный контракт видимости/удаления; нельзя давать два имени тому же видимому маркеру |
| Море | **Открытая зависимость E8-N-SEA**, не выдана за выполненную. Сейчас нет стабильного Sea.id или утверждённого поведения имени при слиянии/разделении connected components. Имя всего моря нельзя хранить на случайном одном гексе и молча переносить. Перед реализацией этого пункта аналитик предлагает узкий контракт sea identity/split/merge внутри утверждённого L1; существенное расширение владельцу. Это не блокирует E8.1 и имена типов выше, но не позволяет объявить «все названия редактора завершены» |

editorNames — необязательный разреженный `Record<string,{en:string,ru:string}>` для перечисленных адресов, не модификация генератора ToponymKind и его языковой модели. Новым объектам имя не генерируется автоматически. При отсутствии записи показывать прежний локализованный тип/номер. Для общих имён trim, оба языка непусты, ≤80 UTF-16 units каждый, текст безопасно экранируется, проверка уникальности по `trim().toLocaleLowerCase()` как в E1 по всем живым именам обоих реестров и kingdom names отдельно в своём языке. Одно и то же POI/fallback исключить из сравнения с самим собой. Оба пусты — явное удаление ручного override, с возвратом fallback; одно пусто — ошибка. Очистка editorNames не стирает исходный settlement toponym. Исходные старые дубликаты не исправляются автоматически; новое конфликтующее имя отклоняется.

Ключи физической геометрии получать из действующих canonical helpers (не приблизительных пикселей); валидатор разбирает суффикс после фиксированного префикса типа, проверяет существование ровно одного адресата. JSON record keys используются целиком, не split по каждому ':'. Не создавать ручное имя для несуществующего/Off-маркера. Расчётные дорожные номера и названия типов — fallback, а не авторские имена. Пока E8.2 не реализован, не писать такие записи в v8 и не объявлять эти типы именуемыми в UI.

E8.2 обязан подключить editorNames к **всем** E3–E7 операции удаления/смены геометрии, generator/delete-last/import/Undo/Redo/snapshot, dependency/loss preview и отображению/экспорту. Переименование/перенос препятствия не меняет identity, поэтому имя остаётся. Для исчезающего адресата без поддерживаемого подтверждения — безопасный отказ с указанием конкретного авторского имени. Нельзя молча prune пользовательские строки. Обычная генерация после rename сохраняет старые имена и не меняет карту из-за наличия названия.

## Формат и совместимость

E8.1 вводит **JSON v8**: причина — новые ручные имена типов POI, которые нынешний toponym-валидатор не принимает. Только `map.editorNames?`; сохраняются schema `hexcrawl-map`, generator version и generationState. Это не изменение алгоритма seed. Старые v2…v7 сначала полностью проверяются существующим валидатором, затем editorNames={}, не синтезировать их из подписей. Новые v8 проверяют типы, канонические ключи, парные строки/размер, существование адресата и неизвестные поддерживаемые типы; неверный/висячий/коллидирующий адрес — атомарный отказ с путём поля. V8 без необязательного поля допустим и означает пустой слой. Будущие версии отклоняются штатно.

Во всех capture/clone/restore/import/export/backup/history/generation paths editorNames обязателен в памяти и сохраняется буквально. V8 экспорт не поддерживается прежним опубликованным v7-приложением; показать понятное сообщение версии и не предлагать «совместимый v7», который потеряет имена. Старые v2…v7 файлы остаются неизменными на диске до явного экспорта. JSON round-trip переносимого поселения сохраняет полный прежний toponym, теги и counters. Миграция не запускает reroll/quota repair. Примеры вида `waterPoi:...` не легализуют неизвестные типы в older version; правила валидации новых полей применяются только к v8.
