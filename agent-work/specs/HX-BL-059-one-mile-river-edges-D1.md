# HX-BL-059 — реки по рёбрам одномильной сетки · D1
Статус: черновик для самостоятельной проверки интервьюером. Не ready_for_development. Задача Согласована; публикация не разрешена. Родительская цель — согласованная одномильная география. Новые биомы021 на паузе, оформление биомов не затрагивается.

## Основания и результат
Владелец16.11: «На1мильной карте реки должны идти по рёбрам, а не по центру гекса». Источник agent-work/decisions/owner-decision-2026-11-16-one-mile-rivers-on-edges.json. Ранее13.11 уже выбраны обход по рёбрам слева/справа, сдвиг обязательных прибрежных POI в пределах родительского6mile, связанные дороги и скрытие дороги внутри крупного POI: owner-decision-2026-11-13-ONE-MILE1-GEO-D01-edge-detours.json. Ответы14.11 «ничего не показывай, сдвигай» и «делай дорогу короче» относятся к обычным source-правкам, не отменяют отдельное первоначальное уточнение и защиту measured/locked. Не спрашивать повторно решённое.

Итоговый пользовательский сценарий: открыть настоящую карту→переключить1mile→видеть русла на рёбрах мелкой сетки, соединённые с озёрами/притоками/переправами→сохранить/загрузить→получить тот же рисунок в PNG. Ширина F1–F5 остаётся10/20/30/40/50% расстояния между противоположными сторонами1mile. Геометрические координаты существующей сетки, её адреса и мировой RNG не меняются. Это визуальная шкала ширины, не новая физическая калибровка.

## Предлагаемый контракт R01–R10
R01. Ось каждого видимого сухопутного участка1mile лежит на объединении рёбер канонической текущей1mile-сетки. Каждая пара соседних вершин — легальное ребро, без диагоналей через ячейки. Толщина воды может заходить в соседние ячейки; условие касается оси. Скругление join не должно срезать углы осевой линии.
R02. Выбор стороны устойчив по seed+river/source-edge+cell: pan/zoom, поворот, стиль, повторное открытие и экспорт не перебрасывают обход и не потребляют мировой RNG. Из допустимых обходов действует прежний контракт, без независимого выбора отдельных соседних кусков, разрыва или наложения независимых рек.
R03. Направление, полноводность, IDs и исходная логическая топология сохраняются. Общий source-узел имеет общую fine-привязку, приток не рождает новую реку, концы на границах соседних регионов совпадают. Дельты и ручные сегменты входят в проверяемый корпус; неизвестные варианты не заявлять принятыми.
R04. Водный вход/выход использует существующий действительный берег озера и непрерывный контакт с ним. Сухопутная часть строго по рёбрам; короткое продолжение внутри воды до фактического берега не оправдывает диагональ по суше. Противоречие точного берегового порта и требования оси — явно разрешить до чистовой версии, не молча ослабить правило. Проверить море, сквозное озеро и смену ширины.
R05. Прибрежный POI остаётся у своей требуемой реки внутри исходного6mile parent; связанная дорога доходит до входа. Крупный POI маскирует дорогу только внутри своего footprint, не удаляя связь. Сохраняются authored/measured/locked ограничения и unrelated объекты.
R06. Тип, ID и порядок мостов/бродов/паромов сохраняются; место соединено с актуальными берегами и сухими подходами. Для меняемого допустимого дорожного пути length-first, затем отклонение от прежнего и canonical tie-break. Не превращать059 в новую систему переправ.
R07. Предложение для ordinary-карт: автоматически готовить согласованное fine-представление при входе1mile, без нового обязательного клика «Уточнить» для простого выполнения требования. Источник6mile не переписывать только от просмотра. Но способ хранения derived-геометрии и связи с уже принятым GeometryPlan — существенная развилка, ещё не выбран владельцем для059. Чистовая версия требует её разрешения.
R08. Для уже уточнённых карт переиспользовать принятую геометрию, которая соответствует инвариантам; не рандомизировать её заново. Для mixed не оставлять оставшуюся ordinary часть проходящей по центрам. Предложение: пересчитывать только необходимую зависимую closure, атомарно. Конфликт measured/locked или невозможный маршрут: исходные данные сохранны; нельзя молча удалить/перенести закреплённое или выдать старый центрированный рисунок за исправленный. Поведение UI при таком конфликте и первоначальный переход старых карт уточняются интервьюером.
R09. Save/load сохраняют принятый маршрут или воспроизводимый ключ/версию, информацию пользователя и связи. Обычная source-правка + closure — одна Undo-транзакция по прежним ответам; чистая смена вида не добавляет правки в историю. Не добавляется требование сохранять весь liveUndo-stack в JSON. До чтения legacy-корпуса не заявлять100% совместимость.
R10. Карта и PNG берут одну согласованную геометрию; экспорт не запускает другой выбор стороны. При busy/stale/cancelled подготовке не публиковать частичный план. Переход масштаба не запускает генерацию соседних регионов.
