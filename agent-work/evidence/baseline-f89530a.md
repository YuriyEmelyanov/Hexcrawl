## Что проверено и чего эта работа не доказывает
Прочитаны актуальные индекс/видение/модель, код, типы состояния и обработчики, тесты и рабочие файлы agent-operations. Существующая CI build job на этом же SHA: **170 pass, 0 fail, 0 skipped**, типы и сборка успешны; выполнены шесть browser scripts. Прочитан лог, а не только зелёный значок. Локально проверки не повторялись: для этого ограниченного аудита использован уже выполненный CI на точном SHA. Новых массовых/нагрузочных серий, пользовательских исследований и изменений приложения нет.
Подмены Math.random в тестовом harness и браузерном smoke дают воспроизводимость проверки, но не воспроизводимость сохранённого мира в продукте. Навигационные измерения 400/1200 гексов не являются измерением генерации и не покрывают все составы карты или Android.
В текущем коде подтверждены пробелы: master RNG не сохраняется; ручные правки биома/POI не добавляются в history; reset/import очищают историю; import validator не проверяет полную структуру roads/ID/references/ui. Последний пункт — подтверждённая неполнота валидации, **не воспроизведённая потеря данных**. Критических падений существующая проверка не выявила; отсутствие всех критических дефектов этим не доказано.
Часть изменений уже существует, хотя бэклог говорит proposed: ручные правки биома/POI, PNG/JSON, SVG POI, географические имена, режим Mythic. Они не превращены автоматически в выполненные G4-задачи. Открытые старые PR не считаются отсутствующими функциями main.

### 1. HX-NEXT-001 — Безопасные изменения карты: атомарный импорт и отмена ручных правок
Довести полную подготовку импортируемого состояния до первой записи React state; валидировать ID/ссылки/roads/ui/координаты. Единая история для существующих biome/POI edits, import и reset; undo/redo этих операций. Без нового редактора воды/регионов, контента и широкого рефакторинга.

Приёмка:
- Невалидные roads/ID/references/ui и будущая версия отвергаются, текущая карта, выбор и история неизменны; UI остаётся рабочим.
- На корпусе текущих fixtures и старых optional fields import→export сохраняет смысловые данные и возможность продолжения.
- Правки биома/сухопутного и водного POI, reset и успешный import отменяются и повторяются без потерь; generation rollback/regenerate tests не регрессируют.
- Не менее 100 смешанных обратимых операций проверены через настоящий UI; именованные версии вне первого scope, поэтому G4 не заявлять.
- npm run check и test:browser на Node24, отчёт и acceptance fixtures.

Зависимости: owner_scope_approval.
Остановка: Если нужны миграции неизвестных старых версий или меняется географический алгоритм — зафиксировать отдельную зависимость и не расширять PR.
Баллы: +2.5 за безопасный импорт/сохранность и +5 за отдельное доказательство отмены изменений. Один round-trip не используется как доказательство обоих результатов.

### 2. HX-BL-030 — Воспроизводимое продолжение: master seed и состояние случайности
Ввести master seed и независимые сохраняемые потоки географии/POI; сохранить независимость имён и визуала. Два сценария: последовательное расширение; save/load→следующее действие; дополнительно восстановление RNG при rollback/undo. Совместимость старых файлов задана явно; не обещать восстановить неизвестную старую случайность.

Приёмка:
- Одинаковые version/seed/options/actions дают одинаковые смысловые данные; сравнение исключает только технический savedAt.
- Непрерывное A→B→C совпадает с A→B→export/import→C; undo→повтор совпадает; сбой не сдвигает RNG после восстановления.
- Изменение визуала/имён не меняет географию; обязательные потоки охвачены проверками через production handlers.
- Файлы без RNG открываются без изменения старых объектов; новый режим продолжения явно определён; версия схемы отделена от версии генератора.
- npm run check, test:browser; fixtures и негативные результаты сохранены.

Зависимости: owner_scope_approval; совместимый контракт сохранения из HX-NEXT-001 либо отдельная проверка его сохранности.
Остановка: Защита произвольных сущностей, полный reroll и переписывание генератора — отдельные задачи. Если без них расширяется scope, остановиться с конкретным предложением.
Баллы: Плановый первый переход G0→G1 (+7.5); G2 (+15 от baseline) только после подтверждения обычных сценариев критерия, не начисляется заранее.

### 3. HX-BL-003 — Устранить воспроизводимую задержку на растущей карте по числу гексов
Предложенный профиль N=400/1200/2400 требует согласования. Сохранить одинаковые версии, состав и качество карт; отдельно измерить add/expansion, render и navigation через реальные действия. Учесть отказы/незавершённые операции. Выбрать одно воспроизведённое узкое место и исправить; без подтверждения не менять алгоритмы.

Приёмка:
- Перед прогоном согласованы устройства, N, состав карт, число повторов, холодные/тёплые запуски, timeout и пороги. Указаны N до/после, прирост гексов и режим.
- Есть сохранение и шаги воспроизведения задержки; генерация, рендер и навигация измеряются раздельно; сбои не исключены из распределения.
- До/после сравнение на тех же fixtures/параметрах; карта и PNG сохраняют качество, проверки географии/сохранений проходят.
- Android заявляется только при реальном замере на согласованном устройстве; эмуляция отдельно обозначена.
- Если узкого места нет — сохранить отрицательный результат, не проводить бессрочный поиск и не начислять баллы.

Зависимости: owner_scope_and_N_threshold_approval.
Остановка: После фиксированного профиля и одного исправления; если нужен новый алгоритм или другая подсистема, отдельное согласование.
Баллы: Прирост неизвестен. Сохраняется G2; G3 возможен только при проверках, обработке ошибок и подтверждении владельцем/пользователями. G4 требует всех условий, утверждённых N/порогов и сравнительного evidence.

Связанные истории и слухи (HX-BL-040) остаются важным следующим игровым этапом. Их преимущество — переход от карты к содержанию экспедиции; сейчас сохранение/история изменений не готовы надёжно обслуживать новые смысловые ссылки. Поэтому первым маленьким результатом после защиты данных должен стать связанный игровой пример, а не бесконечный общий рефакторинг. Маркетинговые публикации и исследование 50 мастеров этим аудитом не разрешены.
