## Конкретные замечания нового harness

1. **HX003-V2-R1, medium — exact CPU assertion строже утверждённого протокола**, `scripts/hx-bl-003-v2.mjs:56`. P1-V2 требует прежний *ресурсный профиль*4vCPU/~16GB, а7763 указан как `recorded`. Фактически9V74,4vCPU,16766414848bytes и требуемый Chromium151.0.7922.34 соответствуют записанному классу ресурсов. Требование `/AMD EPYC 7763/` добавлено разработчиком и само породило остановку. Для новой A/B пары существенны одинаковый host/версии и зафиксированный профиль. Разные CPU означают, что старые и новые серии нельзя бесшовно объединять; это не означает обязательность старой точной модели для новой внутренне парной серии. Исправить проверку на согласованный класс, записать фактический CPU. Отрицательный факт остановки сохраняется.

2. **HX003-V2-R2, medium — timeout не останавливает старую browser работу**, `scripts/hx-bl-003-v2.mjs:21,26,65–66,72`. `bounded` отклоняет Promise.race, но не отменяет `restore`/`page.evaluate`. После таймаута код помечает только variant unusable и продолжает другую версию в том же browser, пока зависший контекст способен продолжать нагружать тот же host. Финальный `context.close()` не ограничен внешним timeout. `closeBrowser()` через5сек возвращает управление без подтверждения завершения/принудительного прекращения процесса, после чего возможен следующий PNG browser. Это противоречит требованию внешнего watchdog с завершением browser и отсутствием параллельной измерительной нагрузки. Нужно подтвердить прекращение старой операции/процесса перед следующей строкой; при невозможности — остановка пакета с сохранёнными not_executed. Это статический дефект потенциального timeout пути, **не наблюдавшаяся регрессия текущей серии**: она вообще не началась.

3. **HX003-V2-R3, medium — analyzer не учитывает неудавшийся прогрев**, `scripts/hx-bl-003-v2-analyze.py:17–27`. Complete вычисляется только по пяти integer iteration строкам; warmup отфильтрован. Offline synthetic input с4 errored warmups и20 successful measured rows даёт4 `bounded_guard_pass`. Это не доказывает выполнение перспективного протокола «успешный явный прогрев →5 повторов». Сохранять цифры и все rows, но отдельно требовать успешный корректно упорядоченный прогрев для protocol-complete/guard-pass. Не добавлять повторы. В actual zero-action artifact analyzer корректно возвращает incomplete; ошибка пока латентна.

Протокол предусматривает no automatic rerun. Число `run_attempt==1` не является глобальным реестром расхода разрешения: новый push workflow может снова иметь attempt1.
