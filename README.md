# Hexcrawl Region Generator

React + TypeScript + Vite приложение для пошагового расширения hexcrawl-карты регионами.

## Механика

1. Для первого региона якорь (`anchorHex`) — стартовый гекс `0/0`.
2. Для следующих регионов якорь — гекс-кандидат, через который регион присоединяется к карте.
3. Размер каждого региона определяется процедурой `d20 + XdF`:
   - бросок масштаба: `d20`;
   - `X = d20`;
   - бросок роста: `XdF`;
   - каждый Fate-куб роста считается как палочки (`- = 0`, `пусто = 1`, `+ = 2`);
   - `regionSize = X + sticks(XdF)`.
4. Регион всегда включает `anchorHex` и строится как связная область.
5. Добавляются только пустые соседние гексы текущего региона (без пересечений с уже занятыми).
6. Выбор кандидата для роста — **взвешенный случайный**: вес потенциального гекса равен числу его соседей, уже входящих в текущий регион.
7. Перед добавлением кандидата выполняется проверка `wouldCreateEnclosedVoid`:
   - кандидат временно добавляется;
   - проверяется flood-fill для ближайших пустых гексов;
   - если нет выхода наружу, кандидат отвергается.
8. Если после фильтрации допустимых кандидатов нет, рост региона останавливается раньше целевого размера.
9. `centralHex` выбирается после генерации по максимуму `sameRegionNeighborCount` (число соседей гекса в том же регионе): случайно среди гексов с максимальным значением; для региона из одного гекса центр — он сам.

## Основные функции

- `generateConnectedRegionFromAnchor(anchorHex, size, occupiedHexes)`
- `weightedPickCandidate(candidates, currentRegionHexes)`
- `wouldCreateEnclosedVoid(candidateHex, currentMap, currentRegionHexes)`
- `hasEscapeToOutside(startEmptyHex, temporaryOccupiedHexes)`
- `chooseRegionCenter(regionHexes)`
- `getRegionColor(regionId)`

## Интерфейс

- Каждый `regionId` рисуется своим цветом.
- `anchorHex` не выделяется отдельным цветом на карте (только в панели деталей).
- `centralHex` выделяется аккуратной точкой.
- Гексы-кандидаты рисуются нейтральным цветом и остаются кликабельными.
- В панели информации отображаются:
  - бросок масштаба: `d20`;
  - масштаб `X`;
  - значения броска роста (`XdF`);
  - палочки роста и итоговый расчёт размера;
  - целевой размер;
  - фактический размер.
- У каждого региона есть отдельная простая река.
- Реки строятся как пути по графу вершин гекс-сетки: `RiverGraphNode` (углы гексов) и `RiverGraphEdge` (стороны гексов).
- Узлы графа знают, являются ли они вершинами границы региона и границы с `candidate`-гексами.
- Концы реки выбираются среди таких boundary nodes (в приоритете — граница с `candidate`-гексами).
- Направления и стрелки используются для показа течения; слияния выводятся в формате `Река 1 впадает в Реку 2`.
- Если в новый регион одновременно входит река и выходит другая река, они соединяются свободным путём внутри региона; остальные входящие реки могут подключаться к этому пути как притоки.
- Если полноводность входящей реки выше полноводности исходящей, коннектор делится в случайной внутренней вершине на два сектора с полноводностью прилегающих внешних секторов, а рядом создаётся озеро размером в разницу полноводностей.
- После основной схемы генерации оставшиеся выходящие реки подключаются внутри нового региона: сначала к озеру без речных соединений, затем к внутреннему истоку; при этом река не выводится в более высокий соседний регион и не пересекает уже занятые речные рёбра/вершины.
- Если выходящая река подключается не к озеру и её полноводность больше 1, внутренний сектор получает полноводность на 1 ниже, чем сектор в выходящем регионе.
- По клику по гексу показываются:
  - `q/r`;
  - `regionId`;
  - `centralHex` (да/нет);
  - `anchorHex` (да/нет);
  - `riverId` рек, касающихся гекса.

## Запуск

```bash
npm install
npm run dev
```

## Проверка

```bash
npm run build
```

- В debug-режиме красные точки показывают вершины региона, общие с candidate hexes; оранжевые точки показывают вершины региона, общие с соседними открытыми регионами; фиолетовые точки показывают вершины centralHex. Если новый регион содержит начальную или конечную вершину уже существующей реки, новая река начинается из этой endpoint-вершины; внутренние вершины существующих рек не используются. Если endpoint нет, простая река строится между красными точками через фиолетовую точку.
- Река не может проходить по одному и тому же ребру графа дважды.
